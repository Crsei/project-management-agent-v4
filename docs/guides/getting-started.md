# 本地安装与首次使用

本页描述当前源码的使用方式和已知限制，不代表当前工作树已通过检查、真实供应商账号验收或生产部署。历史计划和本机验收原件保留在本地，不作为公开安装依赖。

要求 Linux、Node.js 24.21.0、pnpm 11.9.0、Docker 与 Compose；当前 TypeScript MCP/Skills host 不需要 Rust/Cargo，原生编译工具见[开发与验证](development.md)。在本项目根目录对**全新 v4 空库**执行：

完整工程验收另用 `pnpm check:ci`，不是下列安装步骤已通过的保证。`pnpm check:turbo` 默认六 lint，其 `build` / `host-build` 保留完整原类型/构建叶并可恢复已声明公共产物，但仍只是隔离工程检查，不替代按部署环境运行的 `build:v4`。来源/许可/真实测试/fixture/清理不缓存，完整 agent/all 须显式固定公开 authoring source。若服务已托管当前 checkout 的产物，应在新的独立 worktree 中检查，避免覆盖 live dist；参数、source 前提、linked-worktree 和 trusted-only hosted cache 边界见[开发指南](development.md#turbo-显式任务调度与本地-lint-缓存)。

本轮本机缓存/恢复与独立完整 Agent 有实际通过证据，但默认 `all` 的真实 backend 因 MinIO Docker FROM 镜像域名 DNS 失败尚未进入用例；不把工程 HIT、独立回归或现有 3224 健康当作新安装、生产或 hosted 全量成功。实际 hosted workflow、真实 Provider/平台/生产及四项发行许可 blocker 未关闭；结果与测量范围属于内部记录，不随公开树分发。

```bash
node scripts/doctor.mjs
pnpm install --frozen-lockfile
pnpm setup:local
pnpm db:up
pnpm db:migrate
pnpm bootstrap
pnpm build:v4
# setup 生成的描述符与默认 .local/blobs 一致；改过 BLOB_ROOT 时先同步描述符。
pnpm storage bind --new --stopped --target-config .local/blob-target.json
pnpm services:start
pnpm services:status
```

默认公共入口 `http://127.0.0.1:3224/pm`（同端口的 `http://localhost:3224/pm` 等价，便于端口转发访问）；PM API `4194`、Agent API `4325`、Web 开发上游 `4326`、PostgreSQL `55444`。数据库 Compose 名称 `project-management-agent-v4-backend`，应用 Compose 名称 `project-management-agent-v4-app`。不要连接来源副本的端口/卷。

`pnpm bootstrap` 只为尚无账号和工作区的实例准备一次性设置令牌 `.local/setup-token`（0600），不再创建默认账号或明文密码文件。启动后打开 `/pm`，依次填写姓名与邮箱、密码、工作区名称，最后输入部署管理员提供的令牌并确认；成功后选择工作区进入首次使用引导。令牌不得进入日志、URL 或前端配置；其目录及祖先路径必须安全，特殊挂载环境的私有工作目录操作见[部署手册](../../deploy/README.md#首次设置令牌与恢复)。

已有实例保留账号和业务 ID，不因旧访问文件缺失重新初始化。新用户可点击登录页“注册账号”进入 `/pm/register`，依次填写姓名与邮箱、12–256 字符密码并确认；无需邀请令牌，成功后建立普通 PM 会话，再创建自己的工作区。注册本身不授予已有工作区权限，加入其他工作区仍需有效邀请或管理员明确授权。已有用户使用原密码登录，在账号安全中按需改密、独立验证恢复邮箱，再切换 CLI/自动化凭据；不会自动改密或删除旧 `.local/access.json`。

若注册结果未知，页面清除密码并先检查当前会话，不自动重新发送注册。没有会话不证明账号未创建；按页面提示用相同邮箱普通登录。邮箱已注册时也使用原账号登录，不通过再次注册重置密码。邀请邮件仍进入专用接受页，缺少令牌时不能用该页代替自主注册；邀请令牌不放入查询参数。

首次账号的工作区仍初始化内置 **Nova 客户门户**示例；登录后新建工作区时可选择是否创建示例，默认不创建。示例包含 1 个项目、8 个任务、4 份文档及 14 个规划对象，均为可编辑的真实 Markdown 数据。各工作区独立分配 ID、目录及关系；不复制部署实例的账号、权限、凭据、评论或执行历史。示例日期固定，负责人留空，可能显示逾期；这不是当前团队的真实安排。已有工作区不自动补种，删除已初始化的示例也不会重新生成。

在工作区选择页或应用菜单的“新建工作区”打开弹窗，填写名称并选择是否创建示例项目。创建前保存原请求键；结果未知时使用“核对原请求／恢复原创建”，不要换键重复创建。恢复先读取原结果；页面卸载或已观察到会话改变时不继续发请求。创建和恢复写入还须携带发起时的 `expectedActorId`，服务端在任何创建／初始化副作用前与实际认证主体比较，不匹配返回 `409 session_changed`；该字段不是授权身份的替代。已完成引导或升级前已有账号，登录后只有一个工作区时直接进入；多个工作区优先恢复本账号上次使用的已授权工作区，选择页和应用菜单仍可切换。新账号先确认工作区再继续引导。初始化未完成的工作区单独显示，不当作空工作区开放编辑；其他已就绪工作区仍可进入。首次设置已建立身份后若初始化失败，使用原账号正常登录，工作区列表会核对并有界恢复原初始化，不重置密码。

已有安装升级此流程须应用 `0052_workspace_samples.sql`、增量 `0053_workspace_sample_storage.sql` 和 `0054_workspace_creation_without_sample.sql`，并同时更新 PM API、Web 和对应桌面后端，不能只换前端。`0054` 允许创建工作区时跳过示例；跳过记录与示例记录共用原请求键，未知结果仍按原模式核对。原请求仅能恢复属于它的初始化目录；未知已有且没有合法 state 的目录、目录替换、已建立权威后丢失 state 均拒绝自动接管或重建。首次建目录后、所有权提交前中断的窗口同样保持拒绝，不自动删除目录。准确阶段、旧有效 state 的保留及升级边界见[部署手册](../../deploy/README.md#工作区示例初始化升级与恢复)。

`setup:local` 生成并保留已有 0600 的 `.env`、`.env.worker`、`.env.agent`，只为新 v4 生成数据库密码；不会复制秘密或导入 `~/.codex`、`~/.claude`、`~/.gemini`。PM Markdown、附件、可信目录配置、Agent SQLite 和应用管理的运行时 / 账号状态在本仓 `.local/` 下；原生 CLI Home 不再强制迁入其中。Worker 只取得自身角色配置；Agent 继承启动环境并叠加 `.env.agent`，原生子进程仍排除 PM / 数据库等应用私有变量。首次存储绑定不能因目录存在而省略；已有数据不能执行上面的 `--new`。


`services:start` 启动 PM API、Worker、Agent API 与托管统一 Web 产物的公共网关；`services:status` 报告进程与 HTTP 可达性，**不把 HTTP 就绪当 Provider/CLI 执行通过**。`services:stop` 只向记录中的 PID、启动时间、工作目录和允许入口均匹配的本仓进程发送 SIGTERM，不删除数据库、不按端口杀进程。日志为 `.local/logs/`。

宿主 inotify 限额不足时使用 `CHOKIDAR_USEPOLLING=true pnpm services:start` 或 `CHOKIDAR_USEPOLLING=true pnpm dev:v4`；服务管理器不会给已运行进程更新环境。健康检查不能替代真实工作区目录读取。

```bash
pnpm dev:v4          # 统一 Web HMR；后端改动后重启
pnpm services:status
# Ctrl-C 只停止本次 dev:v4 启动的自身进程
pnpm services:stop   # 停止本仓管理器记录的自身进程，切换 built/dev 模式前执行
curl http://127.0.0.1:3224/health/live
curl -i http://127.0.0.1:3224/health/ready
curl http://127.0.0.1:3224/agent/api/access
```

PM Cookie 为 `pm_v4_session`，Agent Cookie 为 `agent_v4_access`；原 same-origin、认证、目录 allowedRoots 与 WS upgrade 检查保留。未配置模型时明确报错或禁用，不生成假回复。

### 登录后首次使用引导

- **身份入口**：普通登录先输入邮箱再输入密码，不探测邮箱是否注册。自主注册仅在已初始化实例开放，不自动验证登录邮箱或恢复邮箱；空实例仍须管理员准备的一次性设置令牌。邀请页依次展示邀请范围、收集新账号资料或验证已有账号原密码、确认接受。接受后须显式普通登录，不因接受邀请自动建立会话或验证恢复邮箱。
- **工作区与资料**：新账号选择已授权且初始化完成的工作区，或通过现有创建弹窗建立工作区，再进入 `/pm/<workspace UUID>/onboarding`。资料步骤复用现有本人资料服务；“保存个人资料”才写入资料，“已查看，继续”只确认引导步骤，也可暂时跳过。
- **引导界面与信息气泡**：引导页使用“个人资料 → AI 配置 → 准备就绪”的横向三步进度，工作区绑定以页内常驻卡片显示，不再在引导页叠加第二层左侧步骤栏。点击“信息气泡导览”会按当前解锁状态高亮步骤条、工作区卡片、资料表单、AI 区域和最终按钮；气泡中的“已查看，继续／暂时跳过／稍后配置 AI”与页面按钮复用同一引导命令，关闭气泡不会改变已完成进度。导览只提供展示与同一命令入口，不新增权限、自动保存、Provider 登录或模型调用。
- **可选 AI 与 PM Skills**：引导 AI 步骤只读核对现有 Provider 的启用、配置和原生就绪状态；仍须通过独立 Agent 访问验证，PM 登录不授予 Agent 权限。可打开原 Provider 设置并返回原引导，也可直接在引导内查看九项 **Dovspace 官方内置 PM Skills** 的源路径、SHA-256 与内容版本，明确选择一个 Provider 及 Skills 后点击安装／更新；Agent Chat 设置的 Skills 页面复用同一安装面板。来源归属由内置清单及字节哈希确认，不凭同名 Skill 推定。未连接、未配置、远端／不支持的原生目标、读取失败和无访问权限分开展示；无兼容目标仍可查看来源并跳过。不会自动认证、导入凭据、调用模型或静默写入；安装中禁止切换步骤，结束后仍可继续或稍后配置。逐项显示安装、更新、冲突、不可用和错误，保留用户修改或无关同名内容；响应未知先重新读取权威安装状态，不自动重发。安装不等于运行中会话已加载，配置也不是模型执行验收；跳过不会被标为已配置。
- **续接与清单**：进度、完成时间与清单关闭状态保存在当前 PM 账号；刷新后继续未确认步骤。完成后进入工作区，首页清单展示当前资料、工作区和 AI 状态；可关闭清单，仍能从账号菜单“开始使用引导”手动打开。并发更新以账号与 revision 校验，响应未知先重读，不自动重放写入；工作区权限撤销后不能凭旧选择继续进入。
- **升级**：应用增量 `0059_user_onboarding.sql` 并同步更新 PM API 与 Web；不能只发布 Web。迁移前账号标为已完成并关闭清单，不强制打断已有使用；迁移后新账号默认待引导。迁移不改密码、权限、工作区或 Provider 配置，部署顺序见[部署手册](../../deploy/README.md#首次使用引导升级)。

此引导不是新权限体系，不影响任务完成规则。Agent 配置仍适用于本机服务，不是 PM 工作区私有配置；会话与持久化仍暂沿用 Agent Chat，统一设计尚未收口。

### 本地项目目录与初始化

本批不新增云端同步、多实例或业务执行规则。`pnpm setup:local` 生成并保留已有 `.local/local-projects.json`。项目保存位置不再限制在 `allowedRoots`：新建项目只有一个“保存位置”字段，预填 `<默认父目录>/<项目名>`，可直接改成服务主机上任意规范绝对目录；服务端仍拒绝符号链接、系统目录、不可写目录和路径逃逸。容器部署还需让 API/Worker 看到相同挂载路径。`allowedRoots` 继续作为文档来源等独立能力的目录根，不再约束项目存储。配置更改须在受控升级/重启时生效，不自动迁移文件。

进入 `/pm/<workspace>/settings?section=local-storage` 查看实际核心/备份路径并设置默认项目父目录。新建项目时，输入路径不存在则在服务端创建；已存在且没有 `.pm`/`.dovspace` 则接管并保留原文件；检测到 `.dovspace/.pm/project.json` 时按标记识别已有项目：仅当 `workspaceId` 等于当前工作区、原登记位置缺失且内容权威校验通过时走现有找回/重绑，其他工作区、已登记或标记无效的目录明确拒绝，不复制、不改 ID。初始化稳定项目 ID、身份标记、项目 Markdown、工作流初始状态、空任务/文档目录、附件绑定和恢复记录；不改原 README/代码，不建样例任务、不初始化 Git。

新建项目使用参考 gr8r-studio 的专用表单：名称、Markdown 描述、图标、颜色、真实负责人及目标日期随首次创建保存；支持 Ctrl/Cmd+Enter，输入法组合期间不提交。保存位置与最终路径预检保留，初始化说明和高级属性可展开。团队需在创建后的项目设置中独立关联；模板目前仅开放空白项目，其余明确禁用，不自动生成样例任务。取消或刷新保留原创建草稿，未知结果仍按原请求核对。

名称与保存位置标为必填；描述、图标、颜色、负责人和目标日期标为可选。负责人从真实成员列表选择，目标日期旁的日历按钮调用浏览器／桌面原生日期选择器；保存位置只显示一个绝对路径输入，不再暴露“保存模式／父目录／新文件夹名”，创建表单也不再显示“本地存储设置”入口。粘贴或浏览选择目录后，若项目名仍为空，用末级文件夹名填入项目名（例如选择 `RunLedger` 即填入 `RunLedger`）；已填写名称不会被覆盖。下拉菜单在创建对话框内打开，不会落到原生模态层之外而无法点击。填写日期与负责人后仍须完成路径预检，再创建项目。初始化返回 `write_unconfirmed` 时保留原请求键，使用“核对原请求／恢复”继续同一操作，不新建替代项目；旧版本写入的畸形 pending 行会在恢复时转换为契约形状。

| 数据 | 本地保存位置 |
| --- | --- |
| 新项目 Markdown 与附件字节 | 所选目录下 `.dovspace/.pm/core/`、`.dovspace/.pm/attachments/`；身份标记 `.dovspace/.pm/project.json` |
| 工作区配置、统一 ID、目录映射与恢复台账 | `CORE_WORKSPACE_ROOT/<workspaceId>/`，默认 `.local/pm-workspaces/<workspaceId>/` |
| 账号、权限、评论、审核、审计、命令收据、附件元数据 | PostgreSQL；物理数据库卷独立于项目目录 |
| 旧项目及历史附件 | 原核心根与原 Local/S3；仅显式迁移改变定位，切换项目不会改全局 `BLOB_ROOT` |
| 完整备份 | `LOCAL_BACKUP_ROOT`，默认应用数据基目录下 `backups/`；包含 SQL、共享台账、全部登记项目托管文件与引用附件 |

PM 在 `.dovspace` 内写入自包含 `.gitignore`（内容 `*`），避免该目录进入用户仓库版本控制；用户仍可在项目自身 `.gitignore` 加入 `.dovspace/` 作为显式规则。

项目详情支持目录状态、复制路径、显式迁移、托管移动及找回已由用户移动的原目录。缺盘不会创建空替代目录；未知结果先核对原请求，显式恢复仍使用原键和冻结输入。项目文件夹不是完整备份。准确配置、停写维护和恢复命令见[部署手册](../../deploy/README.md)，实施与验收见[本地项目存储说明](../../deploy/README.md)。

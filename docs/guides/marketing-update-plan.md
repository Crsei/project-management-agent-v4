# Dovspace 宣传站下一轮更新计划

状态：P0 产品事实纠正已实施，P1／P2 待实施；不是正式发行或公网部署声明。范围仅为 `apps/marketing` 及其公开使用指南，不替换当前 Web 工作台，不恢复隐藏的交付工作台，不改变业务完成、授权或持久化规则。下面的初始问题记录保留为本轮变更依据，当前用法见[宣传站指南](marketing.md)。

## 依据与优先级

2026-11-14 对实际 Astro 构建产物进行了桌面首页、下载入口及 390px 移动端五个路由的检查：

- 首页和下载页仍使用 **PM Agent**；三份指南使用 **agent-workspace**，与当前桌面 Dovspace 品牌不一致。
- 首页仍是产品截图占位；不能用来源项目截图或真实用户业务数据替代。
- `/get-started/`、`/security/`、`/desktop/` 均仍出现 v3 和 `.local/access.json` 指引。当前首次设置使用私有 setup token，已有账号正常登录；旧访问文件不是当前认证入口。
- 安全页把整个产品描述为单用户应用，并写着没有自动更新器。必须分别说明 PM 账号／成员权限与 Agent 主机执行边界，并与当前桌面更新门禁对齐，不能笼统删除风险说明。
- 下载卡片目前正确区分“构建目标”和“已发布产物”；这个边界必须保留。发现一个历史发布页，不等于当前工作树或所有平台已可下载。
- 已检查路由在 390px 下没有文档级横向溢出；这不代替后续改版的键盘、对比度、长内容和完整响应式验收。

本轮工程证据不能直接变成营销效果数据：隔离 PM 上的真实模型任务闭环和原操作恢复，不等于内嵌 Chat Provider、真实客户生产场景或优化收益 A/B 通过。会话／持久化设计仍是候选，尚未由用户确认收口。

## 产品叙事与明确非目标

建议主叙事：**Dovspace，把项目上下文与 Agent 执行放在同一个工作台。** 用实际界面展示项目组织、Agent Chat、可核对的操作结果；不要把 Run 成功描述成任务自动完成。

- 主入口改为“开始自托管”，指向当前安装指南；“打开工作台”使用明确配置的实际应用地址。桌面入口标明真实发布通道与平台状态。
- 保留现有字体与视觉素材；不以这次改版为由替换用户指定字体。现有来源链与许可文件随产物保留，未闭合的发行权利不能被新的品牌文案掩盖。
- 不增加统计跟踪、营销账号系统、邮件收集、虚构用户证言、性能提升百分比或未经验证的安全认证。
- 不自动开放公网，不把 `127.0.0.1` 展示成远程客户可用服务，不以宣传站接管 `3224` 工作台入口。
- 品牌改名仅作用于展示；不顺手改安装 ID、包名、私有数据目录、旧版本兼容路径或认证 Cookie。

## 执行顺序与并行边界

1. 先确定一份**事实与链接表**：以 [根 README](../../README.md)、[Agent Chat](agent-chat.md)、[部署说明](../../deploy/README.md) 和 [第三方说明](../../THIRD_PARTY_NOTICES.md#release-blockers) 为权威，分别核对 PM／Agent CLI 的实际身份边界。记录每条文案对应的已实现能力、实际验收与限制；不把历史计划当现行承诺，也不依赖尚未进入公开源码树的指南链接。
2. P0-A、P0-B 可分别由入门指南和安全／桌面负责人并行完成；P0-C 的共享 Layout 与 `site.ts` 只由一个集成负责人修改，其他工作包提供所需文案和链接。
3. P0 事实收口后，P1-A 采集真实演示图；P1-B 使用这些图编排首页。不能先设计虚构界面，再让产品配合截图。
4. P1-C 可并行整理真实发行元数据，但下载按钮启用受下面的外部前提约束。没有发行许可不阻塞 P0 纠错，也不阻塞诚实标注的产品介绍。
5. 合并后统一运行 P2；使用实际静态产物浏览并验收，而不是只检查源码或截图文件存在。

## 下载与公开发布的外部前提

- **字体／素材**：已有 OFL 字体、营销 SVG 与对应许可的字节来源补证不等于全站发行权利闭合。MiSans 条件许可、其他品牌／背景素材、最终产物许可随附和当前版本对应源码四类门禁继续按第三方说明处理；本计划不替用户作法律授权决定。
- **当前桌面版本**：Windows 安装、启动、升级、卸载保留数据及 GUI 路径，需要当前构建在真实原生环境中验证；macOS 另有对应原生验证、签名／公证要求。历史 smoke 和 Linux 上的包结构检查不能替代。
- **源码发布**：真实仓库为 `https://github.com/Crsei/project-management-agent-v4`。当前本地未发布改动必须和最终成品对应，commit、push、创建／公开 Release 分别需要授权；不自动发布。
- **托管地址**：宣传站与应用仍独立。需要实际可达的宣传站部署地址和工作台地址后，才固定正式公开链接。配置静态站变量不会自动部署或保护应用服务。
- **安全与收益宣称**：完整针对性安全产物、可审计真实模型 A/B、原生 compaction 和真实外部客户端 OAuth 的未完成验收，继续明确列为未证实，不引用演示数据宣称通过。

## 合并与部署检查单

- `pnpm typecheck:marketing`、`pnpm build:marketing`，以及受影响公开文档、许可／素材、来源和链接检查；使用本轮实际命令输出记录结果，不把较早工作树的通过结果沿用为当前通过。
- 从构建后的站点走通首页 → 入门 → 工作台、首页 → 下载／桌面、导航 → 安全／源码／第三方说明；外部源码和发布链接核对实际目的地，下载未启用时验证其确实不可触发。
- 浏览器验收桌面与移动端实际渲染、键盘导航、减少动效及控制台；截图只保存脱敏演示数据，不保存 cookie、token 或含秘密请求。
- 扫描静态产物：不得含 `.local/access.json` 的现行操作指引、旧 v3 服务命令／端口、私有配置、测试登录信息或未经审核的截图；为说明兼容性而保留的历史名称须明确上下文。
- 检查字体、SVG、截图和原始许可在最终产物中齐全，链接与来源清单对应；保留四项发行门禁的真实状态。
- 部署前核对端口、PID、工作目录和服务模式。宣传站静态产物只发布到其明确指定入口；不为宣传页重启 PM／Agent 或覆盖工作台。
- 按仓库约定同时核对 `http://127.0.0.1:3224` 工作台仍正常。若本轮仅改宣传站，无工作台运行产物变化，说明无需重建／重启工作台；临时预览成功不写成正式部署成功。

下一轮完成标准：五个公开路由与当前产品事实一致，核心展示来自真实脱敏界面，入口和下载状态可核验；未取得的账号、平台、许可或发布前提仍被清楚标示，而不是被营销文案隐藏。

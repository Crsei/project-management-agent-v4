# Agent Chat、Provider、MCP 与数据

本页描述当前源码的使用方式和已知限制，不代表当前工作树已通过检查、真实供应商账号验收或生产部署。历史计划和本机验收原件保留在本地，不作为公开安装依赖。

左上产品切换进入 `/agent/workspace`，PM 仍为默认产品入口。Agent 侧栏按“文件夹 → Sessions”组织：点击“打开文件夹”，浏览或输入 Agent 服务器上已有目录的绝对路径，再点击该文件夹下的“会话”。一个 Agent Workspace 对应一个规范化目录，不绑定 PM 工作区或项目；同名目录以完整路径区分。也可新建“仅对话”会话。首次执行受理后目录绑定冻结，改换执行环境须新建 Session。顶部显示当前 Session 的文件夹、Local、实际执行路径及收据证明的 Worktree；点击目录标签可展开来源路径与执行路径。

PM 产品切换先显示 Agent 模块加载状态，支持取消、失败重试和重新加载；保留整页导航与未保存草稿确认，不自动重发消息。Agent 设置页限制在视口内，导航与正文分别滚动，切换设置页回到正文顶部。

Provider 在 `/agent/settings/providers` 配置，原生 Home 留空时沿用服务端 CLI 环境和账号；受管 ChatGPT 使用应用私有账号状态。旧 Provider 选择不会自动替换模型；离页保留草稿保护，不自动取消后台生成。主题直接复用 PM 偏好存储，首次切换、刷新和双产品导航保持一致。目录不是权限或文件系统沙箱。

文件夹支持重命名显示名称、关闭和重新打开；关闭只隐藏列表，不删除代码或 Sessions，也不改变已绑定目录身份。会话行支持右键或省略号菜单：Pin、Settle、Snooze、重命名、隔离生成标题、未读、文件夹筛选、Auto-settle、复制、选择文件夹、Archive 与 Delete。各文件夹内按“置顶 / 活跃 / 稍后提醒 / 已归置”组织，每行显示目录、时间、标题及 Provider；侧栏导航不改绑当前会话。归置不是归档，更不代表 PM 工作完成。状态由服务端持久化并用独立 revision 防止覆盖；自动归置为默认 3 天无活动，不在运行成功时立即执行。归档可从 `/agent/settings/history` 恢复，运行中不能归档；删除沿用现有停止生成后再明确确认的流程，且不可恢复。标题重生成仅对具备隔离无工具调用能力的 Codex / Claude 开放，不修改原消息或原生会话游标。

生命周期使用独立 `lifecycleRevision`、稳定删除操作 ID 和当前 generation。删除先进入 closing 并等待实际停止，不把 HTTP 响应丢失解释为已删除；按原操作查询。提交可见删除后，业务引用、未决副作用所需证据及防复活墓碑仍保留，不是全盘擦除或附件 GC，也不撤销 PM／文件副作用。

侧栏、主区、运行卡片和输出面板沿用服务端保存的同一 Session 标题；重命名不改执行目录。自动标题回调只读已有标题，不再截取首条用户输入并写回；无标题的已保存会话显示“未命名会话”，新草稿显示“新会话”。标题重命名与明确触发的隔离生成仍保留；历史标题没有来源标记，不会猜测哪些来自旧自动逻辑或批量改名。侧栏和详情的活动状态读取服务端 generation 与仍可响应的请求：区分排队、运行、等待审批／输入、失败、取消、中断和空闲，不再以旧 RunLedger 或目录名代表当前活动。详情中的文件夹、路径及环境核验另列；运行结束后不继续显示等待或思考动画。进行中的一轮使用 t3code 风格的工作行与思考行：计时只采用 Provider 提供的时间，没有可信开始时间时只显示进行中；工作详情限高并仅在展开时跟随最新输出。Composer 显示只读的上下文窗口快照（已用／上限／观测时间），不自动压缩、不伪造上限或压缩入口。待审批／待回答以输入区上方的请求横幅呈现：多个请求可切换与收起，原生提问逐题展示并支持数字快捷键；审批只显示 Provider 实际给出的选项。 会话内 Ctrl / ⌘ + F 查找已渲染正文并高亮匹配，宽屏右侧消息地图可跳转；二者都不改动消息或服务端状态。 输入区使用半透明模糊外壳；已添加附件在编辑区上方显示缩略图或文件卡，可直接移除，附件仍随原消息提交。 消息显示生成开始时间；超长用户消息默认折叠；命令块带语法高亮，失败时回退纯文本。 归置或稍后提醒的会话在正文顶部显示状态行并可唤醒；页头标题可双击重命名；保存或模型目录失败时显示可重试提示。 已有会话暂不可发送时显示原因与参数入口；侧栏标题悬浮提示包含文件夹、路径、Provider 与模型。 助手消息顶部显示既有 generation 的交接与续接关系；其他生命周期类型仍需输出合同扩展。 Markdown 的 `<details>`/`<summary>` 折叠块可安全显示（其他原始 HTML 仍跳过），同源会话链接在聊天内跳转。 输入框内 ↑/↓ 可召回本会话已发送提问，↓ 到最后恢复草稿。 失败／取消／中断以正文分隔线显示，不推断未提供的原因。 侧栏会话可悬停查看标题、文件夹、路径、Provider／模型与更新时间。 右侧面板宽度按会话记忆，最大化时隐藏聊天列。 读取历史与助手开始/停止工作会通过无障碍实时区域播报。 超过 256,000 字符的消息会被明确阻止发送。 会话详情显示当前执行目录的 Git 分支；无仓库时不显示。 上滚阅读且输入为空时输入区收起为“继续输入…”条，点击展开。 队列与草稿操作收在输入区的“草稿与队列”菜单中。 终端抽屉按服务端 PTY 显示标签并可切换。 Markdown 代码围栏带 `title="…"` 时显示文件标题。 终端标签可新建会话终端或结束当前终端；已结束且未选中的标签不累积。 最新回复含计划时，输入区上方显示“计划已就绪”并可跳到计划卡。

#### 统一运行面板

PM 顶部“页面与外观选项”菜单和 Agent 产品切换中的 **运行面板** 进入 `/agent/runs`，默认直接展示普通会话运行看板，**无需 PM 登录**，不依赖 Lab 开关。显式的“会话活动”地址 `/agent/runs?view=sessions` 使用同一看板；“业务执行（PM）”进入 `/agent/runs?view=business`，单独展示关联 Issue 的业务 Runs。两者不是同一个执行身份，也不扫描外部终端进程或冒充 PM Worker、自动化总监控。

- **登录与恢复：** 默认运行面板不挂载 PM 登录表单，查看会话、选择文件夹、新建 Chat 和打开目录终端不以 PM 登录为前置，仍保留独立 Agent 访问校验。只有显式进入业务执行、Agents、Teams 和需要处理页面才使用现有 PM 登录表单；登录后保留当前 URL，再读取真实授权工作区。会话失效会清除受限内容及未提交草稿并显示登录入口；登录或“重新读取”不会重发业务写入或恢复旧草稿。已登录但无权访问所选范围时仍拒绝访问，应重新选择授权范围，不把 403 当作需要反复输入密码。项目／Issue／评论里的业务 Run 链接显式携带 `view=business`，不会落到普通会话看板。
- **统一布局：** 普通会话和业务运行看板复用 Agent Chat 的同一个文件夹／Session 左侧栏，包含搜索、文件夹操作、会话菜单、折叠、移动端抽屉和设置入口，不复制另一套侧栏。查看看板不恢复隐藏的 Chat 草稿或上次会话，也不恢复未决终端创建；侧栏明确打开会话后才进入原 Chat。
- **共享侧栏的访问失效：** 业务运行读取或操作收到 Agent 全局 `401 access_required` 时，运行面板同时隐藏缓存的文件夹／Session 侧栏，要求重新核验 Agent 访问。普通 PM 登录或资源权限拒绝只清除对应业务受限内容，不撤销仍有权查看的普通 Agent 会话。
- **业务执行：** 明确选择当前有权访问的 PM 工作区、项目、Issue 及 revision，再选择已发布版本的 Agent／Team 和独立的 Agent 执行目录。打开页面、选择范围或查看执行简报不启动模型；提交才创建具有原请求 ID 的 Run。目标或配置已变化时显式刷新，不自动替换为新版或重发未知写入。
- **Run 输出面板：** 点卡片在右侧停靠面板中查看匹配 generation 的执行输出，不再打开遮挡全页的详情弹层。桌面可调宽或展开，保留左侧栏和部分可交互看板；窄屏覆盖工作区，左侧栏仍可展开。业务 Run 的状态、事件、父子委派、用量和 Issue Work Thread 置于次级视图；可打开原私有 Session，目录身份核验通过后可打开其独立终端。默认输出属于本 Run 最新 generation，历史或子执行保留各自原引用，缺失引用不自动替换。Thread 复用 PM 的任务讨论和评论权限，不是第二套 Issue 数据库。读取历史输出、来源和摘要仍核验当前权限；读取失败隐藏原输出正文，401／403 清除受限数据及待提交草稿。
- **有界协作：** 顺序 Team 按固定成员版本执行；Supervisor 通过实际 `delegate_task`／`ask_agent` 委派和咨询，再接收子 Run 结果。根执行共享并发、委派深度、Run 数量、持续时间及输出上限，同一规范代码目录的写执行互斥。普通 Chat 也参加目录写占用检查。这些限制不是金额硬预算、文件沙箱或无人值守 Mission。
- **停止与结果核对：** 取消须带当前 Run revision 和真实 generation；服务端确认停止前不显示已结束。已可能发送的 PM 写入先按原 operationId 核对，取消不等于撤销副作用；停止后不能再批准尚未发送的原写入。原生一轮输出结束但仍有 PM 审批时，业务 Run 保持等待；原审批处理后由实际后续执行消费结果。
- **普通会话看板：** 保留固定列 Kanban、文件夹／Provider／需要处理筛选。右侧默认展示原生执行输出，已保存对话和运行信息为次级视图，不默认堆叠两份输出与全部技术字段。原生输出不可用时说明来源，必要时显示保存消息；模型输出不是独立终端。新建时明确选择已登记且可用的文件夹或“仅对话”，再选择“在 Chat 开始”或“在终端开始”；仅对话不提供代码终端。失效目录不会回退到其他文件夹；打开页面或点卡片不发送模型消息、不创建 PTY、不执行命令。普通 Chat 与已登记目录终端不依赖 PM 登录。
- **跳转与返回：** 原 Session 和独立终端链接保留看板范围、筛选及所选记录；Chat 的“返回运行面板”经过草稿保护，返回原右侧输出面板。侧栏进入设置后也可返回同一看板选择；关闭输出面板只移除选择、不清空筛选，保留浏览器后退／前进语义。刷新沿原创建身份恢复，不另造 Session；终端意图消费后不因刷新重复创建进程或执行命令。已不存在的会话保留不可用提示，不改选其他会话。
- **浏览器导航：** 后退／前进以当前 URL 与实际选中的 Session 双重确认；旧读取或 SDK 切换不会把迟到结果附到新目标，也不会重复确认同一次草稿保护。切换尚未核对完成时不发送消息或打开终端。
- **会话结果与终端：** 页面可见时每 5 秒刷新，停止操作重新核对精确 generation；详情按同一会话历史区分尚未开始、完成、失败、取消和中断，缺失或不兼容状态显示未知，不编造完成时间或进度。历史审批记录不代表仍待处理，审批、回答及继续操作进入原 Chat 核对。终端是原 Session 实际目录／Worktree 中的独立 Shell，复用已有精确 PTY；手动命令或 CLI 的退出状态在终端查看，不自动更新 generation 或业务完成状态，也不扫描外部终端 Agent。
- **访问范围：** 执行环境读取明确返回所选 PM 引用无权时，只清除该受限环境，不清空无关普通会话及历史；Agent 自身访问失效仍清除整体受限视图，包括共享侧栏的缓存标题与右侧输出，显式重新核验后才恢复。后台读取保留同一会话已核验的目录展示，但打开终端前仍重新核验，读取失败立即失效。
- **完成边界：** Run 成功、团队意见一致或评论已写入都不等于 Issue 完成。PM 继续决定业务权限、合法状态转换与验收；任务详情的交付工作台保持隐藏。
- **适用范围：** 仍面向本机可信单操作者。Agent 会话尚无生产级成员隔离；目录不是沙箱。D1–D4 持久化决策已采纳，但整体设计、生产切换和跨平台验收尚未收口，不能据此开放不可信多租户访问。

#### Agents、Teams 与需要处理

- `/agent/agents` 管理长期 Agent 配置：角色、指令、实际 Provider／模型、能力绑定、项目分配和资源限制。保存生成不可变版本，旧 Run 保留原版本；停用／归档不改写历史。复制配置不复制项目授权，空项目分配不允许派发。
- `/agent/teams` 独立管理可复用团队，而不是在运行面板堆叠配置。当前支持 Sequential 与 Supervisor，成员引用明确 Agent 版本；团队和成员的项目分配必须同时满足。更新配置不会偷偷改变已受理的 Run。
- MCP／Skills 的安装与原生配置仍在既有管理入口。Agent 配置只绑定实际发现的能力及版本；安装、显示或选择不等于本轮可调用。原生 CLI 不能兑现的严格工具子集／只读隔离会被拒绝，不能把 Prompt 或 `observe` 声明当作强制权限。
- `/agent/inbox` 聚合当前有权处理的原生提问、原 PM 审批和真实资源等待，跳转到原入口处理。审批仍核验原操作的固定参数、当前 PM 权限、工作流及能力版本；此页不创建第二套批准接口或假批准按钮。
- 从 Run 进入 Inbox 时只列出该 Run 的待办；改变工作区／项目范围后重新读取对应范围。列表展示不代替原操作的实时可处理性和审批指纹检查。
- 自动智能 Router、自由多 Agent 群聊、Missions／Checkpoint、长期记忆和阶段 D 的远程／企业隔离不属于本轮实现。

- 新建、打开会话、停止与重试保持禁用；不发送消息、不启动进程、不修改 PM 状态。运行结束不等于业务任务完成。
- Demo 不改变正式会话存储；会话与持久化仍暂沿用 Agent Chat，统一设计尚未收口。

#### Agent 工作区与面板

主页保留自动化独立导航行、设置／用量／快捷键工具栏，以及顶栏面包屑和面板开关。右侧 Files / Git 复用单标签，Browser 可以新增多个标签；Terminal 是同一组服务端终端的单一视图，可在右侧和底部停靠，不另建第二套进程。Files surface 采用 t3code 的文件展示布局：可切换的项目文件树、文件类型图标、全项目文件搜索、目录展开／折叠、面包屑与语法高亮只读源码，Markdown 可切换渲染、源码可自动换行；二进制文件继续明确拒绝，不新增写入能力。右侧面板标签支持关闭、排序、最大化和窄屏抽屉；底部终端抽屉与右侧终端只显示终端内容，并以一条横线与上方内容分隔，不显示范围、实例、状态或操作按钮。隐藏或切换停靠只断开视图，不重启服务端 PTY。底部高度可调整，`Ctrl / ⌘ + J` 切换显示。

Browser surface 使用单行浏览器工具栏：后退／前进／刷新、地址栏、元素选择／截图／浮层／菜单；地址栏按 Enter 打开 URL，非 URL 文本在新标签页搜索。跨域页面以 iframe 打开；同源地址不在沙箱中预览，改为引导至新标签页。最近使用记录只存在本机浏览器 localStorage（最多 12 条），可删除或清空；跨域 iframe 明确禁用元素选择、截图和浮层。v4 公共入口是 `3224`，v3 的 `3223` 不共享登录或数据。内嵌页保留展开、关闭和返回 PM 上下文。

#### 桌面端原生 Browser

桌面版（Electron）的 Browser surface 使用受控 `<webview>` 而不是 iframe。工作区窗口新增最小 `desktopWorkspace.preview` preload；主进程 `PreviewManager` 为每个 Browser tab 维护独立 preview session、导航状态、标题、favicon、截图、元素选择和 PiP。地址栏、前进/后退、标题和加载状态由主进程的 `did-navigate` / `page-title-updated` / `page-favicon-updated` / `did-start-loading` 事件同步，Browser 标签标题跟随页面标题；元素选择或截图先进入批注确认，明确添加后才加入 Composer，不自动发送。元素批注可选择附带真实截图；截图失败时保留批注并提示，不伪造图片或源码位置。浮动预览是只读帧流。桌面端可以预览同源或跨域地址，guest 使用独立 partition，不共享工作区 cookie。

原生预览只对**本地工作区**启用：工作区窗口以 `--pm-native-preview` 启动参数决定是否暴露 preload bridge；远程工作区不注入 bridge，继续使用 iframe fallback，避免远程页面驱动本机网络访问。

安全边界：连接窗口仍禁用 webview；只有工作区窗口启用 `webviewTag`，`will-attach-webview` 校验 partition、http(s) URL 和预置 preload，并强制 `sandbox:true`、`nodeIntegration:false`、`webviewTag:false`。preview session 只允许 http(s)/data/blob/ws，权限只允许剪贴板写入和全屏；IPC 只接受工作区主 frame 且必须是当前工作区 origin。纯 Web（`3224`）没有这些原生能力，继续使用 iframe fallback，元素选择/截图/浮动预览按钮会显示“仅桌面版可用”。服务端无头浏览器流尚未接入。

新会话及成功读取的空历史显示当前文件夹名称和居中输入框，纯对话不伪造 PM 项目名；已有消息时输入框停靠底部。Composer 左侧排列模型、原生能力选项和交互模式，右侧放任务引用、会话／Local 环境引用、附件、可选听写及发送/停止；输入框呈现本次消息已选 PM／原生上下文 chips、附件和真实错误提示，不再显示上下文标题、未引用说明、工作目录或执行策略文案；工作目录在会话详情查看。历史读取失败明确阻止发送并提供“刷新重试”，不冒充空会话；刷新仍遵循现有文字草稿恢复和附件/引用丢失提醒。

当前只面向本机单操作者适配；尚未按 PM 成员建立 Agent 会话所有权隔离。不要将目录绑定视作多用户授权或文件沙箱，也不要据此开放公网使用。本次不新增权限体系；PM 工具继续逐次核验原有身份、成员能力与业务边界。

PM 中“Agent 助手”是文字与向下箭头合并的圆角下拉按钮：点击后先显示当前项目已配置的快捷自动化，“新增自动化”直接进入现有编辑器，仅全新配置默认勾选快捷入口；无项目时必须明确选择。菜单最下方“前往 Agent Chat”进入独立 Chat，并保留返回 PM 地址和明确的业务引用入口，不把 PM 范围设为 Session 所有者或代码目录。菜单也提供自动化管理页与运行历史。Agent Chat 自动化控制台中已保存的定义，可从详情的“设置 PM Agent 助手快捷入口”进入原编辑器，勾选并保存后出现在所属项目的 PM 菜单；取消勾选并保存即可移除，不复制定义。辅助 Chat 的返回配置链接仍恢复原草稿或定义，建议须审查保存，不从消息自动创建或启用。配置方法、确认规则与原请求核对见[PM Agent 助手快捷执行](automations.md#pm-agent-助手快捷执行)。快捷执行不自动发送 Chat 消息，也不以 Run 成功完成业务任务。

#### 项目流程：从空项目到任务闭环

自动化导航中的 **项目流程** 提供四个可编辑阶段草稿，不是后台自动化或无人值守调度。打开菜单、选择阶段只读取并核对 PM 引用、向标明的当前会话追加消息，不发送、不调用模型、不写入业务，也不替换已有文字、附件或引用。准备完成后返回 Chat 前仍核验最新的自动化草稿／待决操作离开守卫，不因读取请求完成而强行跳转。检查草稿后仍须点击发送；实际执行需要当前 Provider、PM 登录／项目权限及已核验的代码目录。

输入框不再放置项目流程或“回复显示方式”菜单；默认／计划交互模式保留，回复显示偏好仍可在设置中调整。

1. **选择目标。** 先打开目标代码目录的 Session，再进入“自动化 → 项目流程”，在菜单的“选择项目与任务引用”选择实际授权工作区和项目；空看板也可选。以 RunLedger 为例，PM 项目和本机实际 RunLedger 代码目录是两个独立目标：代码读取使用已打开该目录的 Session，不因选择同名项目自动改绑。每个安装都须选择自己的真实目录。
2. **盘点并建板。** 草稿要求读取源码入口、现行计划与实际状态，完整分页读取已有任务／文档，再按目标、来源和验收去重。用原生 PM 工具建立缺失任务及项目基线／建议文档，并读回真实 ID；不把“文件已存在”当验收通过，不覆盖仓库已有未提交改动。`pm_query` 每页最多 20 条，必须沿 `nextCursor` 读取后续页；失败或结果未决不能解释成空项目。
3. **寻找下一项任务。** 只读核对任务、执行简报、关系和阻塞，给出优先建议；不自动选中任务、修改代码或转状态。随后通过引用选择器添加目标任务，并在菜单中明确选择一个执行／验收任务。只有一项引用也不会自动选择；切换项目或 Session 清除执行选择，不删除其他草稿引用。
4. **执行所选任务。** 发送后按该任务验收和非目标实施，先核对当前 revision／简报／评论／依赖和目录，在 PM 评论中记录开始、进度、检查与阻塞；默认不完成任务，不自动 commit、push 或部署。任务或引用已变化时先显式刷新，不能悄悄采用新版本。
5. **验收与报告。** 检查并发送该草稿才授权本次验收及有证据支持的完成。Agent 须调用 `pm_read_workflow` 读取真实状态、类别和合法转换，不硬编码状态或额外强加审核；满足条件后以当前 revision 转换并读回。失败、未验证或未知结果保留未完成状态与缺口，原 operationId 核对，不重发未知写入。验收记录写入任务评论，阶段报告保存为项目文档并读回，回复真实链接、执行证据和剩余风险。

`pm_read_workflow` 沿用原生 `domain.read` 权限，不增加完成规则。工具卡显示**读取时**的配置来源／revision；历史成功不是当前配置仍有效的证明。重复读取或核对发现配置变化时拒绝返回旧配置，应发起新的只读操作。上述阶段是可检查的 Agent 指令，不是模型必然执行成功的保证；以实际工具收据、任务状态与报告读回为准。会话与持久化仍暂沿用 Agent Chat，统一设计尚未收口。

并发工具调用和消息流会重新核验当前 PM 权限。服务端在工作区事务内复用已有数据库连接完成就绪、文档来源及任务／评论访问检查，避免连接池占满时合法查询或写入等待超时；不缓存正向授权，也不放宽撤权、项目有效性或 revision 检查。若出现“当前不可访问”或“结果未决”，先核对服务与原操作结果，不解释成空看板、不重复未知写入，也不要通过读取旧 `access.json` 或扩大权限绕过。

Chat 的原生 `pm_get_operation_result` 只接收 `{"arguments":{"operationId":"原操作 UUID"}}`。服务端从当前 Chat 的持久化记录读取原请求，重新核验当前执行、PM 身份和目标授权，再核对原结果；模型不需要重建参数，也不需要从受限 shell 连接临时工具端口。该工具不会创建操作、批准待审批操作或重新执行业务命令。缺少权威结果时仍返回未决，不能仅因看板暂时没有同名任务就认定原写入失败。


#### 本次消息上下文与新增记录策略

- **Session** 保存消息、Provider、执行目录和历史，不归属于某个 PM 项目。同一 Session 的不同消息可以引用不同已授权工作区／项目；引用不改变代码目录。
- **TurnContext** 在服务端受理输入用户消息时冻结，包含 threadId、输入 messageId、明确 PM 引用及 revision、可选的服务端执行记录引用，以及已受理的原生 `contextItems`。它不绑定 assistant 输出 messageId。**PM 引用仍只是受理时核验的实体／任务 revision 元数据，不是正文快照或操作许可**；旧版本不匹配时要求显式刷新，不拿当前正文冒充旧版本。原生上下文则按下表冻结核验后的选区或用户快照，两者不混为一种授权。
- **新增执行策略固定为 `full / audit-only`**：自动记录与提醒，不新增允许／拒绝选择、逐次放行、额外启用开关或基于新增 grant 范围／时间字段的操作限制。`executionGrantId` 只引用服务端来源记录；客户端不能声明 actor、grant 或权限。既有认证、PM 成员／项目权限、OAuth 委托与撤权、目录身份、revision／CAS、幂等及明确配置的审批仍生效。
- 发送前捕获本次引用与原生上下文；服务端确认受理后只清除这批未再修改的草稿，保留发送期间新增、修改或重新选择的内容。受理前失败保留草稿；结果未知不盲目重发。历史消息的“本条消息的 PM 上下文”从服务端读取冻结快照，“复用到下一条消息”只复制引用到草稿，不恢复权限或改变目录；无需先选择 Provider。
- 会话与持久化仍沿用 Agent Chat，整体统一设计尚未收口。本次消息级不可变绑定不代表该设计已经完成。

原生上下文使用 t3code 风格的来源 chips、详情浮层和回复引用卡；**添加只进入当前草稿，不调用模型、不执行命令、不修改 PM 业务**。每次最多 20 项，单项来源文本最多 16,000 字符，来源文本与评论合计最多 48,000 字符；有界会话／原生输出摘录会明确标记截断，明确选择的受保护内容不能被静默裁掉后发送。

| 来源种类 | 入口与实际语义 |
| --- | --- |
| `terminal` | 在真实 xterm PTY 中选中文字，右键“添加到对话”；添加时重读实际选区，并核验 terminal／service 身份、目录及当前 Session 的实际执行根／Worktree。它是**用户选择的终端快照**，不是服务端对输出内容的独立证明，也不是随意粘贴的“命令结果”。已结束的原生命令输出也可从 `Reference output` 引用其真实 generation／item。 |
| `review-comment` | Files 源码／Git Diff 的行号或 gutter 选区可附评论后添加。文件行号从 1 开始且首尾包含；Git 同时保留实际 patch 行范围、old／new（删除／新增）侧的起止坐标及 staged 状态，以所读完整 content／patch 的 SHA-256 核验，反向拖选不改变原侧语义。文件树“添加到对话”仍是原文件 mention，不冒充选区快照。手动 PR 链接只引用用户提供的 URL，不查询远端标题、审核或合并状态。 |
| `preview-annotation` | 本地桌面 Browser 的截图／页面批注由用户明确捕获、确认，保留真实 URL、标题、捕获时间及可用的图片附件；不是服务端抓取 URL。 |
| `element` | 本地桌面 Browser 的真实元素选择可附评论及可选截图；仅保留实际返回的 selector、文字、tag、位置、DPR 等元数据，不补造组件栈或源码定位。纯 Web iframe 不提供元素选择／截图，服务端无头浏览器未接入。 |
| `thread` | 输入区“引用会话或本机环境”明确选择可访问的已有 Session，固定其真实分支 head，读取有界历史；不随来源继续生成而悄悄换成最新会话，也不授予该会话或其 PM 项目的权限。 |
| `environment` | 同一选择器只提供“当前 Local 执行环境”，核验真实目录／Worktree 身份；不是远程 host 登记、环境切换或文件沙箱。 |
| `response` | 选中已结束回复的文字后引用，只采用**实际选中的连续文字**，半行也不扩大为整行／整条回复；引用评论与原文分开保存。原生输出的 `Reference output` 绑定真实消息、generation 和 item，运行中、歧义或缺失来源明确拒绝。 |

- **先核验，后受理。** 草稿解析是只读检查，不是已保存证明；发送、排队、暂存及恢复仍核对当前权限、来源版本和执行环境。来源变化须重新选择，不能用新正文替代旧选区；复制／粘贴与历史编辑携带结构化输入并重新核验，不信任剪贴板自称的 accepted／授权记录。
- **来源导航不执行。** 引用详情可定位原文件／Diff、Session／回复或原生输出；打开前重新核验，找不到或已变化时明确不可用，不回退另一条记录。Browser／PR 来源只由用户明确打开新标签页，不触发服务器 URL 抓取；终端快照查看不会打开旧进程或重放命令。
- **历史保存与当前可见性分离。** 历史使用服务端冻结记录，不从当前磁盘重建旧正文；撤权或源删除后投影移除相关正文、评论、路径、URL、标签及关联附件，不仅盖一层 UI，也不从缓存复制／恢复。引用源删除不删除目标 Session 的历史、队列或暂存；不可用引用不能被静默丢弃后继续发送。原生续聊受到来源污染时改用重新授权的可见历史，不沿用受污染游标。
- 未显式保存的选区、截图和撤销历史只是页面内存，刷新不保证恢复；持久保存边界见[队列、草稿暂存与活动引导](#队列草稿暂存与活动引导)。图片／文件仍走实际附件传输；当前原生附件桥支持 Codex／Claude，其他未支持的驱动明确拒绝，不把附件降为文字冒充成功。真实 Provider 账号／模型消费和桌面 GUI 捕获仍须单独验收，本页不证明已部署。


#### 任务执行简报与知识候选

任务详情的「执行简报」读取当前任务 revision，可切换分析、开发、审查、恢复四个阶段；查看、刷新和切换不创建 Session、不调用模型、不修改业务状态。它展示原文、已有验收／约束／非目标、正式关系、来源定位和缺口，不由模型补造“已确认验收”。分页或预算裁剪会明确阻止交付派发，不能忽略尾部约束继续执行。

- 普通 Chat 收到明确任务引用时，会提示 Agent 实际调用已提供的只读 `pm_task_brief`，携带 `projectId`、`taskId`、当前 `revision` 与阶段；没有工具的轮次不能声称已经读取。交付／工作流在实际派发前读取同一简报，保存实际输入消息及来源，和之后重新生成的当前简报分开展示。
- `pm_search_knowledge` 使用明确检索词，默认只检索当前项目；跨项目须显式列出同工作区内当前有权读取的项目。当前为确定性词法检索，不依赖 WeKnora／向量服务。候选一律为 `needs_review`，保留原文、revision 和替代／失效文字，不把命中当作有效决策或自动写入长期记忆。
- 来源查看会重新读取并核对实体、项目、类型和 revision；版本变化须重新检索／读取，撤权清除敏感内容，失联显示过期而不是空成功。历史简报／知识工具结果也不能绕过当前权限和来源版本核对。
- 重复读取、并发受理和 `pm_get_operation_result` 恢复同样核验工作流、任务简报及知识结果的新鲜度。当前来源变化时拒绝交付旧正文，保留原操作的历史成功事实；不会把旧成功改成失败，也不会自动重发，需显式发起新的读取。
- 在完整当前快照中，简报／知识请求因旧 revision、无权项目、失效游标或没有有效检索词被明确拒绝时，原 `operationId` 保留为 `failed`，重复调用和结果查询不重新执行。源文件读取故障、保留最后可用记录的 stale 状态或扫描遗漏来源不能证明权威拒绝，仍保持 `unknown`；恢复后如需重新读取，应显式发起新的只读请求。两种结果都不改变业务任务状态，也不授权重放未知写入。
- Skill 安装或目录可见不等于本轮已加载／可调用；阶段引导只报告真实 Provider 基础能力，不编造 Skill 执行能力。OMP Skill 调用仍禁用。

交接、版本新鲜度和原操作核对见[任务代码交付](task-code-delivery.md#执行与交接简报)。会话与持久化仍暂沿用 Agent Chat，统一设计尚未收口。



#### PM 文档、代码目录与终端

- **PM 文档**继续由 PM 管理。Agent 通过带明确工作区／项目目标的工具和引用读取 PM 资料；不把 PM 文档存储自动挂载为代码区。一个 Git 只管理一个独立文件夹，Git 面板不会借用父目录仓库。
- **打开文件夹**只登记服务器上的已有目录，不上传浏览器文件、不创建目录、不复制仓库。允许范围由 Agent 角色的 `AGENT_WORKSPACE_ALLOWED_ROOTS` 配置为绝对路径 JSON 数组，未设置时使用服务用户 Home。目录记录保存在 Agent SQLite，规范路径与设备/inode 身份不可改写；缺失、替换、越界或符号链接改指时拒绝，不自动重建或回退。原 Code Workspace 登记页及其 PM API 已退役。
- **选择文件夹：** 本地桌面工作区提供原生“选择文件夹”按钮；Web／远程工作区浏览的是服务器目录，并显示当前允许根。桌面 Agent 显式允许当前用户 Home、应用受管项目目录及配置的项目父目录；更改桌面配置后需重新连接。选择器不绕过服务端规范路径和目录身份核验，其他目录仍须由操作者明确配置允许根。
- **Session 环境**使用 v2 `agentWorkspaceId + agentWorkspaceRevision`，不再保存 PM 归属、代码组合或 `rootIds`。重命名、关闭、重新打开只增加元数据 revision，不使原 Session 改绑或失效；未来版本仍拒绝。Files / Git 按 Session 与相对路径读取同一实际执行目录；受控交付指向收据拥有的 Worktree，原生仓库模板显示实际仓库副本路径而不冒充 Worktree。
- **多个仓库**分别打开为不同的 Agent Workspaces，各自创建 Sessions；不存在把多个根拼成一个 Code Workspace 的运行层。普通代码会话、文件检查、Git、终端和原生 Skills 目录解析不依赖 PM 登录或 PM 服务可用。
- **纯对话**不要求代码仓库。服务端在 Agent 私有数据目录的 `chat-scratch` 下按 Session 分配 scratch 并保存目录身份；Files / Git / Terminal 不把它展示为代码环境。已登记 scratch 丢失或身份改变时拒绝重建；PM 文件区域与保存根配置不是执行回退。
- scratch 仅在新建时设置平台私有权限；复用时只核验，不自动收紧或接管已有目录。Unix 核对所有者与私有 mode，Windows 核对原生 ACL、目录身份及 reparse 属性，不将 POSIX mode 当作 Windows 权限证明。遇到身份或权限错误应核对原目录，不通过删除登记或重建目录绕过。

| 终端 | 起始目录与切换行为 |
| --- | --- |
| Workspace Terminal | 显式选择的 Agent 文件夹／子目录；跨 Session 保留，隐藏与停靠切换只重附着 |
| Session Terminal | 当前 Session 的实际目录／Worktree；切换 Session 或显式改绑目录时立即脱离旧 PTY，新目录终端须明确创建 |

文件夹菜单可以从该目录打开终端；终端内 `cd` 不改变 Agent 主目录。服务端在本次进程生命周期内拥有 PTY，校验目录身份和 Session 执行身份，保留有界输出用于重附着。创建请求有稳定 ID，未知输入不重放；当前终端视图不提供范围、实例、终止或重新附加控件。**不支持跨 Agent 服务重启存活**：旧终端不可用，不恢复进程、不重放命令，用户须明确创建新终端。

关闭文件夹仅改变目录元数据；只要原目录仍可用且身份匹配，已有 Session 可以重附着原绑定终端。关闭的目录不能用于新建 Session；目录丢失、被替换或权限失效仍拒绝，不以旧终端记录回退。

Inspector 请求携带当前 Session，不接受浏览器任意 cwd 或旧 `rootId`。Terminal 使用服务进程的本机 shell 权限，不是文件沙箱；它与 Provider 共用原生环境过滤规则，保留正常 CLI 环境，但不继承服务端 PM 凭据、Agent 私有控制变量或加载器注入变量。`Ctrl / ⌘ + Alt + B` 切换右侧面板；网页预览继续保留 iframe sandbox。


若已打开的页面在更新后点击面板出现“页面暂时不可用”，还需检查动态模块请求，而不是重发消息。本机 Web 重建现在保留旧哈希资源，避免已打开页面依赖的模块被删除；历史资源只在停机维护时清理，见[部署手册](../../deploy/README.md)。修复前已经缺失的模块仍需手动重新加载一次页面；不会自动提交、重试消息或取消后台生成。

#### Chat 设置

统一入口为 `/agent/settings/general`；设置页共用导航和未保存 / 保存中离页保护。服务配置适用于本机 Agent 的全部目录与 Sessions，不是新增的 PM 权限或项目级 Provider 覆盖。

PM 首次使用引导可打开提供商设置，并通过“返回首次使用引导”回到原工作区；尚未通过 Agent 访问验证时也保留返回入口。该跳转只接受本项目的工作区引导路径，沿用现有未保存保护。引导读取配置状态而不自动登录、导入凭据或调用模型，允许稍后配置；PM 登录不替代独立 Agent 验证。完整步骤见[首次使用指南](getting-started.md#登录后首次使用引导)。

设置布局参考 t3code 的“全宽外壳与独立正文宽度”分层：PM 设置导航贴齐主工作区左侧内边距，不再与正文一起限制在 1440px 居中容器；Agent 设置侧栏保持贴左，正文紧随侧栏左对齐。两者正文最大宽度为 1160px，避免超宽表单；窄屏保留 PM 页面选择器，Agent 导航可展开收起，不按 2560×1440 固定比例缩放。布局调整不改变保存、权限或会话持久化。

当前会话参数保存会先采用客户端已接受的较新会话 revision，例如刚完成文件夹选择后的返回快照。尚未观察到的真实并发修改仍返回冲突；失败保留本地草稿并阻止发送，用户明确点击保存／重试时重新读取当前 revision 再提交，不自动重放失败写入或修改全局默认值。

模型目录浏览复用同一 Provider revision 的真实状态快照，30 秒内不重复探测，过期时先返回已有快照并后台刷新；没有快照时仍等待首次真实检查。刷新失败会标记未知／不可用，不把旧成功永久当作就绪；配置、认证与维护变更使旧状态失效。浏览器合并同时发生的目录请求，网络失败保留上次目录供查看和选择但阻止发送，401／403 清除旧目录。显式“检查 Agent”和执行前校验不使用目录缓存跳过检查；目录中的检查时间仍为实际观测时间。

Provider 集合为 Codex、Claude、Cursor、Grok、FX、OpenCode、Antigravity、Muse Code、Pi、OMP（Oh My Pi）、ACP Registry。初始化仍只持久创建 Codex / Claude；其他默认位仅在已配置、有效启用或定向访问时显示，浏览页面不创建实例。FX 位于“显示更多”，ACP Registry 为独立搜索 / 准备入口；Registry 先显式准备，再填写身份并按协议认证，local 命令走较短路径。实例 ID 固定、字母开头、最多64字符，显示名称可清空回退驱动名；默认实例可重置，额外实例可删除。普通字段失焦或 Enter 保存，环境变量和模型显式保存。非敏感环境变量可回显编辑，敏感值遮蔽且空值回传保留；旧环境变量默认按敏感值迁移。模型段统一管理隐藏、排序、收藏、自定义能力选项；Antigravity 不开放自定义模型。独立 OpenAI / Anthropic / DeepSeek API 卡片及新执行入口不恢复，原始历史和私有凭据不删除。

新安装的 Codex／Claude 是**未启用的配置入口**，不是已经连接的账号；查看卡片也不选择会话模型。需显式启用、检查并选择模型，已有实例的启用状态与模型偏好不会被重置。显式重置默认实例也恢复为未启用。

适配以 `t3code@30eb7e7bb1ef103fdd6f54081b6a4acf66b3ee4c` 为配置与协议基准；MIT 归属见 [LICENSE.t3code](../../LICENSE.t3code)。Codex 通过“使用现有 CLI”与“继续使用 ChatGPT”进入对应流程，不再展示模式下拉框。existing 复用原生配置 / 外部认证，可使用 API Key 或第三方服务，不强制 ChatGPT 登录；managed 使用受管运行时、ChatGPT 多账号 OAuth / token broker，私有状态保留在本副本 `provider-homes`。Claude 的四种 idle compaction 模式接入实际宿主调度并重新核验执行身份；业务来源仍受原授权上限约束。Cursor 的 `CURSOR_API_KEY` 位于专属 Setup，填写密钥后隐藏浏览器登录，清除并保存后恢复该入口。Grok / FX / Muse / Pi / OMP 与 existing Codex / Claude / OpenCode 遵循来源的外部认证边界，不另造应用内登录 / 登出。

**CLI 与 SDK 的交付边界：** Claude 使用服务机器／桌面用户已安装的 `claude`，也可在 Runtime binary 填写其实际路径；未安装、不可执行或路径错误时明确失败，不回退到 SDK 自带 CLI。安装包保留 Claude 通信 SDK、manifest 与许可证，但排除 `@anthropic-ai/claude-agent-sdk-*` 平台执行包。Muse 同样通过用户的 `muse serve` 通信。Cursor 当前使用本地 Agent SDK 引擎，并不是用户 Cursor CLI 的包装器；其 SDK、SQLite、搜索／sandbox／tree-sitter 等必要资源仍保留，旧 `binaryPath` / `apiEndpoint` 字段不控制当前执行，不能把它宣传为已完成外部 CLI 适配。

这不移除现有明确选择的安装流程：Codex managed、Antigravity managed 和 ACP Registry 各有原生准备／安装语义。ACP 的 npx / uvx 状态探测还可能解析并准备 Registry 包，不能概括成所有 Provider 的检查都绝不下载；该行为与桌面安装包预捆绑外部 CLI 不同，本次未重做 ACP 安装流程。

桌面随包 Node 仅用于运行应用，不包含 npm/npx。ACP 的 npx 分发路径需要有效 Provider 环境 PATH 中另行安装的 npm；缺失时检查返回缺少 runner，准备操作明确失败，不自动补装工具链。此边界不改变操作者配置的原生 CLI Home、环境覆盖或已明确触发的 Provider 安装流程。

安装、更新、取消与移除仅对实际支持的驱动开放；“继续使用 ChatGPT”先准备运行时，再发起登录，Codex 的只读检查或发送消息不会自动下载。维护与认证 / 执行互斥。原生 Home 留空时继承宿主规则，显式 Home 和实例环境覆盖对应配置，不重写进程 HOME / XDG，也不清除宿主 Provider 凭据。应用自有状态与原生 Home 分离，重置、删除和备份不收集、创建或删除外部 Home。PM 作用域、审批与完成规则不变。

Codex 执行仍要求本次原生操作确认同一个 Home。Windows 路径命名空间、分隔符或真实目录别名不再仅因字符串不同被拒绝，但必须由当前文件系统的规范路径／目录身份证明一致；不同、缺失或无法核验的 Home 仍拒绝执行，重连不会跳过证明。

原调查和前两轮实施保留为历史记录；旧的强制独立 Home 与配置文件教程已被替换。


##### 配置并使用 Provider

1. 在“提供商”选择已有实例，或“添加提供商”。Codex 选择“使用现有 CLI”复用服务所在机器的原生配置；只有选择“继续使用 ChatGPT”才走受管账号连接。
2. 原生 CLI 已可用时，无需填写 Home 或重复登录。需要覆盖时，使用驱动提供的 Runtime、Launch arguments 和 Environment；实例变量覆盖同名宿主变量，敏感值只写入、不回显。页面不展示额外 `config.toml` 路径或要求编辑配置文件。
3. 保存后“检查 Agent”，回到会话选择 Provider / 模型并发送消息。新会话未设置默认模型时，选择器也会展示可用 Provider 的模型；浏览列表不自动选中，须明确点选后才保存当前会话选择。原生 `account/read` 明确 `requiresOpenaiAuth=false` 时可就绪、身份仍未知；缺失 / 非法报告和真实认证失败不推断成功。managed 仍要求有效 ChatGPT profile。

状态检查不执行计费推理，不能证明远端接口、密钥或模型可用。真实模型、受管 OAuth、各供应商账号、额度与平台专属能力必须分别验收，不能由状态检查推断。


##### OMP（Oh My Pi）

OMP 是新增的独立 `@t3tools/provider-omp`，不是 Pi 命令别名。协议基线为 OMP `18.13.2`；实施计划、来源与分层验收见 [OMP 适配说明](agent-chat.md)。本次未发布或重启 `3224` 常驻服务。

- 在服务机器外部安装并认证 OMP；添加“OMP / Oh My Pi”，Runtime binary 默认 `omp`，也可填写实际可执行文件绝对路径。应用不代装、登录、更新或复制账号；保存后检查、明确选择发现的模型再发送消息。认证未知与运行可检查并不矛盾，也不代表推理成功。
- 原生 Home / 实例 Environment 按 OMP 自身语义生效，支持 `OMP_PROFILE`、`PI_CODING_AGENT_DIR` 等原生目录变量；不使用 Pi 的 `~/.pi/agent`。Profile 不替代显式 PM 工具目标、执行身份、revision 或 session lease，也不能绕过启动预检。
- stock OMP 无法通过一个开关关闭所有环境扩展 / 插件 / MCP。适配器启动前只检查相关路径元数据；存在无法证明安全的启动源时明确拒绝，含可能触发原生加载的 `.claude.json`。必要时明确指定无这些启动源的 Home / 项目目录，不通过启动参数绕过。该门禁不是操作系统沙箱，不读取或清除全局凭据。
- 原生工具权限遵循现有 PM `deny-ungranted`；PM 工具通过 OMP Host Tools 进入既有授权和业务审批。技术性标题 / 压缩生成显式无工具；Fork、Rollback、主动子 Agent、Goal、原生历史 Usage 和账号额度读取未开放。
- 已用真实 OMP + 受控模型验证流式、取消、多轮及重启恢复、真实 PM 查询与审批 / 拒绝，并在网页观察配置、选模、历史恢复与取消。真实模型验收尚未通过：本机 Ollama 返回 `unable to load model`，未改动该服务或读取供应商账号。运行事件 Usage 不等于历史扫描或订阅账单。

#### MCP、原生 Skills 与交互 Apps

MCP、Skills 与交互 Apps 的源码能力须与实例部署、实际账号及授权前提分别核对。

设置侧栏统一使用 **MCP** 入口，页内分为“MCP 服务器”（Agent 使用外部工具）和“外部访问”（外部客户端访问本系统）；切换分区保留 URL 中的 Provider／上下文与工作区／项目参数，并沿用未保存草稿及操作进行中的离页保护。

- **MCP 管理：** `/agent/settings/mcp-servers` 只显示已启用并绑定的 Agent / Provider 实例；同一用户 Home 下路径兼容且尚未启动管理服务的 Provider（如 Codex / Pi / OpenCode）可共用一个管理上下文，MCP / Skills 矩阵同时显示这些 Agent 列。不同 Home、同类实例的不同原生根及不兼容的 Claude 路径拼写分别管理；停用的 Provider 实例不会进入目标列表。已有独立配置库不自动合并。页面使用“已安装 / 探索 / 配置”管理连接；后端从 Provider 的真实配置解析目标；同类实例显示独立名称与实例 ID，不按“Codex”等类型名称混写。原生导入先只读预览，再逐项应用；保存、文件同步和显式连接探测分别展示，不把“已保存”当成“已连接”。
- **Skills 管理：** `/agent/settings/skills` 与 MCP 共用已启用 Provider 的管理上下文，提供“目录 / 发现 / 配置”、筛选、Agent 覆盖、分配矩阵和详情抽屉，以及真实发现、ZIP 安装、原生导入、更新与备份。MCP 与 Skills 页面间保留同一管理上下文；有草稿或操作进行中不能切换。安装不等于运行时已加载；Pi / OMP 的目录观测也不是安全隔离或可调用证明。
- **Dovspace 内置 PM Skills：** Skills 页提供九份随 App 打包的分析／审阅与流程 Skill，显示 Dovspace 来源、原始相对路径、内容 SHA-256 和真实安装状态。选择已就绪且支持扩展的 Provider 后明确勾选安装；不要求额外下载仓库或自动安装 MCP。初始化引导的可选 AI 步骤也有相同入口，跳过不影响完成引导。完整目录及外部分发步骤见 [Skills 说明](../../.agents/skills/README.md#app-内置安装与外部分发)。
- **内置安装与更新保护：** 查看目录、连接 Provider 或升级 App 不自动安装。写入绑定当前资源摘要及 Provider 原生根身份；同名未托管、用户修改或身份变化明确拒绝，不覆盖。更新共享配置库时会核对所有已有分配并提示跨 Provider 影响；响应未知先重读结果，不自动重发。来源记录随托管备份／恢复保留，但安装或恢复成功不表示活跃会话已重新加载，更不表示模型调用、认证或 PM 写入成功。
- **本机已安装 Skills：** 页面单独只读扫描当前绑定 Provider 的原生目录及受支持的共享 `.agents/skills`。扫描不自动加入配置库、分配、同步或启动 Skill；“纳入管理”是明确导入动作，之后仍需显式分配。导入固定所选 Skill 根及目录／文件身份，保留经核验的根和内部路径别名，拒绝越界目标、循环或无法核验的 Windows reparse；文件描述符身份／时间戳复核和私有暂存完成后才发布管理副本，不把别名当作扩大授权。远程机器的 Skills 不会被当成本机目录读取。
- **目标与保存位置：** 后端内部保留配置记录，不再作为用户绑定流程。兼容且尚未启动的上下文可以扩展绑定；已启动的管理服务不因新增目标被关闭，新目标使用独立上下文。实例 revision 更新且原生根未变时原位重新核验，保留定义、事件订阅和待重新加载状态。跨 Home 的物理根重叠、已登记根的符号链接改指等冲突明确拒绝，不自动搬迁或导出旧配置，也不删除已有定义和 Skills。共享目录的影响显示在目标详情。没有支持扩展管理的 Provider 时，MCP 仍可浏览公开目录，Skills 明确显示尚未读取，入口引导至 Provider 设置，而不是要求额外授权。
- **新增 Provider 与已保存配置：** 保留 `context` 的页面只重新核验所选上下文的原生归属，同时单独读取全部已启用实例，Provider 选择器仍可显式切换到新 OpenCode 的独立上下文。无关的已登记外部宿主上下文不会阻止访问，也不会被自动扩张或重新绑定；所选上下文失效、目录变化或真实归属冲突仍拒绝，不静默改选其他配置。不为合并列表重启活跃管理服务。远程／自定义 OpenCode 无法可靠映射本机扩展目录时显示不可管理原因，不静默消失，也不凭 loopback 地址假定拥有本机 Home。
- **保留的边界：** 仅已有 Provider 的正常管理使用上述直接流程；宿主登记的外部 CLI 仍使用其明确登记/绑定流程，不开放浏览器任意路径。旧的明确配置链接仍访问原数据；项目私有配置仍受 PM 身份与范围检查，不导出到原生 Home。MCP 自身的 API Key / OAuth 和项目工具审批不因配置页面简化而取消。事件流断开时暂停新写入，重连只重读状态，不重放操作；结果不明确时先刷新核对，配置变更不会自动重启活跃原生会话。
- **外部连接：** MCP 设置的“外部访问”（`/agent/settings/mcp-servers?section=external`）提供连接地址与已授权客户端撤销。部署未配置或元数据读取失败时明确显示外部访问尚未就绪，下方仍保留 PM 登录及已有授权的查看／撤销；不把读取失败当作没有授权。外部 HTTP MCP 客户端经 `/connect-agent` 完成既有 PM 登录主体同意、授权码与 S256 交换，再访问 `/mcp`。原 OAuth 默认只读与明确工作区／项目上限不被新增 full/audit-only 记录扩张。直接 PM 工具使用独立外部执行根，无需创建 Chat Session；访问 Chat 仍须原有显式纯对话线程委托，不能取得代码目录权限。可访问 Session 中失权的 PM 项目结果逐项占位，其他已授权结果保留。full 不绕过既有审批；外部 token 不可登录普通 PM／Agent API，也不能枚举同项目的全部历史。
- **原生工具：** 工具注册在本机读取真实 schema，不为启动普通代码会话访问 PM。`pm_list_workspaces` 只发现当前授权的业务 ID／名称，不选择目录或 Session 所有者；其他 PM 工具每次明确携带 `target: { workspaceId, projectId }`，可在同一 Session 内访问多个已授权目标。PM 不可用时未派发的请求拒绝；已可能派发但没有权威结果的调用保持 unknown，不能仅凭 HTTP 状态码确定失败。普通代码环境仍可用。当前成员能力、审批、revision、幂等与原结果核对不变；Chat 成功不会完成 WorkItem。OpenCode 的单 transport、Pi 的 generation-owned 扩展、OMP 的单 `pm_tools` Host Tools 桥仍有各自限制。
- **查询参数与错误：** `pm_query.limit` 必须是 1–20 的整数，首页用 `after: null`，后续新查询把 `nextCursor` 作为 `after`。Agent 在派发前按同一业务 schema 校验参数，非法输入保存为明确失败，并说明字段限制及未发送 PM 命令；修正参数使用新的操作 ID，不能修改旧 ID 对应的参数。历史未决的非法 `pm_query` 可在当前授权和原身份/哈希核对后明确拒绝，不重发；这不把未知写入或普通 HTTP 4xx 当成无副作用证明。
- **工具通道与只读盘点：** 优先使用当前会话暴露的原生 PM 工具；generation-scoped CLI 仅作没有原生工具时的回退。临时 loopback 地址不是常驻 PM API，受限 Shell 无法访问它不代表原生工具也不可用，不因此修改网络安全配置。PM 查询失败时可以继续已授权的仓库只读盘点，但候选任务必须注明尚未与 PM 现有任务去重，暂不写入；缺少可选本地工作流助手不要求安装，也不阻断普通只读工具。
- **原生权限状态：** 自动批准只有在 Provider 响应成功后才显示已批准/已完成；运行结束或中断不会把已确认的批准改成已取消。拒绝、取消、过期和响应失败不冒充批准。旧卡片缺少结构化批准证据时保留原历史，不根据标题或提示文案回写；原生批准仍不代表 PM 写入、任务完成或验收通过。
- **Skills 与文件引用：** 全页和 PM 内嵌 Chat 共用 Composer 的 `@` 文件、`$` 原生 Skill 与 `/` commands 建议列表及引用 chip；目录在输入、执行环境或实例变化时自动读取，Composer 不提供目录工具栏或 session 重启按钮。`@` 只搜索同一服务端核验的 Session 执行目录，跳过忽略目录与符号链接，不回落 PM 文档、来源目录或父仓库；选中后插入可移除的相对 Markdown 链接，发送内容不额外注入正文。Skill 目录绑定 Provider 实例／revision 和同一 cwd；失败、pending、空目录在建议菜单分别展示，禁用及不可由用户调用的条目不能选。原生安装／修改仍在各 Provider 支持的位置进行；既有 WorkspaceSkill 指令块不再从 Composer 进入，且不是通用 Skill 协议。
- **Provider 差异：** Codex 使用 `skills/list` 与原生 mention；Claude 保留 frontmatter／最后一个 Skill 展开；OpenCode 1.x 文本／命令与 2.x 结构化 IDs 不混同，目录只借用当前已授权且匹配的 live session，不为刷新启动插件／MCP；Grok／Pi 使用 leading mention，Cursor／FX／Antigravity 按各自发现和分派语义。Muse 只公布原生 commands，ACP Registry 只调用当前会话实际公布的 commands（虚拟 skill URI 不当作文件）；OMP 目录可见不等于可调用，Skill 调用禁用，命令仅开放既有 `session` 白名单。逐家真实账号／Skill 行为尚未全部验收。
- **MCP Apps：** 当前原生交互能力由 Codex adapter 提供；其他 Provider 保留真实工具结果，不假造 App 支持。类型化 producing item 绑定原 Server／thread／session；成功工具结果结束后可保留 live session，停止、配置／范围变化、显式重启、撤权或服务关闭使相应能力失效。历史可读不代表仍可交互，打开 App 不隐式启动新模型轮次。frame 使用 `sandbox="allow-scripts allow-forms"`，不含 `allow-same-origin`；工具确认不能替代服务端授权。App 模型上下文按产生项替换／清除，仅在匹配的有效范围／session 内送入后续轮次。

**部署前提：** Agent 配置固定可信 `MCP_PUBLIC_ORIGIN`，用于 OAuth issuer／公开地址，不从任意 Host／Forwarded 猜测。PM 配置私有 `PM_MCP_AGENT_URL` 指向可达 Agent；仅可回退已有 `PM_AUTOMATION_AGENT_URL`，没有猜测 localhost 的默认值。PM 与 Agent 使用既有服务端 `PM_AUTOMATION_SERVICE_SECRET`，MCP 委托采用独立 `pm-mcp-service-v1` 域／audience，不能把秘密放入 `VITE_*`、iframe 或外部 token。网关需显式代理 `/mcp`、OAuth 发现／授权端点及连接页，不能公开 `/internal`；公网客户端还需可信 HTTPS 与可达地址。本轮不自动配置公网，也不将单操作者 Chat 宣称为多用户隔离产品。

内部服务地址与 public issuer 分开核验：非 loopback 的内部 HTTP 必须由对应角色显式设置 `MCP_INTERNAL_HTTP_ORIGINS`（精确 HTTP origin 的 JSON 数组，默认 `[]`）。这明确接受可信私有网络上的明文传输；不可信网络使用 HTTPS。白名单不放宽 OAuth issuer／客户端 redirect，不自动信任服务名、私网 IP 或 Host，服务请求仍禁止重定向。Compose 分别声明既有 PM→Agent 和 Agent→PM origin，仍需上述共享密钥与真实 PM 同意。

撤销会拒绝后续访问并使相应 live 能力失效，但不承诺 Agent SQLite 与 PM PostgreSQL 跨存储原子撤销，也不把取消视作已提交动作回滚。离线备份的 `--secrets exclude` **和** `include` 都会使导出副本中的 MCP grants／tokens／consent 与 App model context 失效，不修改源数据库；恢复后须重新授权，不能恢复 live App 会话。

#### PM 工具结果、可见性与命令审计

执行事实与当前读者能否查看结果独立：

| 执行结果 | 含义与界面 |
| --- | --- |
| `pending_approval` | 既有部署审批模式要求批准；不是新增记录策略产生的门槛 |
| `running` | 正在执行 |
| `succeeded` | PM 已确认提交；展示当前有权读取的结果、原收据与命令关联 |
| `failed` | 已证明未成功；不把未知 HTTP 错误当作证明 |
| `unknown` | 是否提交尚未确认；显示“待核实”，没有失败结论、运行计时或执行重试 |

“核对原操作”始终使用原 operationId，不再执行一次。取消生成不回滚已提交业务；确认成功后，旧失败帧、结果读取失败或撤权不会将事实降级。旧 failed 没有可信结果证据时按未核实处理，不批量猜测成功。

PM 内部 `/api/v1/internal/agent-tools/reconcile` 只提供原身份／目标／请求摘要绑定的最小执行证明，使用既有服务端密钥、独立用途签名与持久单次 nonce；公开网关拒绝该路径。撤权后内部仍可核对事实，但不能向失权用户返回正文、参数、错误详情或收据。缺少服务签名密钥时，普通合法工具不因新增关联而被阻止；记录 `pm_linkage_unavailable` 提醒，不能伪称跨服务关联或内部核对已经可用。

历史、工具卡、native output／SSE、命令输出、MCP/App、引用与后续模型输入均按当前权限投影；失权内容不只在 UI 遮盖。受污染的原生上下文不能继续用于续聊／压缩／fork；可见工具项与不可访问的生成正文分开处理。

工具事件、PM 收据与业务变更仍是不同记录。traceId 关联输入消息、generation／外部执行根、operation 与原 commandId／revision；收据卡可按精确 commandId + operationId 查询现有 PM 审计，审计页可反查仍有权访问的原工具调用。审计继续要求既有 `audit.read` 与项目权限，仅公开白名单字段，不保存任意参数／正文或用文件观测冒充操作者审计。权限代码清单和分层验证入口属于内部记录，不随公开树分发。

#### 可安装的 dovspace-pm 能力包

包源码及逐客户端步骤见 [dovspace-pm README](../../plugins/dovspace-pm/README.md)。它从同一个 PM registry 导出工具能力与共享 Skills，提供 Agent Plugins 1.0.0、Codex、Claude、Pi 和 OpenCode 薄适配，不新增业务执行系统。

```sh
# PRIVATE_DIR 必须是显式存在、归当前用户所有的私有绝对目录
pnpm pm plugin generate --root "$PRIVATE_DIR" --origin http://127.0.0.1:3224
pnpm pm plugin install --root "$PRIVATE_DIR" --origin http://127.0.0.1:3224
pnpm pm plugin update --root "$PRIVATE_DIR" --origin http://127.0.0.1:3224
pnpm pm plugin uninstall --root "$PRIVATE_DIR"
```

`generate` 与 `install` 都写入该 root 下的自有 `dovspace-pm` 包，首次生成／安装二选一；已有包使用 `update`。更新／卸载按完整自有 hash 清单核验，不覆盖用户改动或自动改写外部客户端 Home。卸载不撤销 OAuth、不删除 PM 历史。安装策略默认 full/audit-only，不增加放行选择；客户端原有身份认证与 OAuth 同意仍是独立前提。

CLI 的 `plugin tools`、`plugin workspaces`、`plugin call --file ORIGINAL_REQUEST.json`、`plugin result --file ORIGINAL_REQUEST.json` 复用既有 PM 登录和原生业务通道；不借外部 OAuth token 登录普通 API，也不声称经过 Agent 的 ask 队列。首次发送前保存 origin + operationId 的私有记录；同键重复调用／进程重启只查原结果，不换键重派。

PM／Agent CLI 的完整步骤见 [CLI 操作指南](cli.md)。Agent 管理使用显式 `PM_AGENT_URL`；可信本机服务未配置令牌且明确允许访问时无需额外 Agent 登录，状态标为 `local_unprotected`，不保存身份文件。已配置令牌的服务仍须独立认证，非回环地址不得匿名回退。PM 登录与业务授权不变，Delivery／Workflow／Preview 仍需要当前 PM 身份。`agent logout` 不关闭本机无令牌访问，也不声称服务端支持逐会话撤销。`plugin call/result` 的退出 0 仅表示投影处理完成，机器消费需再运行 `plugin check`。

精确客户端版本、加载方式与真实授权／执行证据分别记录。配置加载、schema 检查和协议夹具不是四客户端闭环验收；公共 OAuth 发现不可用时不能宣称插件已连接。OpenCode 2.x 排查应使用 README 的原生只读 API／明确命令面板，不能把裸 `/mcps` 输入 Composer 当作无模型诊断。Plugin Manager、SDK／第三方可执行宿主与事件订阅仍是独立条件式后续范围，未自动启用。









#### Provider 运行输出

原生驱动共用按 generation 保存的事件输出投影；前端以实际到达的 Thinking / Action / Output 交错活动流显示回复、可折叠思考、工具输入/结果、命令终端、文件 diff、搜索、计划、子代理、上下文压缩与失败状态，不要求固定三段循环。旧历史继续原有正文显示，新输出不会再重复显示一份纯文本回复。

- 有原生顺序信息时，仅在同一排序域内恢复条目顺序；同 id 累积更新替换原项，不按文本去重，不比较不同轮次的 ordinal。缺少顺序信息的旧历史保留原顺序。
- 思考块仅展示 Provider 实际提供的摘要／文本，相邻且关联一致的条目可合并；没有摘要时不补造内部推理。连续工具可折叠为操作组，正文、错误、提问、计划及独立 PM 收据／MCP App 保留边界。手动展开或收起不会被流更新反复覆盖；该显示偏好仅在当前页面内有界保留，不新增持久化协议。
- 明确的 Codex `commentary` 显示为进度更新，`final_answer` 保留最终回答语义；未知 phase 不猜测为最终。Run 是否结束仍由 generation 生命周期决定，文本或单个工具完成不代表整轮完成。只有 Provider 提供可信起止时间时才显示精确耗时，不把投影首次观察时间伪装成模型耗时。
- 回复显示方式中的“逐段 / 整轮”只改变显示时机。逐段按完整 Markdown 边界约 400ms 释放；整轮在结束时展示正文，工具过程仍实时显示；错误和取消保留已收到的内容。
- 输出投影保存在 Agent SQLite，SSE 以序号和完整快照恢复；断开页面不取消原生执行。条目更新约 50ms 合并，慢消费者重置为快照，不无限积压。
- 命令仅在展开时单独订阅，约 100ms 合并输出；折叠释放订阅但不停止命令。终端处理 ANSI、回车覆盖和跨块控制序列，尾部有界且标明截断，最终结果持久保存。工具没有实时命令协议时只显示实际最终结果。
- Codex、OpenCode、Grok、Muse 的明确**信息提问**可回答或取消；重复、过期和不匹配回答被拒绝，服务重启后失去原生回调的请求不可回答。回答本身不写入输出投影。原有命令/文件/权限审批默认继续拒绝；Pi 通用扩展 UI、ACP 含义不明确的 elicitation 不自动当成安全提问放行。
- 部署开关 `AGENT_APPROVAL_MODE`：默认 `ask` 保留人工审批；`auto-approve` 时 assistant-ui 工具审批、PM 破坏性工具审批与原生权限审批全部自动放行并直接执行，审批代码与端点保留。该开关不改变 PM 业务校验，也不表示 WorkItem 完成。

本轮改进范围、接口合同与核验标准属于内部记录，不随公开树分发。该功能不新增 PM 权限或业务完成规则；受控原生协议验证不代表真实供应商账号和模型已验收。会话与持久化尚未统一设计，仍暂沿用 Agent Chat 的保存方式。

#### 对话阅读与富文本输入

- 已结束的相邻工具使用紧凑摘要；完整命令仍可展开查看。只有带服务端 `auto_approved` 决定的已完成审批可并入摘要，待响应、未知结果、错误和不可访问记录不隐藏。当前可响应的审批／提问集中在输入区，时间线保留定位；密码型回答和多选沿用原有协议。
- 原生输出与旧历史正文共用 Markdown：代码高亮、复制／换行，表格展开及 Markdown／电子表格安全 CSV 复制，数学公式和隔离的 Mermaid 预览。外部图片不自动请求；本地媒体须显式点击，经当前会话目录授权、文件类型／大小和私有路径检查后读取。
- 文件链接可打开当前会话 Files 并定位行号；文件检查器中的 Markdown 相对链接以该文档目录为基准。Changed Files 汇总区分历史记录的 diff 与当前授权目录的 Files／Git，不把当前工作树冒充执行时快照。
- 输入框使用富文本编辑器，保留原始发送文本、文件／Skill chips 和结构化引用。支持多行／代码粘贴、代码语言、附件及输入法；代码块内 Enter 换行，Ctrl／⌘+Enter 离开代码块。活动轮次期间仍可编辑下一条草稿，但不能用普通发送绕过运行中守卫。

#### 队列、草稿暂存与活动引导

- **加入队列**显式保存完整消息，包括所选 PM 引用、原生上下文输入及真实附件。当前页面保持可见、授权有效且已启用队列时，核验上一轮完成和分支 head 后自动发送下一条；发送使用当次浏览器授权，不持久化 Cookie／Bearer。
- 离开前台、切换／卸载页面、服务重启、历史改变、授权失效、执行失败或结果未知都会暂停；核对后显式恢复，不后台重放。队列支持修订检查下的编辑、排序、移除与立即发送；未知受理结果先核对原请求。
- **暂存草稿**是按会话隔离的显式多草稿库，不发送。恢复要求输入框的文字、附件和引用均为空，恢复后原暂存仍保留至手动删除。文本、PM 引用、原生上下文和已完成的附件载荷一并保留；临时 blob／外部附件 URL 不能冒充可恢复附件，持久载荷上限为 20 MiB。保存草稿不等于消息已受理，恢复／发送仍须重新核验来源。
- **未保存与已保存分开。** 普通文字草稿可沿用既有浏览器恢复机制，但原生选区、截图字节及撤销记录不自动写入 localStorage／sessionStorage；需要保留时明确加入队列或暂存，不能把一次只读解析当作持久保存。
- **保存终端选区不保存 PTY。** 原 PTY 过期或 Agent 重启后，仅可在同一目标 Session、当前权限及未变化的真实环境下，复用服务端已在队列／暂存／已受理历史保存的**完全相同**上下文输入（包括 contextId、来源、文字、评论和范围）。界面明确标记为历史用户选区；修改这些字段不能借用旧证明，未保存的解析结果也不能补成证明。不恢复进程、不重放输入或命令；如需终端，须明确新建。
- **引导当前执行**与队列不同：仅在原生 Provider 当前活动轮次真实支持 steering 时可用；若可能中断待处理工具，先明确确认。未知派发结果不重发，不支持时说明原因。

#### 长会话、计划与分支操作

- 历史通过稳定分页读取，**完整消息图核验后才导入运行时**，不截断发送／编辑所需祖先和分支。界面先显示最近约 80 条消息，可展开更早内容、搜索全部已载入历史、跳转匹配、折叠已完成轮次及使用轮次地图；阅读位置按会话保存在当前浏览器会话中。这是完整图预载加分段展示，不是按需网络虚拟列表。
- 完成的计划可展开、复制、下载或通过浏览器“另存为”保存；**在新会话中实施**会显式创建并发送新的会话，重新核验执行目录与 PM 引用，不代表 PM 任务完成。
- 子代理仅跳转到服务端能授权解析的已有会话；缺少映射时明确不可用。原生分支仅对具备能力的 Provider 开放，准备新会话后，在该会话第一次显式发送时创建原生分支。
- **回退**须确认且核验当前 head／revision，只改变对话分支并解除旧原生游标关联；保留历史，不回滚文件、终端、PM 写入或业务状态。

这些源码能力仍须与实例部署和真实 Provider 验收区分；会话与持久化统一设计尚未收口，继续沿用现有 Agent Chat 保存方式。


#### Usage 用量与额度

- Agent Chat 左下角侧栏的“用量”进入 `/agent/settings/usage`：紧凑顶栏、Cost / Tokens / Limits、24小时及7/30/90天、实例和 Provider 筛选。概览包含 Provider 汇总与平滑趋势、五项 Totals、缓存/速度费用分解，以及 Model / Day / Hour 明细。成本是 API 等价估算，不是订阅账单；未定价记录保留 token 并明确标记，不当成免费。旧的 `/agent/usage` 保留为跳转到该路由的兼容地址。
- 历史读取 Codex、Claude、Grok、Pi JSONL，以及 OpenCode、Antigravity、Muse 的原生存储；Cursor 使用账号 Dashboard 数据，不从本地对话估算。目录依据生效的原生 Home / 环境变量定位，包含已停用实例的历史；ACP / FX / OMP 没有已接入的通用历史扫描，FX / OMP 不推测历史用量。扫描缓存支持重启、追加与文件身份失效，容量与保留期有界，不能恢复已被淘汰的原生历史。Codex 速度档位仅从匹配的原生记录或冻结启动记录补全，不拿当前会话选项改写历史。
- 公开价格缓存、自定义价格和模型别名在 `/agent/settings/usage/config` 配置；保存使 Usage 查询失效，revision 冲突保留草稿。Limits 展示真实账号/窗口快照、剩余额度、重置时间和支持的 reset credits。页面自动检查有5分钟间隔，显式刷新另行执行；失败保留旧数据及其原有效时间，不伪装成新快照或推测已补满。CLIProxyAPI Hub 的管理密钥只写入、不回显，使用重置 credit 必须明确确认；动作成功但回读失败与动作结果未知分开呈现，均不自动重复兑换。
- OpenCode Go 由服务端使用原生 API Key，以 Bearer 调用 `https://opencode.ai/zen/go/v1/usage`，不以本地 token 估算订阅额度。SQLite 优先选中原生 `opencode-go` 连接，再考虑旧 `opencode` 别名；有效 v2 凭据不受旧 `auth.json` 损坏影响。保留内联认证、实例环境/Home及远程服务边界。5小时、每周、每月窗口沿用原百分比/重置时间模型，`rate-limited` 按额度耗尽显示；只有明确的 `EntitlementError` 才判定无订阅，其他403仍显示查询失败。本次修正仅更新源码，尚未部署或执行真实额度查询。
- 输入框不再显示上下文 token / 进度、费用估算或本轮供应商用量，也不再轮询会话用量；后台原生记账和独立“用量”页保留。`/usage-limits` 仍可显式读取现有额度快照，不执行模型、不自动探测或隐藏刷新。
- Cursor Keychain 只在明确启用、macOS 与对应原生认证条件满足时可用；不会自动导入全局账号。离线备份 `--secrets exclude` 清除 Hub 密钥、停用恢复的 Hub，并排除 Cursor 账号历史缓存；`include` 仍需显式离线授权。

真实供应商账单、额度及 macOS Keychain 需要对应平台和账号独立验收。

#### Agent 离线备份与恢复

先核对所属 PID、工作目录和服务，再停止**本副本 Agent**；工具不会替你停止进程。数据目录由 Agent 角色配置的 `AGENT_WORKSPACE_DATA_DIR` 指定（示例配置为 `.local/agent-data`），备份目录与恢复目标必须和源目录分离，恢复目标必须为空。不要对运行中的目录直接打包 SQLite。

```bash
pnpm agent:backup create --source <Agent数据目录> --bundle <新的私有备份目录> --secrets exclude --stopped
pnpm agent:backup restore --bundle <私有备份目录> --target <独立空目录> --stopped
pnpm agent:backup:verify --bundle <私有备份目录> --target <恢复目录> --stopped
```

必须显式选择 `--secrets exclude` 或 `--secrets include`。两种备份都包含私有会话及 `provider-attachments` 内的Agent附件，目录 / 文件权限为 0700 / 0600，不能放在公共 Web 根目录。`exclude` 保留一致的会话、历史、设置和模型配置，但排除凭据、`provider-private` 凭据/环境身份、实例环境、原生私有配置及应用自有 home，清除原生续聊引用并停用恢复的实例；恢复后必须明确检查原生配置并启用。`include` 纳入上述私有凭据/身份、私有实例配置及数据目录内部的应用自有 homes；外部 Home 只保留路径引用，不收集其内容，恢复时也不创建该目录；应用目录内的符号链接仍被拒绝。可重建的 `provider-cache` 探测缓存不进入任一备份；两种模式均不修改原始数据。

新建 `exclude` 备份同时清除 `provider:t3code:continuations` 及 Session 的原生环境／待 fork 环境引用；保留执行目录身份、generation 请求／输出／谱系和 PM 业务证据，不修改源库。`include` 保留原生引用，但两种模式仍撤销副本的 MCP live 授权。旧备份不会自动重写。[持久化设计](../architecture/session-persistence-design.md)已采纳 D1–D4 保守方案，但生产切换与整体设计验收未收口。

两种模式均包含应用拥有的 `chat-scratch` 内容及目录／Session 元数据，但外部代码文件夹仅保留引用，不复制源码。恢复不会把旧目录身份自动绑定到另一个路径或新建 inode；后续执行仍须通过身份核验，不能借恢复流程补建或接管丢失目录。

v2 Agent 备份校验源 Store／schema／关系版本及完整记录引用；恢复分配新 Store 身份和 restore epoch，旧线程有明确执行围栏。历史可读，不自动恢复原生执行或续跑队列；后续工作须显式新建 Session 并核对真实目录。旧非空、缺少持久化元数据的数据不能直接交给新 runtime 写入，先按[部署手册的隔离副本流程](../../deploy/README.md#agent-协作与持久化升级)核对。

恢复时同样核验 `exclude` 策略：原生实例必须明确为 `enabled:false`，不得携带旧 `cliHome` 覆盖；缺失禁用标志也会拒绝，即使备份文件摘要已重新计算。拒绝发生在创建恢复目标之前。

工具校验文件摘要、SQLite 一致快照和记录覆盖，拒绝活跃 / 陈旧锁、不明确的文件、路径穿越及非空目标；不通过 HTTP 提供秘密备份。Agent 备份包含 Chat 保存的 PM 工具结果和核心文件差异快照，仍**不包含完整权威 PM 数据**：PostgreSQL、Markdown 根目录、PM附件、用户项目源码、`.env.agent`、浏览器登录或全局 / 外部 CLI home 不在其中；PM 仍需既有完整备份流程。恢复校验通过不代表 Provider 已登录、PM 范围已获授权或真实模型可执行。

完整 PM＋Agent 恢复使用同一停写屏障下的恢复集：PM 备份显式提供 `--agent-source` 与 `--agent-secrets include|exclude`，或使用桌面加密备份。恢复集绑定 SQL/core/blob/chat/Agent 组件及其摘要和关系，不包含外部副作用。独立 `verify-recovery-set.ts` 的 `sqlExecutionVerified:false` 仅表示静态及文件／Agent 检查，不能替代实际 PostgreSQL 还原验证。

### 统一 Agent Chat 与 PM 工具

PM 侧栏与完整 Chat 页共享会话、模型选择、生成订阅和草稿交接；会话列表、历史、取消、归档及删除全部归 Agent Chat。旧 `/pm/<workspace>/agent` 仅重定向到 Chat，不映射旧 PM 线程。模型统一使用 Chat Provider，不再读取 `AGENT_CHAT_BASE_URL/MODEL/API_KEY`。**会话与持久化尚未经过统一设计，当前暂沿用 Agent Chat。**

PM 业务工具共用一个注册表和执行入口：核心查询／创建／字段与 Markdown 保存、配置／视图／迁移、评论与变更审阅、成员与项目管理、外部文档／成果、私人协作／时间／规划、Evidence／Submission／决策／Roadmap、自动化及集成的具名动作；`pm_list_workspaces` 发现当前授权目标。实际参数、可用性和原生能力以认证工具目录为准，不固定宣称历史工具数量。Codex、Claude、Cursor、Grok、OpenCode、Antigravity、Muse、Pi、ACP Registry 通过原生 MCP 或 Pi 工具扩展接入，OMP 使用原生 Host Tools 接入同一 PM 桥；同一代生成还提供统一 CLI。标题生成和空闲压缩不获得业务工具。接入源码不等于真实供应商账号已验收。

PM API 的 `/api/v1/agent-tools` 提供经认证的 schema 目录，`/api/v1/workspaces/:workspaceId/agent-tools/call` 执行，`/result` 核对原结果。请求保存明确目标和原操作者证据；Chat 只在当前请求内存中转发 PM 认证，不把 Cookie/Authorization 保存进会话、后台计时器或 Provider 环境。PM 仍在服务端检查成员、项目 scope、原生能力、revision、幂等键、关系防环和领域规则；目录不是权限或沙箱。

工具卡显示状态、来源、revision、收据和原对象链接。写入结果未知时只核对原 operationId 的原收据，不自动重派，也不把后来修改的对象冒充原结果。停止生成只阻止后续派发，不回滚已经提交的业务修改。PM 工具仅开放注册表明确声明的动作；归档、恢复、删除和状态转换仍受对应能力、确认与原生生命周期保护，具名成员／授权管理动作仍要求实际原生管理权限与适用的非受限成员条件。它们不开放账号秘密、模型审核批准、任意宿主路径或 shell；Provider 自己的本地执行能力不因此成为 PM 授权。历史内容在每次展示前重新检查当前来源可见性，拒绝展示不改写原成功事实。

Chat 的“PM 核心文件变更记录”保存明确目标下已登记共享/独立核心目录的文件新增、修改、删除及前后内容，非 Git 目录和无效 Markdown 也可观察。记录是观测快照，不是完整 Git 历史或防绕过审计；无法证明操作来源时不归因给某次工具调用。扫描由当前合法请求触发，不保留 Cookie/Authorization 进行后台轮询；权限丢失或不完整快照不得推断删除。界面明确区分观测结果、空闲、过期、不完整和失败。

PM 原生详情和文档工作台另提供持久“变更记录”、Markdown Diff 与个人待审阅提示，见 [PM 变更记录说明](project-management.md#变更记录待审阅与完成通知)。来源仅由服务端工具/自动化执行上下文标记，不能由浏览器请求自行声明；无法证明来源的磁盘编辑保持未知。实际任务完成通知沿用现有 PM 通知路由，不以生成结束代替任务完成，不增加 Submission 或自动验收。打开变更、确认已阅、通知已读和人工验收彼此独立；不建立新的 Agent 执行引擎或会话存储。

# 任务工作流与节点画布

> 公共使用合同摘录；历史验收结果不作为最新工作树通过证明。会话与持久化尚未统一设计收口。


日期：2026-10-31。用户要求预制工作流、画布节点与一次授权后的自动交付。本模块是既有任务代码交付的编排，不恢复 v3 业务执行计划，不增加角色、业务审批或任务完成规则。对应 INV-01/03/05/13/14/15/20、SC-03/12/13/14/20、INF-05/06/07 的部分路径。

## 数据与授权决策

- 任务 Markdown 仍是需求权威；执行固定 task revision、项目目录、仓库身份、工作流发布版本、Provider、模型、测试命令及授权。后续编辑不能污染正在运行的快照。
- 工作流定义（草稿与不可变发布版本）、运行记录、节点记录与 Chat 会话分开建模。第一版复用 Agent 私有 SQLite 的独立命名空间、单进程所有权和 CAS；Chat 仅承载 Agent 节点执行，Git 副作用仍由原交付收据核对。
- 每个任务至多一条工作流运行，不能接管已经手动创建的交付。项目级模板通过当前任务的项目授权访问；发布/启动/恢复/人工确认需要原 planning.edit，不设新权限体系。
- 发布模板不授予执行权限。启动时明确授权 worktree 写入、测试命令，以及分别勾选自动 commit、push、Draft PR；服务端根据固定图再次校验，不因画布连线扩大权限。仓库名称须与实际 origin 一致。
- 认证头仅在进程内短期持有，不持久化；每次后台推进重查 PM 权限与任务版本。退出、会话失效、服务重启不会静默使用全局凭据。重启后需重新登录并显式恢复，原运行/节点身份不变，未知动作不会自动重放。
- 关闭页面不停止已授权的后台推进；暂停仅阻止后续推进，不冒充已经取消在途 Agent、测试或 Git 操作。人工确认节点仅是工作流继续确认，不是业务 Review 或任务完成批准。

## 第一版节点与限制

内置“需求分析”“开发并验证”“开发并交付”三套图。节点：任务输入、独立环境、Agent、测试、条件判断、commit、push、Draft PR、等待 CI、人工确认、结束。画布可拖动、连接、删节点/连线与配置；发布校验类型、连通性、必需参数、前置依赖与循环。只执行单令牌有向无环图，不支持并行、循环、任意脚本节点或自动合并/部署/完成。

分析模板也在独立 worktree 内运行只读 Agent。测试节点复用既有显式 shell 验证能力（120 秒上限），不是新增任意脚本节点。失败可走条件分支或停止，不自动无限重试。CI 按当前提交后台轮询，未发现检查不算通过；超时/远端版本变化/未知副作用转人工处理。评审仍展示真实 GitHub 证据，不伪造审批。

## 节点状态联动（2026-11-01）

新增[节点与任务说明联动](workflow-task-state.md)。开发模板 v2 默认在 Agent 派发前自动申请进行中，交付模板在同提交的 CI 通过后人工确认待审核；画布可关闭或改为自动/人工模式。启动须单独授权状态联动。旧 v1、已发布图及运行不变。系统状态转换另存可信 revision 收据，不改需求快照，也不豁免人工编辑。

## 持久化提醒

**会话与持久化尚未统一设计，仍暂沿用 Agent Chat 基础存储。** 本次仅明确工作流数据与 Chat 的逻辑边界，不代表统一设计已经用户确认收口，也不是多实例 Runner、成员会话隔离或完整 G3 验收。

## 使用入口

保存任务后展开“任务工作流”，选择预制模板，或“复制为项目工作流”进入画布。编辑后先保存草稿，再校验发布版本。在没有既有运行/手动交付的新任务中，选择实际基准分支、已就绪的 Provider 和模型；“运行工作流”展示本次固定流程和分项授权，明确确认后由系统自动推进。暂停/恢复/人工确认在任务进度区域操作，Git 技术细节折叠展示；结束后的新评审可通过“核对 CI / 评审结果”更新证据快照。

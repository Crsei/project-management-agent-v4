# 自动化、触发与集成边界

本页描述当前源码的使用方式和已知限制，不代表当前工作树已通过检查、真实供应商账号验收或生产部署。历史计划和本机验收原件保留在本地，不作为公开安装依赖。

正式入口为 `/agent/automations?workspace=<id>&project=<PRJ-ID>`，从 Agent Chat 侧栏独立的“自动化”导航行进入；旧 `view=automations` 链接迁移到新入口。保留主侧栏，内容区提供 Dashboard、47 个模板（23 个 OpenHands 来源模板＋24 个 PM 原生场景）、创建/编辑、详情/历史、Git Sync 和集成配置；不是会话记录或第二套应用。部署前提及旧报告规则边界见[部署与历史报告](#部署与历史报告)；历史验收不表示当前工作树已通过。

页面管理执行类自动化，支持 Prompt、隔离 Custom Python、八个 OpenHands 来源的原生处理器及24个 PM 原生分析处理器，保留持久草稿、revision 冲突与原请求收据。执行类“试运行”会真正执行已保存快照；启用不会立即运行，暂停不取消已开始的运行。手动、一次性、五段 Cron/IANA 时区及签名事件使用同一授权队列，未知外部结果先查原操作，不以新键重发。

原生模板的确定性筛选、当前 head/CI、去重与外部发布由宿主执行；模型阶段使用现有 Chat/Provider。Watchdog 与 Stale CI Closer 不需要模型；News Digest 不需要仓库工具；其余五个仓库模板要求所选 Provider 的实际工具通道支持。接口与界面按驱动明确阻塞不兼容的工具组合，不把“支持 MCP”当作无人值守权限，也不扩大现有 Provider 原生权限。仓库命令只经受限工具进入固定镜像的隔离容器；这不把整个 Provider 进程或文件区域宣称为新的安全沙箱。

脚本和五个会实际准备仓库的原生模板，必须在动作配置中明确选择一个独立 Agent Workspace 文件夹，不要求该目录登记在 PM 项目中。validate／test／enable／run 分别核验原有 PM 业务权限，并通过既有服务 HMAC 调用 Agent 的目录解析边界，检查 v2 选择、允许范围和磁盘目录身份。显式选择目录的 Prompt 也走同一解析；纯 Prompt 可明确使用纯对话。缺失、未知、未来版本或目录被替换时拒绝，不回退 PM 文档或对话 scratch；仅重命名／关闭／重新打开目录不会使已有选择失效。选择保存在 `config.action.executionSelection`，随草稿、不可变运行快照及辅助 Chat 交接保留。PM 分析、News 和确定性维护不因携带仓库元数据而被错误要求代码目录。原生仓库副本的实际执行路径与登记源路径分开展示。

能力探测和外部执行不占用数据库工作区锁；提交 test／enable／run 时在原收据重放和定义 revision/CAS 之后再次核对本地目录登记，Agent 真正受理排队执行时仍重新授权。已受理请求按原键返回原始收据，不因之后的登记版本或运行时可用性变化而改写历史；新的请求必须修正配置后提交。Git Sync 更新已启用定义也遵守同一检查；Worker 通过核心的只读项目／目录映射端口取得权威，不启动可写 Workspace、索引、恢复或 watcher，也不借用新的服务凭据。

切换前已启用但缺少有效 v2 选择的仓库／脚本定义不会被删除或自动补 cwd。旧 v1 配置保留为只读历史证据，编辑后须明确重选 Agent 文件夹；不能把旧组合 ID 当新目录 ID。每次到期会持久化带明确执行选择错误的 `skipped` 运行和原配置快照，不派发、不消耗执行预算；一次性排期变为已耗尽，Cron 推进到下次未来时刻，签名事件沿用原事件身份去重。其他健康定义、已排队执行及未知结果核对继续处理，Worker 心跳不被这类旧定义阻断。切换前已排队但尚未派发的无效选择也明确跳过；已经派发的未知结果只查询原身份，不能以修复目录为由重新执行。

PM 原生模板覆盖任务/依赖、执行协作、知识/需求变化、项目/规划四组场景；模板页可按来源、分类和触发方式筛选。16个确定性处理器无需 Provider 或项目文件区域；8个语义处理器必须显式选择已认证且支持 `pmAnalysis` 的 Provider，当前仅实现 Claude 的无工具通道，不以 Codex 的工具沙箱替代。任务、评论、活动、文档、Session、Run、PR、里程碑和访问区间均来自当前主体/项目的授权快照；缺少来源明确报告缺口，不能把“无发现”解释为验收通过。

分析只持久化发现与类型化候选。用户在运行详情中编辑、预览、确认应用或忽略，实际写入复用现有 PM 服务、权限、版本检查与原操作收据；规划候选支持选择发布、既有任务复用及依赖闭包。来源变化需明确重基，结果未知先核对原收据，不自动重新执行。不会自动完成任务、合并/删除重复任务或启动调查执行；场景12目前生成共同假设与验证任务提案，不冒充尚不存在的执行审批单。

GitHub/GitLab 可使用独立验证的原生 API 连接，无需无关的 MCP 服务；MCP 模板仍要求实际 MCP 工具验证。私有输入只写入受保护的服务端存储，连接器版本固定到执行快照。导入默认草稿；完整 PM bundle 保留原生动作和文本脚本包，来源 `.automation.json` 仅在无损可表达时交换，不支持的格式明确拒绝。Git Sync 使用独立受控裸仓库、远端 CAS 和原提交核对，不操作业务工作树。

历史报告页面与后台规则的保留边界见[部署与历史报告](#部署与历史报告)，不把删除页面视为暂停调度。

## PM Agent 助手快捷执行

PM 项目、任务列表、实体详情与文档上下文的“Agent 助手”采用统一圆角下拉按钮，文字后显示向下箭头；点击按钮任意位置均展开菜单，不再分成 Chat 与箭头两个点击区域。菜单上方列出当前工作区、当前项目内自己创建且已标记的自动化，底部“前往 Agent Chat”保留业务引用入口及返回 PM 地址，不把这些参数设为 Session 所有者或执行目录。打开菜单或进入 Chat 不会自动执行任务、创建会话或发送消息。快捷自动化仍要求明确项目范围，不把工作区列表当作全项目执行入口。

1. 从下拉菜单进入“管理自动化”，创建或编辑自动化。
2. 在配置中勾选“Agent 助手快捷入口”并保存；使用的是同一份自动化定义，不复制执行配置。旧定义默认不显示，取消勾选后仍可在自动化控制台管理。
3. 返回 PM，打开下拉菜单，点击已保存的任务。符合原生 PM 分析合同的配置直接请求执行；任意 Prompt、自定义脚本及其他原生模板先展示配置确认，不因加入快捷入口而豁免原有权限或执行检查。
4. 页面保留在 PM，显示本次受理状态与“查看此次运行”；详情定位到准确的运行记录。排队或执行成功都不代表业务任务完成，分析候选仍须人工审阅与确认应用。

菜单由服务端在分页前按授权项目和 `quickAccess=true` 筛选，支持继续加载；不会只从控制台第一页筛选。草稿不可执行，暂停仅停止调度、仍可手动运行。缺少权限、运行能力或必要配置时显示禁用原因；最终执行仍由服务端校验。执行使用已保存 revision，不自动保存编辑器里的未提交内容。

快捷入口与自动化控制台共用当前主体/工作区的操作状态及原请求收据。请求结果未知时先核对原请求，不创建新键重发；核对后可查看原运行。快捷标记随完整 PM bundle 保留；来源 `.automation.json` 无法表达该字段，显式设置过标记的配置不能以该格式有损导出。

## 部署与历史报告

八个 OpenHands 来源处理器需要 `0040`–`0042`、24个 PM 原生场景需要 `0043_automation_pm.sql`，以及配套 PM/Worker/Agent/Web、受信服务密钥和实际使用的隔离镜像、连接账号或 Git 存储。按[部署手册](../../deploy/README.md)在受控窗口升级，不从旧部署记录推断新迁移已生效。

旧“原报告规则”前端页面、导航和跳转已移除，`/agent/automations/reports` 不再加载旧规则；后台报告 API、已有规则、不可变历史和 Worker 调度仍保留，删除页面不等于暂停已启用规则。

Run 成功不代表 WorkItem 完成；Agent 仍为本机单操作者环境，部分任务容器隔离不把整个 Provider/cwd 变成文件沙箱。会话与持久化仍暂沿用 Agent Chat，统一设计未收口。

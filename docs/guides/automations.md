# 自动化、触发与集成边界

本页描述当前源码的使用方式和已知限制，不代表当前工作树已通过检查、真实供应商账号验收或生产部署。历史计划和本机验收原件保留在本地，不作为公开安装依赖。

正式入口为 `/agent/automations?workspace=<id>&project=<PRJ-ID>`，从 Agent Chat 侧栏独立的“自动化”导航行进入；旧 `view=automations` 链接迁移到新入口。保留主侧栏，内容区提供 Dashboard、24 个 PM 原生模板、创建/编辑、详情/历史、Git Sync 和集成配置；不是会话记录或第二套应用。部署前提及旧报告规则边界见[部署与历史报告](#部署与历史报告)；历史验收不表示当前工作树已通过。

页面管理执行类自动化，支持 Prompt、隔离 Custom Python 及 24 个 PM 原生分析处理器，保留持久草稿、revision 冲突与原请求收据。编辑器先选择“按时间”或“按事件”，只显示该方式需要的字段；保存草稿、试运行与启用是分开的动作。“试运行”会真正执行已保存快照；启用不会立即运行，暂停不取消已开始的运行。手动、一次性、五段 Cron/IANA 时区及签名事件使用同一授权队列，未知外部结果先查原操作，不以新键重发。

PM 原生模板的确定性筛选、来源核对、去重与结果持久化由宿主执行；语义模板的模型阶段使用现有 Chat/Provider，并强制无工具只读。产品模板目录只包含 PM 原生模板，不再包含 OpenHands 来源目录；接口与界面按驱动明确阻塞不兼容的 Provider 工具组合，不把“支持 MCP”当作无人值守权限，也不扩大现有 Provider 原生权限。隔离 Python 仍只经受限工具进入固定镜像容器。

隔离 Python 脚本必须在动作配置中明确选择一个独立 Agent Workspace 文件夹，不要求该目录登记在 PM 项目中；PM 原生模板可以明确使用纯对话环境。validate／test／enable／run 分别核验原有 PM 业务权限，并通过既有服务 HMAC 调用 Agent 的目录解析边界，检查 v2 选择、允许范围和磁盘目录身份。显式选择目录的 Prompt 也走同一解析；纯 Prompt 可明确使用纯对话。缺失、未知、未来版本或目录被替换时拒绝，不回退 PM 文档或对话 scratch；仅重命名／关闭／重新打开目录不会使已有选择失效。选择保存在 `config.action.executionSelection`，随草稿、不可变运行快照及辅助 Chat 交接保留。PM 原生分析（无论语义或确定性）不因携带外部仓库/PR 元数据而被要求代码目录；外部 PR 只读快照不等于本机执行文件夹。

能力探测和外部执行不占用数据库工作区锁；提交 test／enable／run 时在原收据重放和定义 revision/CAS 之后再次核对本地目录登记，Agent 真正受理排队执行时仍重新授权。已受理请求按原键返回原始收据，不因之后的登记版本或运行时可用性变化而改写历史；新的请求必须修正配置后提交。Git Sync 更新已启用定义也遵守同一检查；Worker 通过核心的只读项目／目录映射端口取得权威，不启动可写 Workspace、索引、恢复或 watcher，也不借用新的服务凭据。

切换前已启用但缺少有效 v2 选择的脚本定义不会被删除或自动补 cwd。旧 v1 配置保留为只读历史证据，编辑后须明确重选 Agent 文件夹；不能把旧组合 ID 当新目录 ID。每次到期会持久化带明确执行选择错误的 `skipped` 运行和原配置快照，不派发、不消耗执行预算；一次性排期变为已耗尽，Cron 推进到下次未来时刻，签名事件沿用原事件身份去重。其他健康定义、已排队执行及未知结果核对继续处理，Worker 心跳不被这类旧定义阻断。切换前已排队但尚未派发的无效选择也明确跳过；已经派发的未知结果只查询原身份，不能以修复目录为由重新执行。

PM 原生模板覆盖任务/依赖、执行协作、知识/需求变化、项目/规划四组场景；模板页可按分类和触发方式筛选。16 个确定性处理器无需 Provider 或项目文件区域；8 个语义处理器必须显式选择已认证且支持 `pmAnalysis` 的 Provider，或选择一个已发布的只读 Agent（固定版本提供 Provider、模型和受控指令）。执行器不把 Codex 等工具沙箱替代无工具只读边界。任务、评论、活动、文档、Session、Run、PR、里程碑和访问区间均来自当前主体/项目的授权快照；缺少来源明确报告缺口，不能把“无发现”解释为验收通过。

分析只持久化发现与类型化候选。用户在运行详情中编辑、预览、确认应用或忽略，实际写入复用现有 PM 服务、权限、版本检查与原操作收据；规划候选支持选择发布、既有任务复用及依赖闭包。来源变化需明确重基，结果未知先核对原收据，不自动重新执行。不会自动完成任务、合并/删除重复任务或启动调查执行；场景12目前生成共同假设与验证任务提案，不冒充尚不存在的执行审批单。

仅希望在普通 Agent Chat 中盘点新项目、建立看板、寻找并执行任务，可使用本页导航中的[项目流程](agent-chat.md#项目流程从空项目到任务闭环)。先打开目标 Session，再进入“自动化 → 项目流程”；选择阶段后将草稿追加到该会话并返回 Chat，需用户检查并发送。它不新增自动化模板、调度器或无人值守完成规则；已有自动化候选仍按本页流程审阅应用。

PM PR 覆盖模板可使用一个独立验证的 GitHub/GitLab 只读原生 API 连接，无需无关的 MCP 服务。私有输入只写入受保护的服务端存储，连接器版本固定到执行快照。导入默认草稿；完整 PM bundle 保留原生动作和文本脚本包，来源 `.automation.json` 仅在无损可表达时交换，不支持的格式明确拒绝。Git Sync 使用独立受控裸仓库、远端 CAS 和原提交核对，不操作业务工作树。

历史报告页面与后台规则的保留边界见[部署与历史报告](#部署与历史报告)，不把删除页面视为暂停调度。

## PM Agent 助手快捷执行

PM 项目、任务列表、实体详情与文档上下文的“Agent 助手”采用统一圆角下拉按钮，文字后显示向下箭头；点击按钮任意位置均展开菜单，不再分成 Chat 与箭头两个点击区域。菜单上方列出当前工作区、当前项目内自己创建且已标记的自动化，底部“前往 Agent Chat”保留业务引用入口及返回 PM 地址，不把这些参数设为 Session 所有者或执行目录。打开菜单或进入 Chat 不会自动执行任务、创建会话或发送消息。快捷自动化仍要求明确项目范围，不把工作区列表当作全项目执行入口。

1. 从 PM 下拉菜单选择“新增自动化”，直接进入同一自动化编辑器，保留工作区、项目和返回 PM 地址；仅全新配置默认勾选“Agent 助手快捷入口”。恢复草稿、已保存定义以及用户取消勾选的选择不会被该入口改写。没有项目上下文时须在配置中明确选择，不自动挑选项目或跨项目运行。
2. 已在 Agent Chat 的自动化控制台创建的定义无需重新创建：打开该定义详情，点击“设置 PM Agent 助手快捷入口”，在编辑器勾选并保存；也可从“管理自动化”进入编辑。使用同一份自动化定义，不复制执行配置；已保存的 assisted/launch 来源定义编辑实际配置，不重放创建向导的默认值。取消勾选并保存即可移除快捷入口，定义和授权历史仍保留。普通控制台新建不会默认加入。
3. 返回定义所属项目的 PM 页面，打开下拉菜单，点击已保存且已启用或暂停的自动化；草稿会显示但不可直接运行，须先明确启用。符合原生 PM 分析合同的配置直接请求执行；任意 Prompt、自定义脚本及其他原生模板先展示配置确认，不因加入快捷入口而豁免原有权限或执行检查。
4. 页面保留在 PM，显示本次受理状态与“查看此次运行”；详情定位到准确的运行记录。排队或执行成功都不代表业务任务完成，分析候选仍须人工审阅与确认应用。

菜单由服务端在分页前按授权项目和 `quickAccess=true` 筛选，支持继续加载；不会只从控制台第一页筛选。草稿不可执行，暂停仅停止调度、仍可手动运行。缺少权限、运行能力或必要配置时显示禁用原因；最终执行仍由服务端校验。执行使用已保存 revision，不自动保存编辑器里的未提交内容。

快捷入口与自动化控制台共用当前主体/工作区的操作状态及原请求收据。请求结果未知时先核对原请求，不创建新键重发；核对后可查看原运行。快捷标记随完整 PM bundle 保留；来源 `.automation.json` 无法表达该字段，显式设置过标记的配置不能以该格式有损导出。

编辑器“在 Chat 中辅助配置”仍先保存本机恢复草稿，再把当前配置和返回编辑器链接放入新会话输入框，未经发送不会调用模型；从返回链接恢复的是原草稿或原定义。Chat 中的建议本身不是已保存自动化，须返回编辑器审查并保存；快捷标记沿同一草稿保留，不根据聊天正文自动创建、加入、启用或执行定义。

## 部署与历史报告

24 个 PM 原生场景需要 `0043_automation_pm.sql`，以及配套 PM/Worker/Agent/Web、受信服务密钥和实际使用的隔离镜像、连接账号或 Git 存储。Prompt/Python 与 PM 原生分析不使用外部来源目录或来源 Python bundle。按[部署手册](../../deploy/README.md)在受控窗口升级，不从旧部署记录推断新迁移已生效。

旧“原报告规则”前端页面、导航和跳转已移除，`/agent/automations/reports` 不再加载旧规则；后台报告 API、已有规则、不可变历史和 Worker 调度仍保留，删除页面不等于暂停已启用规则。

Run 成功不代表 WorkItem 完成；Agent 仍为本机单操作者环境，部分任务容器隔离不把整个 Provider/cwd 变成文件沙箱。会话与持久化仍暂沿用 Agent Chat，统一设计未收口。

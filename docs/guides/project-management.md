# PM 页面、文档与当前能力

本页描述当前源码的使用方式和已知限制，不代表当前工作树已通过检查、真实供应商账号验收或生产部署。历史计划和本机验收原件保留在本地，不作为公开安装依赖。

已实现正式命令与 Markdown 核心接口；当前命令清单以生成合同为准。`project`、`work_item`、`milestone` 的读写进入 `/api/v1/workspaces/{workspaceId}/core`。本地模式的新项目写入所选目录的 `.pm/core/`，未迁移旧项目仍在共享工作区根；配置、统一 ID 和恢复台账继续归工作区所有。对话/意图/决策、成员能力、上传元数据/成果/证据/提交/审核及 Dashboard/项目协作附加记录使用 PostgreSQL，附件字节另存。核心命令收据同样写入 `command_receipts`，创建以 `commandId` 幂等。当前服务为本机后端部署，不将此结果等同于完整生产发布验收。


| 接口 | 当前行为 |
| --- | --- |
| `GET /health/live` | 200：API 进程可响应 |
| `GET /health/ready` | 数据库 schema、内容卷、Markdown 核心根目录、Worker 心跳和失败隔离均正常时 200，否则 503 |
| `GET /api/v1/capabilities` | 按实际配置分别声明能力；配置/初始化不代表依赖已就绪、邮件送达或接收器可达；execution 始终 false |
| `GET /openapi.json` | 现行 OpenAPI3.1；接口路径与严格命令 payload 以生成合同为准 |
| `/api/v1/workspaces/{id}/core/*` | Markdown 核心：protocol/config/workspace/query/graph/files/entities/lifecycle/context/views/migrations/SSE |

接口契约见 [openapi.yaml](../contracts/openapi.yaml)，Node/浏览器客户端见 [client.ts](../../packages/contracts/src/client.ts)。命令统一提交到 `/api/v1/workspaces/{workspaceId}/commands`；实体读取、收据查询、changes/SSE、成果下载使用各自接口。客户端写入不自动重试，丢响应后按原 commandId 查询。

Web 产品名称为 **Dovspace**（工程目录与包标识仍为 `project-management-agent-v4`）。PM / Agent 侧栏分为独立品牌头部、应用选择器与常规导航：56px 品牌行使用黑底白色 D 图标、22px 粗体字标与右侧折叠按钮，品牌链接返回 `/pm`；60px 浅中性色应用卡片显示当前应用及描述，与导航间隔 12px。PM 折叠栏保留独立品牌和应用图标，手机抽屉在品牌右侧关闭。菜单分为“切换应用”和“管理”，选中项仅保留勾选，刷新工作区藏于可展开的“更多操作”，读取异常时仍可直接重试。登录页保留左上 22px、表单顶部 30px 居中字标；浏览器标题、favicon、认证与错误页页脚同步使用 Dovspace。

品牌是产品标识；工作区仍以真实 `workspaceId` 约束数据、成员和权限；Project Management / Agent Chat 是同一工作区内的应用入口，不创建第二套数据工作区。切换应用保留当前工作区，Agent 中过期的跨工作区返回地址不会被应用选择器沿用；真实工作区切换仍单独列出。此次仅调整导航与展示，不改业务数据、路径、Cookie、桌面安装标识或授权规则。会话与持久化仍暂沿用 Agent Chat 保存方式，尚未统一设计收口。

后端启动后，在根目录另开终端：

```bash
pnpm dev:web       # 仅启动统一 Web 开发上游；完整同源入口使用 pnpm dev:v4
pnpm storybook     # http://127.0.0.1:6017，独立组件样例
```

`/pm` 根据服务端状态展示首次设置或正常登录；数据库/网络错误不会视作空实例。设置响应不明时先核对状态和当前会话，不能盲目重建；登录后只选择实际授权工作区。浏览器不读取服务器令牌或旧访问文件，无权限或后端失败不回退示例。公共网关将 `/api`、`/health`、`/openapi.json` 转发 PM API，将 `/agent/api/*` 去除 `/agent` 转发 Agent API，页面与资源来自统一 Web 构建，流不缓冲并保留 WebSocket。

新工作区通过首次设置或工作区选择页明确创建，自动持久初始化内置 Nova 示例；已有工作区不补种。示例各类对象使用该工作区自己的 ID、目录与关系，固定示例日期和未分配负责人不代表当前团队排期。账号、权限、凭据、评论和执行历史不从部署样例复制。手动新建项目仍是空白项目，不会每次附带 Nova。

工作区创建使用原请求键：结果未知先核对，未完成则恢复原初始化，不创建替代工作区。恢复先查询原结果；页面卸载或已观察到会话变化时停止后续请求。创建／恢复写入必须提供发起时的 `expectedActorId`，服务端在副作用前与实际认证主体比较，不匹配返回 `409 session_changed`，不能用当前其他账号接手原意图。列表分开展示可用工作区和待初始化工作区；待初始化的核心访问拒绝，但不会阻断其他工作区。存储路径离线保留具体目录错误，恢复原存储后继续原请求。此流程需要迁移 `0052_workspace_samples.sql`、增量 `0053_workspace_sample_storage.sql` 及配套 PM API／Web／桌面后端，不能仅更新前端。

首次核心初始化在原请求行持久保存目录身份与 `prestate`／`established` 阶段：已证明的 `prestate` 中断可在同目录身份下续接；目录替换、未知已有且没有合法 state 的目录或已建立权威后丢失 state 均拒绝重种。建目录与所有权提交之间尚未证明的中断也保持拒绝，不自动接管或删除。readiness 对全部示例初始化记录检查核心 state，不因禁用本地项目目录而将已丢失权威的工作区视作空实例。升级与恢复见[部署手册](../../deploy/README.md#工作区示例初始化升级与恢复)。

从 PM 切换 Agent Chat 时先显示模块加载反馈，可取消、失败后重试或重新加载；保留整页导航及原有未保存草稿确认。PM 会话／工作区读取失败时仍提供 Agent 入口，不把业务 API 的失败当作 Agent 页永久不可用。

隔离端口通过本地角色配置与 `PUBLIC_HOST`、`PUBLIC_PORT`、`PM_URL`、`AGENT_URL` 设置；不要把服务秘密放进 `VITE_*`。生产 Caddy 使用等价代理；部署见[手册](../../deploy/README.md)。

PM 左侧栏底部在账号上方提供“设置”入口，展开、折叠图标栏与手机抽屉均保留当前工作区路径及设置子页选中态；不再展示“已连接”按钮及其服务状态弹层。底层连接、离线 / 错误 / 快照过期提示与未知写入恢复仍保留。

`/pm/<workspace>/settings/design-system` 为设置内的“设计系统”，桌面导航和窄屏页面选择器均可进入。参考 gr8r-studio 的顺序展示颜色、状态与优先级、字体、间距 / 圆角 / 阴影、按钮、输入、导航、数据展示、反馈和图标，复用本仓真实主题令牌及组件。示例交互只改变页面局部状态，不创建任务、删除项目或发出业务写请求，离页重置；主题切换沿用全站 PM 浏览器偏好。此次未改会话与持久化设计，仍暂沿用 Agent Chat 保存方式，尚待统一设计收口。



### 原生右键操作

在对象所在区域直接右键即可打开操作菜单，不需要先点击省略号。共用 `components/ui/context-menu.tsx` 的 Radix Menu 焦点与定位能力；菜单在屏幕边缘避让，支持 `Shift+F10` / 菜单键、方向键和 Escape。窄屏原生文件浏览器 `dialog` 内的菜单留在其顶层中；打开管理面板后焦点交给面板，不抢回原列表。

| 区域 | 右键入口与既有操作 |
| --- | --- |
| 文档与附件 | 文档集合、文件树、来源根、标签、正文/大纲和外部文档标题；复用导航、格式、任务准备、对象/附件、保存及外部文件管理面板。项目附件卡片/列表及版本历史可预览、下载、复制链接或复制明确选中的版本 |
| 任务与项目 | 任务列表/表格/看板卡片、分组空白、详情标题；项目卡片/列表/侧栏/标题。沿用已有属性、创建、设置、分享及生命周期操作 |
| 日程与图形 | 日历日期/事件、甘特任务/里程碑、知识图谱、项目/任务依赖图、规划与工作流节点、个人白板。菜单打开已有编辑器或只读信息；共享画布空白提供适配/缩放，拖动不误开菜单 |
| 成员与通知 | 成员明细/工作量/角色/访问及可见联系信息；通知导航、已读和归档操作复用原有队列 |
| Agent | 会话行、消息操作区、Files/Git 行、Terminal 工具区及自动化卡片/列表；Files/Git 仍只读，Terminal 正文保留原生选择/复制 |

右键本身不提交业务写入、不切换会话，也不改变工作项完成规则。菜单与现有按钮复用权限、revision、草稿保护、确认及未知结果核对；外部 Markdown 文件操作不扩展为通用服务器文件管理。普通输入框、链接、代码、已选文本与 iframe 保留浏览器菜单，已有专用正文编辑器使用其格式菜单。实现及有界浏览器证据见[说明](project-management.md)；源码接入不表示常驻服务已更新。

认证入口使用独立全窗口登录页，支持密码显隐、字段校验和本地化反馈；登录后进入授权工作区选择。登录响应未知时先检查当前会话，不自动重发。账号由管理员或有效邀请创建，未开放公开注册或第三方登录。`/pm/account/security`、`/pm/account/recovery` 和恢复邮箱确认页不依赖工作区；配置邮件能力且本人独立验证恢复邮箱后才可自助找回，历史登录邮箱/邀请不自动算可信证明。

正式应用以工作区为稳定外壳：侧栏顶部切换实际授权工作区，依次排列个人入口、工作区聚合入口和授权项目树，底部保留账号与设置入口。内容区只有一条上下文顶栏；主题、语言、页面变体、设置与个人白板可从“页面与外观选项”进入，工作区菜单另有设置及按权限显示的成员入口。项目可独立展开看板、列表、时间线、文件，展示真实状态和个人收藏；展开偏好按账号和工作区隔离。工作区全部任务、日历、时间线跨授权项目汇总并显示归属；项目页固定项目，工作区的项目筛选可清除。工作区创建需选择所属项目，项目创建预填并锁定项目。跨工作区使用整页导航，释放旧查询与订阅；未保存编辑和创建草稿保留离开提示及恢复机制，浏览器存储失败时须先重试保存，避免强制离开丢失内存输入。设计、分工与实际验收见[工作区导航说明](project-management.md)。

项目侧栏、列表和详情共用真实项目 `…` 菜单：打开、个人收藏、重命名与编辑、分享、复制链接、复制项目、侧栏上移/下移、归档及删除。排序按账号/工作区在服务端保存；分享复用实际成员范围，不提供公开访问。复制使用新 ID 和新目录，重映射所选任务关系，不复制历史、权限、附件或用户代码；未知响应先查原收据，未完成复制只能显式恢复原请求。`/projects?archive=archived` 提供恢复入口；永久删除须已归档、无引用且完整名称确认，不删除用户代码目录。启用需要 `0035_project_sidebar_order.sql` 及配套 API/Worker/Web，未自动升级既有服务。实现与验收见[项目菜单说明](project-management.md)。

任务集合默认展示范围、布局、搜索、筛选与一个“新建任务”主操作。“筛选”中保留项目、状态、优先级、排序、归档和看板分组；“更多任务工具”中保留完整创建页、保存视图/完整查询、文件浏览器、高级源码分栏及帮助。已启用的筛选和查询保持可见，项目路由的固定范围不能清除。列表按标题、状态、负责人、优先级、截止日期和项目对齐；每行“任务操作”提供真实状态/优先级编辑，手机端使用紧凑元数据行和独立操作入口。只显示有可信来源的负责人名称，其他已分配引用不伪造姓名。

项目内“新建任务”（含看板分组和日历日期入口）直接进入 `/projects/<id>/issues/new` 的 Markdown 编辑页，不先创建空任务。正文使用 Markdown 编辑器和预览，同页维护标题、状态、负责人、日期、优先级、标签及高级关系；当前项目固定，已有恢复草稿优先保留原输入。“保存并创建”后进入同一任务的源码/实时视图继续编辑。工作区快速创建仍保留。

文档“内容”页默认直接可编辑，提供 Markdown 正文、实时预览、格式工具栏、三级右键菜单、查找替换、命令搜索、大纲与块操作；正文、属性、关联和高级源码共用原文/revision 草稿，支持显式保存。授权双链按对象类型跳转项目或任务页面；选区转任务和附件上传使用真实服务及原请求恢复。插件技术参考、语法、安全边界和验收见 [Markdown 编辑补全说明](project-management.md)。Agent/Session 执行与多人逐键合编仍未启用。

### 变更记录、待审阅与完成通知

任务、需求和 PM 文档的详情提供“变更记录”；外部 Markdown 在文档工作台使用同一入口。记录列出保存版本、发生或观测时间、可信来源、字段前后值及 Markdown 增删行，可切换完整源码（包含元数据区），也可比较当前对象自上次已阅以来的累计差异。任务中的正式 `requirement` / `related_to` 关联会单独标出需求、文档变更；普通正文双链不自动变成审阅关系。累计比较只覆盖当前对象，不把多份文档拼成一个 Diff。

- **待审阅不是任务状态：** 看板卡片、任务行显示个人“待审阅 · N”。筛选中的“仅待审阅变更”与原项目、搜索、保存视图等范围取交集；即使平时隐藏已完成任务，这个筛选也能显示仍有未阅变更的已完成任务。返回集合保留该筛选。
- **明确已阅：** 打开任务或 Diff 不清除计数。“已阅这些变更”仅保存本人的服务端已阅位置，覆盖当前对象及所列关联来源至本次显示水位（包括更早分页）。面板固定本次水位，刷新才读取新水位；审阅期间产生的新修改仍待阅，其他成员不受影响。关联范围或权限改变时须重新读取，不能使用旧确认覆盖新范围。
- **完成后通知：** 普通任务修改、评论沿用显式关注和新提及；任务真正转换到配置工作流的“已完成”类别时，额外通知仍有权限的负责人及可信 Agent／自动化发起人。本人手工修改不通知自己；服务端已确认来源的 Agent 代办结果不会仅因同一操作者而被过滤。重复路由不产生重复通知，历史通知不授予新权限。
- **通知不等于验收：** 个人通知仍在“活动 → 定向通知”（`/notifications?section=notifications`），可打开准确变更版本；打开不自动标通知已读。通知已读、变更已阅、任务完成和人工验收是独立状态。Agent 执行成功不等于任务完成；不新增或改变 Submission、Evidence、Review 逻辑，也不自动替人验收。
- **历史边界：** 受控保存保留真实前后端点；首次采集只建立基线，外部编辑只保留实际观测到的端点，不补造离线中间版本、作者或更早历史。外部文件只有在当前来源及路径仍获授权时才能查历史；移动和删除依赖原完成证据，未知写入不能冒充成功。已删除外部文件的历史可通过原来源/路径 API 查询，但不会在文件树伪造一份当前文件。

需要迁移 `0050_change_history.sql` 与配套 PM API、Worker、Web，不能只升级前端。历史列表每页最多 100 项，任务提示每批最多 500 项；同一外部历史流超过 100 组不同保留来源绑定时明确返回不可用，不静默截断计数。外部观测导入与界面提示不是逐键实时协作；可见页面每 30 秒补读提示，也可显式刷新。

**会话与持久化尚未统一设计，当前仍暂沿用 Agent Chat。新增 PM 历史与个人已阅位置不表示统一设计收口。**


### 多文档工作台

打开普通 PM文档或外部文档后进入 `/pm/<workspace>/documents?workbench=1` 工作台；任务 Markdown 仍进入任务详情。PM 主导航在工作台临时折叠为图标栏，退出后恢复原来的展开状态与宽度；旧文档对象链接和项目 Files 的文档入口沿用同一工作台并保留返回位置，不嵌套第二层项目导航。

- **文件范围：** 当前账号有权读取的PM文档（核心文件），加上工作区及各项目已配置的外部文档来源；不是任意磁盘浏览器。原生文件按项目与类型分组，非文档对象跳转既有对象页；外部来源自动加载全部可用分页，扫描排除、限制和失败明确显示，不冒充完整结果。
- **浏览与切换：** 左侧文件树支持搜索、定位当前文件、刷新、独立滚动和调宽；窄屏改为抽屉。顶部标签去重、切换、关闭，提供溢出菜单与方向键 / Home / End / Delete 操作。外部标签用来源、revision 和相对路径区分身份，同名文件显示来源与相对路径。关闭最后一页保留空工作台。
- **保存保护：** 原生正文编辑后约 800ms 自动保存，也保留显式保存。保存按文档 ID 与 revision 提交；快速切换、关闭及卸载不会把旧稿写到新文档。未保存关闭可选择保存后关闭、保留草稿关闭或取消。结果未知时保留原始恢复记录并暂停写入，先读取权威版本核对，再显式采用核对版本；不盲目重发。
- **状态边界：** 原生标签身份沿用账号 / 工作区隔离的浏览器存储，正文草稿沿用现有恢复机制；编辑位置与外部标签仅保存在当前会话内存。外部文档默认按现有权限开放编辑及文件操作，草稿仅存内存，切换标签保留、刷新前提示保存；未决操作只持久化安全的操作身份，不持久化外部正文。来源或权限变化清除无权读取的正文，文件删除不静默抹去仍有权恢复的未保存草稿。


**会话与持久化尚未经过统一设计，当前仍暂沿用 Agent Chat；本次文档标签与草稿接入不代表统一设计收口。**

### 目录型 Markdown 文档来源

PM 文档页右上角“文档来源设置”默认使用当前工作区，选择项目或“工作区公共文档”，通过服务端文件夹浏览器关联一个或多个 **PM 后端机器上的已有目录**，空目录也可选择。一次“确认”完成目录检查及整组原子保存，不再单独预检。同一路径可关联多个项目或工作区；仅同一关联范围内拒绝重复或互为父子的目录。选择器禁用已选目录及其子目录，移除关联不会删除磁盘文件，也不影响其他范围的关联。目录仍须位于允许根内并通过身份与权限检查，不改变 Agent cwd。多来源需要迁移 `0045_document_source_associations.sql`（以及之前的 `0039`、`0044`）和配套 API/Web，不能只发布前端。

外部来源递归列出普通 `.md` / `.MD` 文件，不要求 frontmatter 或 PM ID；前端以有界并发读完各来源分页，显示安全排除或扫描失败，不混合旧游标。有当前来源读取及 `planning.edit` 权限时，**编辑、新建、移动、重命名和删除默认可用，没有另设启用开关**。正文使用 CodeMirror，点击“保存”或 Ctrl/⌘+S 显式写回真实文件；新建和移动可在来源内建立缺少的父目录，不能重建丢失的来源根。支持在同一工作区的授权来源之间移动，重名目标拒绝覆盖；删除须确认且会永久删除磁盘文件，不是关闭标签。文件操作不转成 PM 文档对象、不插入 frontmatter，也不改变 Agent cwd。多个关联引用同一实际文件时，编辑和删除会影响所有引用。

工作区和项目导航的“文档”入口统一进入 `/pm/<workspace>/documents`。默认在一张表中显示当前账号有权读取的任务 Markdown、普通 PM 文档及工作区内所有授权项目／公共来源的外部文档；PM文档排在外部文档之前。外部文件按工作区内不透明物理位置键去重，显示其授权关联项目，不按同名或相同正文合并；项目筛选和文件操作使用对应项目的来源权限。来源名称统一为“PM文档”和“外部文档”，可按项目、类型（含“任务”）、来源、名称或 ID 筛选。已完成、已取消及已归档的任务文件仍可列出，不沿用任务页的状态或归档过滤。任务点击进入原任务详情，普通文档和外部文档进入文档工作台，不转换实体类型或复制文件。外部来源失败或扫描不完整明确提示，不冒充空集合。

内容读取沿用当前工作区/项目授权；仅项目成员不能借关联读取其他项目或工作区实体。明确关联的普通目录可以跨范围共享，但宽泛父目录不会隐式开放未授权的登记项目子树；私有目录和凭据始终排除，问题列表不泄漏受限路径。主机绝对路径仅向可管理该关联范围的主体披露。私有存储、路径穿越、软链接、硬链接和特殊文件仍被拒绝；`.pm` 不进入外部文档，避免重复展示 PM 文档。正文最多 4 MiB，不静默截断。扫描限制为 100,000 个条目、128 层目录和 1,000 条问题；遇到排除或限制会明确显示“不完整”，不能当成空目录或完整结果。预览禁用原始 HTML、相对资源与 PM 实体嵌入。

关联集合 revision、来源 revision 与文件 revision 分别防止覆盖他人的配置、来源重定向及覆盖外部编辑。配置保存响应未知时先 GET 比较整组目录和版本，不能盲重发。文件冲突保留草稿，须核对最新正文并显式采用版本；未决操作保留原 operationId，刷新后使用“核对原操作”，不盲目重发。跨来源移动先发布目标再删除源文件；若中途出错，状态保持未知，不声称数据库回滚已撤销磁盘副作用。缺少可信完成证据时，服务端阻止跨工作区、跨来源别名的重叠物理目录写入；解除关联不清除未决记录。迁移保留历史请求／收据及证据哈希，旧来源标识只作为不透明 sourceId 保留，不保留旧配置 API。实施与分批验证见[目录文档来源说明](project-management.md)。

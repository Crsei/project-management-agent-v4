## 1. 简化结论

先不做多模式切换器、Custom 规则编辑器、策略继承编辑页、审批规则 DSL、复杂预算配置及后台自动授权管理。

先做一条真实可用路径：

**用户明确作用域与启用 → 固定 Full access → 模型调用已经接通的工具 → 复用当前用户的业务权限和原应用守卫 → 保存真实操作结果。**

Full access 只定义可使用的工具范围，并不自动等于 Auto approve。为了减少逐次审批交互，本清单的**推荐实现组合**是：

- `accessMode = full_access`。
- `approvalPolicy = auto_approve`，仅作用于已注册、可委托、作用域内的动作。
- 只有这一种可启用组合；暂不提供审批策略选择器。
- 启用前一次明确展示授权范围、允许动作、排除项和到期时间；此后允许动作不再逐次弹确认框。
- 受保护操作不进入自动工具清单，返回明确原因并引导原生人工流程，不先建设完整人工审批工作台。

这是任务方案中的推荐，**不将用户选择 Full access 偷换成运行环境已经开启 Auto approve**；启用授权仍需在产品中明确发生。仅修改系统提示词或加一个 Full access 标签不算实现。

## 2. 第一批允许什么

### 2.1 作用域

- 使用当前登录主体、当前工作区以及明确选择的项目/对象范围；无明确范围时只能普通聊天，不能默认绑定第一个项目。
- 可选择当前项目，或明确授权当前工作区内该用户可访问的项目集合；不另做自定义权限矩阵。新增项目或工具不能悄悄扩充既有绑定，扩大范围需重新确认。
- 服务端每次调用复核当前权限。Full access 不使普通成员成为管理员，也不向模型暴露后端服务凭据。
- “有权读取”与“已经发送给模型”分开；按需读取、展示来源，不能把整个工作区一次性塞进提示词。
- 用户未明确附加的草稿、其他人的私有会话、凭据和无关个人数据仍不发送。

### 2.2 操作处理

| 动作 | 固定 Full access 推荐路径 |
| --- | --- |
| 授权项目/任务/文档查询、搜索、总结 | 已接通读取工具可直接执行，记录实际读取来源 |
| 创建任务、编辑普通字段、文档正文、合法关系 | 工具已实现且用户有权时可直接执行；先读当前版本，走原生应用服务，记录变更与收据；不要求额外弹窗 |
| 创建项目 | 只在用户具有原生工作区级创建权限、此次范围明确包含该动作且工具已接通时允许；项目级绑定不能创建新项目 |
| Run 启停、沙箱文件修改、受控测试 | 等执行/Host 功能实际接通后复用同一权限入口；这批权限任务不假装完成执行系统 |
| 任务 Done、成果通过审核、受保护生命周期、删除/归档、跨项目移动 | 保留原计划的人工边界；模型给建议或原生操作入口，不自行完成 |
| 秘密/ACL/自身策略修改、越权读取、不可变历史改写 | 禁止，不因模式改变而开放 |
| 任意 shell、原仓库写入、Git commit/push、远端 PR 发布/合并、生产部署 | 不在现有接入计划内，不以 Full access 名称隐式增加这些能力 |
| 自动化后台持续执行 | 不继承交互会话的 Full access；另按原 F17/F18 实现与授权 |

如果要把 Done、删除、原仓库写入等也纳入自动执行，需要单独变更对应业务/执行范围；不是本次“先做 Full access”所自动带来的权限。

## 5. 不能省掉的最小技术事实

### 5.1 不必做完整策略引擎

首批采用代码定义的工具清单和单一规则：

`已启用且未到期/撤销 + 当前用户原权限 + 当前绑定范围 + 已注册可委托工具 + 原生业务守卫 = 允许自动执行`。

其余返回明确拒绝/原生人工入口。无需条件表达式语言、层级策略编辑器、策略可视化模拟、动态审批规则引擎或独立身份服务。后续增加模式时在这一入口扩展，不能再建第二个校验入口。

### 5.2 不必先做复杂预算系统

保留模型/工具循环的固定上限、执行超时、内容/文件大小限制及必要并发限制；由服务端配置，并展示实际 usage/上限。费用估算未知就显示未知。多币种费用台账、逐规则预算编辑、复杂额度分配不是首批前置条件。

### 5.3 自动写入也不能直接相信模型

模型提交类型化请求，由服务端生成真实授权记录并调用原应用服务。普通写入可省掉逐次确认，但不能省掉读取当前版本、写入校验、原请求身份和实际收据；不能靠模型输出“已完成”更新页面。

### 5.4 最少前端元素

只需三个可组合界面职责，不为首批重新拆出大型设置产品：

- 当前权限摘要：复用计划中的 AgentRuntimeContextBar。
- 当前工具调用与结果：复用 AgentToolCallCard。
- 设置中的模式说明与启停：在 AgentSettingsOverview 中实现单模式内容。

它们不是新的聊天组件库。使用同步任务确定的 `@assistant-ui/react` / `useExternalStoreRuntime`、现有 Radix、MessageContent 和 PM token；不重建 Thread、Composer、线程列表、认证或缓存。

## 7. 权限做完仍需要哪些业务能力

Full access 是执行方式，不会自动产生读取工具或业务服务。需要与以下最小接入并行配合，但**不用先完成其所有场景和复杂页面**：

| 必需配合 | 最小闭环 | 原任务归属 |
| --- | --- | --- |
| 项目上下文读取 | 指定项目/任务查询、来源与当前 revision、实际提供给模型 | F06 |
| 模型工具调用 | 真实供应商支持的工具 schema、多轮调用、结果回传、取消/错误/循环上限 | F07 |
| 普通业务写入 | 先接任务创建和一个普通字段修改，复用现有原生 API/幂等/CAS，不先建设完整提案待审页 | F09 的工具应用切片 |
| 运行时与入口 | 将上述实际能力显示到同步 UI 的既有插槽，注册精简设置入口 | F08/F19/F20 的最小接线 |

代码执行仍要等 F12/F13 的真实 Host，自动化仍要等 F17/F18；不能为了让 Full access 看起来完整而给模型任意 shell、直接数据库或系统文件读写工具。

## 8. 实施顺序与交付判定

顺序：FA01 → FA02 → FA03/FA05 → FA04/FA06 → FA07。斜杠表示在真实依赖满足后的独立工作；不是要求同时编辑共享文件。最小 F06/F07/F09 工具切片与权限接口合同对齐后同步推进。

交付需要同时满足：模式真实启用且范围可见；有效普通动作无需逐次审批；原应用守卫、撤权、未知恢复有效；用户与模型看到相同能力；首个真实读写闭环通过。仅能选择 Full access、只显示标签、或者工具仍全部未接通，均不算交付。

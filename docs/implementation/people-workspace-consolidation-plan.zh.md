# 成员、团队与工作量统一入口计划

状态：实现与本轮隔离验收完成；本轮只整合正式前端，不更改后端授权或数据所有权。

## 目标与合同

- 正式侧栏只保留“成员与团队”，规范路由 `/pm/<workspace>/members`。
- 使用 `tab=members|teams|workload` 三个功能页签；缺省为 members。成员原有展示变体保留在成员页内，不能再把功能页签称为布局。
- 团队页复用现有团队管理；正式界面不再使用重复的 team2 人员目录。Lab 展示变体不改变。
- 工作量支持按成员、按团队和任务池；“按团队”区别于团队管理。成员详情、团队详情可跳转工作量并带 `memberId`（userId）或 `teamId` 筛选；筛选可见、可清除且刷新可恢复。不用姓名匹配，不改变授权和负载计算口径。
- 成员邀请、记录、角色和独立能力保留在成员页；`panel=invitations` 打开邀请管理，`profile=me` 保留本人资料入口。SMTP 未配置时不能新建或重发。
- 所有正式站内入口迁往规范路由。删除独立正式 `/teams` 路由，不建设第二套页面或兼容服务。历史实施记录和 Lab 路由不批量改写。
- 各页签按需读取；工作量读取错误不能阻断成员目录。权限、未知写入核对、版本冲突与草稿恢复沿用既有机制。

## 规则

遵守 [领域权限](../domain-design/permissions.md)、[成员规则](member-backend-completion.md)及[团队规则](teams-backend-completion.md)：INV-01/08/13/14/15/20、SC-12/13/14/20、MEMBER-INV-01/03/04、PROJ-INV-03/06。团队与维护者不授予权限；容量是并行未完成工作估算点而非工时；未知和零不同；部分授权范围不能宣称全局未超载。任务事实仍归 Markdown，容量和组织关系复用 SQL。

## 验收矩阵

1. 单一侧栏入口；三个页签支持直接链接、切换、刷新、前进后退；Lab 独立保留。
2. 成员目录、详情、本人资料、角色/独立权限、邀请记录与 SMTP 禁用状态可用。
3. 团队创建/编辑/成员/维护者/项目关联/归档仍复用真实服务。
4. 成员和团队进入工作量时筛选正确且可清除；任务跳转、容量和估算操作可用；缺估算、零和部分范围语义保持。
5. 普通受限账号只看到授权成员、团队和任务，无管理员操作；一个页签数据失败不污染其他页签。
6. 桌面与 390px 移动表面可用；无重复功能选择器或页面级横向溢出。
7. `pnpm check:web`、受影响现有行为测试与文档检查；实际浏览器在自建账号、随机 schema 和临时端口中验证，不用 mock 替代业务数据。

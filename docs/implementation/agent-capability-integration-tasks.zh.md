## 3. 最小接口与存储边界

- 继续使用既有聊天 API、持久消息和流式协议，只增加此次工具所需的合同与事件，不切换整套消息 SDK。
- 最小新增信息是授权绑定、上下文来源、工具调用身份/状态、真实结果或原命令收据引用；复用现有数据库和领域存储，不直接 SQL 改业务对象。
- 工具身份关联当前聊天 request/message，而不是新业务 Run。现有聊天内部的同名标识保持原约定，不做无关重命名或迁移。
- 不新增 execution Session、RunEnvelope、Finding、Automation、Host、产物核验或后台规则 API，不把它们作为隐含接口前置。
- 模型配置、已验证连通性、工具可用性分开显示。仅配置了 API key 不表示业务权限或工具已接通。

## 5. 实施约束与完成判断

- 同步 UI 任务继续拥有 Thread、Composer、sidebar、相关样式及依赖；只有单一集成人接共享文件、路由、合同和迁移编号，不覆盖并行修改。
- 后端复用 Fastify/domain/application；前端复用同步任务确定的 React、assistant-ui external-store runtime、MessageContent、Radix 和 PM token，不引入另一套后端、认证或消息系统。
- 仅使用本副本环境及隔离验收资源，不复用来源项目数据库、存储或凭据。
- 交付验证受影响 lint/typecheck/build、合同/文档检查和必要后端测试；涉及数据库/事务/流时按仓库要求运行 `pnpm test:backend`。浏览器必须证明真实工具动作与原生数据一致；跳过/失败/超时分别记录。
- 检查、真实模型与浏览器证据集中登记在计划第8节，不沿用此前仅文档阶段或 UI 固定响应阶段的通过结论。
- 不以完整权限产品、独立场景工作台、业务 Session/Run、主动发现或自动化作为本次收尾条件。将来要增加这些能力须另定范围，不能从旧场景矩阵自动重新导入。

既有用户线程不会因本次部署自动启用工具授权。原完整计划的三份 `full-scope-reference` 副本保留，不将其中排除项重新纳入任务。

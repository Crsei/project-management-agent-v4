# 投资人 POC：演示与真实验收

目标：用真实任务和可核验的代码成果，展示“让 AI 围绕任务交付，而不是只在聊天框回答”。不虚构模型执行、CI、评审、成本或收益。

**最新完整 App 场景（2026-11-02）**：[IdeaBoard 场景与隔离预览](./app-scenario-preview.zh.md)记录 TASK-003 从预置需求、真实 Agent 开发到 Draft PR #3、同 SHA CI、可操作 App 和重启数据保留的证据，并附演示步骤。以下既有记录保留为历史验收，不冒充本次现场运行。

## 演示范围与门槛

1. 从公共入口 3224 创建明确需求与验收标准，选用发布的工作流。
2. 启动前展示仓库、Provider、模型、测试与发布授权；不让用户手工拼装 Git 操作。
3. 独立 worktree 内真实 Agent 开发，展示可追溯的当前阶段和过程入口。
4. 测试成功后在隔离验收仓库创建真实 Draft PR；绑定当前 SHA 的必需 CI 全通过后进入待审核。
5. 成果面板展示测试、提交、PR、CI 与任务状态；执行完成不冒充业务验收。
6. 演示一次明确失败/阻塞，保留原记录，说明可采取的操作；不自动重放未知副作用。
7. 提供 5 分钟演示脚本、预检清单、真实结果入口和降级说明。历史证据展示必须标明历史时间，不冒充现场执行。

## 实施顺序

- P0 稳定性：Codex 账号路由请求、公共入口长连接占用、可操作的预检错误。
- P0 交付可信度：明确必需 CI、同提交证据、真实工作流端到端。
- P1 产品表达：任务详情突出“交付工作台”，默认展示阶段/下一步/成果，画布和 Git 技术细节渐进展开。
- P1 演示保障：启动和恢复不重复副作用；准备可复核的历史成果，但不提供伪装成真实运行的演示模式。

## 保留边界

- 仅修改本仓库，保留上一轮未提交改动；本项目 commit/push 仍分别授权。
- GitHub 写入仅使用用户已授权的隔离验收仓库；不合并 PR、不部署。
- 不降低沙箱、证书或权限校验，不复制全局账号凭据，不自动启用暂停的 MCP。
- 会话与持久化仍暂沿用 Agent Chat 基础存储，统一设计尚未收口；本 POC 不宣称多实例 Runner 或生产级分布式事务。

## 如需现场从新任务开始

在同一隔离项目新建任务，不重跑或覆盖已完成的 TASK-002。示例：

> 标题：新增安全整数奇数判断
> 描述：新增 `isOdd(value)`，只接受安全整数；奇数返回 true、偶数和零返回 false；非法输入抛出 TypeError。覆盖正数、负数、零、小数、非数字、非有限数及越过安全整数范围的输入；更新 README；不引入依赖。

1. 保存任务，再进入交付工作台。未保存草稿不会被作为执行输入。
2. 选“开发并交付 v3”、Codex 和当前可用模型；确认基准分支为实际存在的 `main`。
3. 核对 `npm test`、必需 CI `test`、隔离仓库，分别确认执行、限定 worktree 写入、提交、推送、Draft PR 和状态申请。
4. 启动后不需要手工创建分支或操作 Git；可关闭页面，后台继续。
5. CI 达标后确认进入待审核；不要点击“标记完成”来代替验收。

现场时长取决于网络、Provider 和 GitHub 排队，不承诺固定 5 分钟。当前模板的 `test` 是本验收仓库的真实 job 名；接其他仓库时必须在画布中配置其真实测试命令和必需 CI 名称，不盲用默认值。

## 演示前预检与启动

- 统一使用公共入口 **3224**。当前 v4 已切为 **built 模式**，没有 Web HMR；4326 开发上游不运行是预期行为。
- 检查本副本：`.local/dev-env.sh exec node scripts/services.mjs status`。只检查本目录所有的 Worker、PM、Agent、网关与端口，不停止其他副本。
- 需要启动已构建服务时，在已配置的专用 v4 容器内运行 `node scripts/services.mjs start`。切换模式前先用同一脚本检查并停止其拥有的进程。普通 `.local/dev-env.sh start` 会请求开发模式，不用于本次 built 演示。
- 源码改动后重新构建再启动；Web 构建后刷新页面。演示中不要更新代码或重启后端。
- 手工登录 PM；登录过期时手工重新登录，不将账号或密码写进演示材料。
- 在 Agent 设置检查原生会话和可用模型。**已登录不代表可执行**。本机 Codex 实例使用既有宿主代理解决容器账号路由问题，不更改全局代理；不要将该机器地址照搬给其他环境。
- Provider 探测可能需要约 20–30 秒，页面现在允许其完整结束；看到尚未就绪时先处理原因，不重复启动。
- 打开 PR 与 CI 链接，确认网络、GitHub 登录、Draft 状态和 SHA。保留本地截图作证据备份，但断网时明确标为历史记录。
- 若启动返回未知，先“刷新工作流 / 核对启动”；只能核对后重发原 ID 和原参数，不创建第二次执行来试运气。CI 未出现、名称不符、跳过或失败都不算通过。

# 产品规划工作台：需求引导、多任务 Roadmap 与集成预览

日期：2026-11-02。复用 Markdown 核心、项目授权、任务与交付工作流；不是恢复 v3 的完整执行计划，也不新增角色或业务完成规则。遵循 INV-01/03/13/14/15/20、SC-12/13/14/17、Markdown ADR。

## 使用路径

项目导航进入「产品规划」：

1. **明确产品**：逐步回答想法、用户、问题、核心流程、验证目标、非目标、共享实现约定、假设。右侧同步形成轻量 PRD。可载入客户反馈与需求决策场景，仅预填需求，没有应用源码。
2. **规划路线**：按每行用户流程生成候选任务，编辑成果/验收/非目标/阶段；拖动节点、调整位置、选前置依赖，自动布局、缩放与适配画布；发布视图点击节点可核对冻结的成果与验收。规则生成明确标注，不能冒充模型推理；有环、缺失依赖、重复节点或必填缺口不可发布。
3. **Agent 协作**：复制当前 PRD/结构化计划并打开现有项目 Agent Chat，用户选择 Provider 后粘贴发送。不会自动发送消息或写入计划；返回的结构化建议经过格式检查及覆盖确认后才进入草稿。当前不是自动多轮 AI 访谈。
4. 保存后审阅并发布不可变计划版本。发布本身不创建任务、不执行 Agent、不推送代码。后续编辑留在草稿，新版本不改写旧任务，也不自动去重或复用已有任务。
5. 在发布版本逐项创建真实任务。先创建前置任务，后续任务使用真实 `blocked_by` ID；需求、共享约定、范围和验收随任务创建保存。可跳转原任务开发/测试/PR/CI流程，不另建执行器。
6. 线性任务可基于前置已推送分支继续，默认建议该分支；服务端核对前置需求版本、测试、PR、最新CI及基线实际提交祖先关系。准备前、实际准备出的固定基线及开发前均检查。多个前置未集成则拒绝，不自动合并。
7. 项目交付面板汇总真实任务证据，以最后创建的交付为集成候选。所有任务有同版本测试/PR/CI，且提交均包含在候选SHA中，才提供项目预览。启动前再次核对最新GitHub结果，复用既有隔离预览；运行仍仅本机、30分钟、限定Node协议。提交祖先关系不证明功能仍保留，用户仍需跨任务业务验收。

## 数据与一致性

- 草稿与发布版本保存在项目 Markdown 的 `x-pm-product-roadmap`，发布内容不可通过常规核心修改覆盖或删除；`x-pm-roadmap-origin` 固定真实任务来源。阶段仅为规划分组，不冒充业务 Milestone 对象。
- 应用层拥有计划发布检查、任务输入和来源投影；HTTP 使用既有当前授权、工作区SQL锁、文件CAS、原生命令journal/收据、审计和事实捕获。没有数据库迁移，也不引入第二个任务事实源。
- 同一版本/节点的创建键固定，核对原收据；并发跨用户通过串行守卫再次检查来源，不能重复创建。删除/缺失来源不能被当作从未创建，已归档/需求偏离的前置不被静默复用。
- 草稿写入要求项目revision；并发变化不覆盖。响应不明时保留原请求并冻结编辑，先刷新读取真实版本与任务映射，再明确载入服务端内容，不自动重放。发布与创建均不自动转换任务状态。
- 本机未保存草稿按origin/actor/workspace/project分区，离页提示；没有统一跨设备草稿同步。持久化失败明确提示；服务端不可读时不显示为可编辑。
- 最大24节点、20个发布版本；不生成工期、预算或负责人承诺，不做任意DAG自动调度。GitHub授权仍沿用已有任务的独立确认；本功能不批准或合并PR。

## 运行与安全边界

现有单任务预览与项目预览运行同一已提交候选，项目入口额外要求全图提交覆盖证据；并非新建公网服务。只读Chat权限不变，开发只在绑定worktree。CI缺失、过期需求、不兼容仓库、前置代码未包含、未知操作等均保持未就绪；不以假数据或手动勾选覆盖。

会话与持久化尚未统一设计，仍沿用 Agent Chat 基础存储。本次显式划定项目规划源、任务来源、浏览器草稿和既有Agent交付记录的边界，不宣称统一会话设计收口。

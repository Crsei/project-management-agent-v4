# Agent Chat 权限子任务：固定 Full access

状态：FA01–FA07 本次权限切片已实现并完成定向验收；全仓库回归未通过，详见主计划，不自动启用既有用户线程。配套：[本次接入计划与证据](agent-capability-integration-plan.zh.md)、[本次八项任务](agent-capability-integration-tasks.zh.md)、[同步 UI 技术栈](agent-workspace-ui-adoption.zh.md)。

## 1. 本次边界

本清单只负责 **现有 Agent Chat 调用普通 PM 读写工具** 的授权和展示。此前“原 82 个场景仍保留、等 Host/Run/自动化接通后再交付”的表述撤销。这些系统不在本次范围，也不是本次后续阶段。

七项 FA 是 CHAT01–CHAT08 内的权限切片，不另造权限产品，不额外重复计数。这里的“聊天授权绑定”关联现有 thread/conversation，不是新建业务 execution Session；“工具调用记录”不是建设业务 Run 或通用操作调度平台。

## 2. 固定模式，不先做权限产品

- 访问模式固定 `full_access`：仅在用户明确选择的工作区/项目/对象范围内开放本次已接通的普通 PM 工具。
- 审批方式固定 `auto_approve`：用户启用时明确授权允许动作直接落地，此后不逐次弹窗。Full access 与自动批准概念独立；未启用的线程仍为普通聊天。
- 不做模式切换、Custom 编辑、审批策略选择器、层级策略 DSL、复杂预算页或授权中心。
- 无明确范围或未启用时保留原普通聊天，不虚构项目读取权，也不冒充已经实现另一套权限模式。
- 保留当前用户 ACL、目标范围、工具参数、版本/业务守卫、有限有效期、停用与基本调用上限；这些是正确写入所需校验，不是一套额外产品。
- 项目/任务普通创建和字段写入、文档正文、评论、合法关系只走原生应用服务。受保护生命周期、Done、审核、删除/归档、跨项目迁移不进本次自动工具清单。
- 不开放秘密、ACL、自身授权、不可变历史、越权私有数据、通用数据库访问、任意文件读写或 shell。
- 模型和 UI 使用同源能力数据，明确区分“允许访问”和“实际已发送”。未完成的工具不得因为 Full access 标签显示为已可用。

## 4. 操作持久化的限度

需要记录一次工具调用是谁发起、操作什么、是否提交、真实结果是什么。优先复用现有聊天消息/事件、命令幂等键、CreationDraft/收据和原生审计。

不为此增加 execution Session、RunEnvelope、排队调度、租约/epoch、执行目录、产物历史或独立运行页面。聊天内部既有同名 request/run 标识原样复用，不进行无关迁移。操作记录所需的最小数据扩展属于聊天工具适配，不应发展成完整执行系统。

取消聊天生成或停用授权，只能阻止后续派发并核对已经提交的结果，不能把已成功的 PM 写入描述为自动撤销。

## 5. 不在本次范围

- 业务 Session/Run、Host、代码/测试执行、终端、产物核验和 PR/CI 连接器。
- 主动发现、Finding、Pulse、持续扫描、风险推送及对应组件。
- 自动化规则、调度 Worker、后台新建/续接对话、定时摘要和后台自动应用授权。
- 全部旧 S/P/A/J 场景、完整旅程、独立规划/提案/审核工作台。
- 多权限模式、精细策略编辑、动态审批规则、复杂预算和完整授权中心。

这些不是本次的待补阶段，不计入任务依赖或完成标准。若将来需要，另行定义任务，不能从旧计划自动恢复到当前清单。

## 6. 与真实工具接入的配合

权限模式本身不会生成业务能力：CHAT03 负责真实上下文，CHAT04 负责模型工具循环，CHAT05 负责原生业务写入。FA 只覆盖其中权限与可靠性职责，不能单靠改提示词或设置标签宣称“已接入 Full access”。

最终验收遵循 CHAT08：真实模型、真实业务数据、真实工具事件与浏览器交互一致；失败、未知、冲突及停用路径可观察。同步 UI 继续使用既定 assistant-ui/Radix/MessageContent/PM token，不重写聊天主体。

实际授权、工具调用、收据及浏览器验收见主计划第8节。权限切片不重复计数；旧完整场景计划副本保持只读参考。

# 工作区外壳与项目导航改造计划

## 目标与边界

用户授权：先建立修改计划，再由 `gpt-6.1-sol / xhigh` 子代理完成实施。正式 `/pm` 改为稳定的工作区级应用外壳，Project 保留目标、任务、里程碑、成果与完成判断。参考 `../../../UI-package/gr8r-studio/src/shell/layout.js` 的工作区切换、导航分组与可展开项目列表；不移植其 localStorage 演示数据或仅改名称的工作区切换。

当前基础：`pm-shell.tsx` 已包含工作区路由、全局入口和项目列表，但项目内导航插在工作区入口之前；`service-project-layout.tsx` 已提供项目作用域守卫。Markdown 核心和现有业务权限继续为权威，不新增数据库模型、不更改业务完成语义、不修改参考仓库、不接入假 Inbox/通知/Agent 功能。

依据：[领域术语](../domain-design/glossary.md)、[隔离与作用域 INV-01](../domain-design/invariants.md)、[权限与 SC-14](../domain-design/scenarios.md)、[Markdown 接入 ADR](markdown-integration-adr.zh.md)。原始提案的项目归属与权限边界仍适用；核心生命周期继续遵循现行 Markdown 合同，不恢复旧审核完成守卫。

## 目标导航

1. 顶部：当前授权工作区与切换菜单；工作区选择页仍保留。
2. 个人分组：我的任务、重要/关注。我的任务严格显示当前登录人负责的已授权任务；今天、即将到来仅是其内部分组，不再保留独立侧栏入口。
3. 工作区分组：概览、全部项目、全部任务、日历、时间线、文档、视图、成员、团队与工作量、真实活动；日历与时间线复用工作区任务集合布局。
4. 项目分组：授权项目树。每个项目可独立展开看板、列表、时间线、文件；项目内容区继续提供完整视图。当前项目不再重复置于侧栏顶部。
5. 底部：工作区设置、个人白板入口、账户菜单及准确的连接/能力状态。

进入或切换项目不改变工作区导航排列。项目数量多时提供局部搜索或受控折叠，不能截断可访问项目而不提供入口。只使用真实授权结果；错误、空态、加载明确展示。

1. 核对现有并行修改、权限和草稿机制，固定上述契约。

3. 集成：移除 obsolete 出口与引用，确认工作区/项目切换、URL 与筛选一致，保持现有页面和调用方。
4. 统一运行前端 lint、TypeScript、生产构建与受影响已有行为测试；文档检查。若修改后端事务/流则补对应真实后端检查。
5. 使用隔离真实服务和数据或可安全使用的现有授权会话验证下列场景；不读取凭据文件、不写入正式业务测试数据。
6. 验证后补交付证据和 README 入口；清理本轮临时资源，不停其他服务。

## 验收标准

- 工作区顶部菜单仅列授权工作区；切换后名称、URL、项目、任务、权限与订阅全部属于目标工作区。
- 工作区导航始终在项目树之前；进入两个不同项目时分组顺序稳定，项目快捷入口不重复出现在顶端。
- 项目树支持键盘和独立展开；当前项目与当前子视图高亮准确；刷新后展开偏好按作用域恢复。
- 工作区全部任务可展示两个项目并明确归属；日历/时间线同源。进入项目后只出现该项目数据；工作区项目筛选可清除，不改变外壳的作用域。
- 工作区新建明确选择所属项目；项目新建预填并锁定正确项目；取消、保存、返回、刷新不会把草稿带入其他项目/工作区。
- 已有未保存编辑和新建草稿在切换时受到明确保护或可靠恢复；未知写入结果仍需按现行机制核对。
- 受限成员只见授权项目；越权 URL 不泄露内容；聚合视图不扩大权限。
- 桌面及 390px 移动布局、深浅主题、菜单键盘操作可用；现有 Lab 不被正式导航改造破坏。
- 未支持能力不以示例数据冒充。所有验收注明实际执行范围，不将源码推断写成运行事实。

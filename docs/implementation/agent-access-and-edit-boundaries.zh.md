状态：权限设计梳理，待产品确认与后续实现；不是授权配置，也不是功能交付声明。本次仅整理文档，不开放读取、写入、Host 或自动化能力。

## 1. 已讨论什么、尚未确认什么

**尚未逐项确认本副本的模型读取范围、委托能力、可编辑字段、审批策略、代码执行范围与后台自动化策略。** 原计划已给出这些能力的目标与安全约束，可以据此形成权限清单，但不能把配置模型密钥当作授予这些权限。

## 2. 当前聊天模型实际能看到什么

| 数据或动作 | 当前实际边界 | 源码依据 |
| --- | --- | --- |
| 系统提示词 | 收到服务端配置的提示词；默认提示词明确没有工作区写权限 | [agent-chat-config.ts](../../packages/infrastructure/src/agent-chat-config.ts) |
| 当前输入与会话历史 | 收到当前私有会话中被选入历史窗口的用户消息、完整助手回复；窗口默认 40 条、可配置 1–100 条；失败/取消的助手输出不作为完整历史发送 | [agent-chat-routes.ts](../../apps/api/src/agent-chat-routes.ts)的 history 查询与模型消息组装 |
| 用户粘贴的项目内容 | 作为普通消息发送给模型；不等于模型可以查询对应业务对象或验证其当前版本 | 同上 |
| 项目/任务/文档、成员、附件、审计、代码 | 当前聊天请求未自动组装这些上下文，也没有向模型开放读取工具 | [agent-chat-model.ts](../../apps/api/src/agent-chat-model.ts)仅发送 model/messages/stream |
| 项目入口上下文 | 当前界面可显示入口项目，但不因此把项目或任务数据发送给模型 | [AgentChatPage](../../apps/web/src/features/pm/agent/agent-chat-page.tsx)、界面接入矩阵第 6 节 |
| PM 写入与工具执行 | 没有提供修改 PM 对象或执行命令的模型工具；模型输出只是文字 | 模型请求与聊天路由 |
| 会话保存/删除、停止生成 | 是认证用户触发的聊天服务动作，不是模型拥有业务编辑权限 | 聊天路由的主体/工作区/会话归属检查 |

因此，模型回答“不能查看项目，也不能编辑”符合当前接入；但“只能看到本次消息”不够准确，它还会收到服务端选入的当前会话历史。模型自述不是权限探测结果，后续应由服务端提供真实能力描述。

## 3. 目标权限模型：四种动作不能混为一谈

| 层级 | 允许的效果 | 必要条件 |
| --- | --- | --- |
| 授权读取与分析 | 解释、检索、总结、查重、依赖分析；不改业务对象 | 当前用户有权、委托范围覆盖、项目策略允许；服务端加载并标记来源版本 |
| 生成候选/提案 | 保存未发布任务草稿、字段差异、文档候选、Finding；正式项目/任务/正文保持不变 | 明确用户请求，或已启用且允许该输出的后台规则；候选自身持久化也必须按权限执行 |
| 人工确认后应用 | 由原生应用服务创建任务、修改允许字段、保存文档或关联关系 | 展示目标、before/after、来源 revision；有权人确认；当前权限与版本复核；原请求键、收据及审计 |
| 受控执行 | Host 在隔离目录读写允许文件、运行允许的测试，登记真实成果 | 独立执行能力、受信 Host、项目根策略、精确动作审批、租约/收据；不允许任意 shell 或直接改原仓库 |

“能生成建议”不等于“能应用建议”；“能读项目”不等于“能读服务器文件”；“用户能操作”不等于“模型自动继承用户全部权限”。权限必须由服务端执行，不能只靠 system prompt。

## 4. 数据对象读取与编辑清单

下表是从计划提炼的目标边界。最小化范围等未明细化部分作为推荐策略，见第 9 节；本副本目前未开放这些业务读取/写入工具。

| 数据对象 | 可提供的读取范围 | 可产生的修改 | 不允许或需要额外条件 |
| --- | --- | --- | --- |
| 项目 | 选定授权项目的名称、目标、描述、当前工作流、关联任务/里程碑/依赖与必要活动 | 开发计划、风险分析、里程碑/任务候选 | 不因项目摘要自动关闭/归档项目；不默认扫描整个工作区 |
| 任务 | 标题、正文、状态、优先级、负责人引用、验收标准、父子关系、里程碑和依赖；范围由选定对象/查询确定 | 新建/拆解候选，标题/正文选区、验收标准、优先级/负责人/状态和关系提案 | 状态按当前工作流处理；完成/取消/重开不由模型自行决定；未明确的字段不自动加入工具白名单 |
| 文档 | 已保存正文、来源 revision、选区、明确关联的授权对象 | 改写差异、总结/决策/知识/风险文档候选，确认后保存 | 不自动保存全文；不能覆盖用户后续编辑 |
| 未保存草稿 | 仅用户明确选择附加的草稿/选区，标注未保存及其来源 | 生成建议 | 默认不发送；不能把草稿当作已保存事实或有效写入基线 |
| 评论与讨论 | 指定任务的授权评论、显式 @Agent 的内容及必要上下文 | Agent 来源评论、关联提案；字段变更另行确认 | 不伪装人工评论，不编辑他人历史评论，不把普通提及自动解释为字段写入授权 |
| 会话与 Session | 当前会话；显式关联且获授权的其他会话/执行 Session | 消息追加、来源化候选 | 不因为同属一个项目就扫描所有成员私有对话；不能覆盖旧会话或混淆聊天与执行 Session |
| Run/测试/成果 | 获授权 Run 的输入快照、日志、diff、真实测试输出、退出码、成果元数据；字节内容单独授权 | 失败调查候选、PR 本地草稿、总结、核验报告 | 不伪造通过结论，不改历史输入/收据，不把 Run 成功转换为任务完成 |
| 人员与负责人 | 仅分派/规划必要的可见成员标识与显示名，遵循成员目录权限 | 为有权人提出负责人建议 | 不读取无关邮箱/电话/账号资料，不修改成员角色或授权 |
| 审计与通知 | 当前授权对象的来源、审阅/待办状态；审计另需 audit.read | 用户确认的审阅备注、个人已读等既有交互 | 不改审计历史；读取列表不允许模型代用户自动处理审批 |
| 普通附件 | 明确选中的授权附件；元数据与内容分别检查，内容提取能力需单独实现 | 可用作分析依据或新成果来源 | 计划中的 RunArtifacts 不等于任意上传文件都能解析；默认不整库读取附件 |
| 项目代码 | 管理员配置的受信项目源码根中的允许普通文本，经有界只读快照进入隔离 Run | 隔离 Run 内的文件变更、真实 diff/test/产物 | 不修改原代码目录；不读 .env、密钥、凭据、符号链接逃逸、依赖/生成目录；不暴露主机绝对路径 |
| 外部 PR/CI | 配置好的真实只读来源适配器返回的授权数据 | 覆盖缺口、风险与调查提案 | 无访问前提时禁用对应来源；不伪造 PR URL，不创建/合并远端 PR，不 push |
| 工作区设置与凭据 | 必要的业务规则和脱敏能力状态 | 本轮不授予模型管理写入 | 不读取/修改密钥、数据库配置、授权策略、账号安全、工作流配置或基础设施 |

跨项目引用必须逐个校验权限；工作区范围查询只能返回用户授权且此次委托允许的结果。归档/删除后的历史仍受权限保护，不因保留快照而公开。

## 5. S01–S36：交互场景对应的权限

共同规则：除表中明确的用户聊天/审阅动作外，业务修改都经提案确认或独立执行审批；这里只描述目标，不声称本副本已实现。

| 场景 | 模型需要的输入/读取 | 允许的输出或应用边界 |
| --- | --- | --- |
| S01 详情侧栏 | 当前任务已保存内容；草稿默认不发送 | 开关面板无业务写入、无隐式执行 |
| S02 自然语言建任务 | 用户描述、明确目标项目及创建规则 | 编辑候选后显式发布；取消零正式任务 |
| S03 选区改写/缩短/扩写 | 标题或正文选区、定位与来源 revision | 预览/拒绝不写；确认只改目标区，撤销需版本匹配 |
| S04 补验收标准 | 当前描述与已有标准 | 确认后写原生验收字段，不改状态、不写成评论 |
| S05 展开工作台 | 同一对象/会话、相关报告引用 | 导航不新增消息/Session/Run |
| S06 返回原任务 | 原来源和 UI 恢复信息 | 不触发模型或业务写入；草稿不丢失 |
| S07 Coding Agent | 固定任务版本、允许的源码快照与执行指令 | 人工申请 Run、逐受控动作审批；仅隔离目录副作用 |
| S08 结果回任务 | 对应 Run、待审批与历史、成果摘要 | 人工审阅标记持久化；不完成任务 |
| S09 消息转任务 | 明确来源消息、会话与目标项目 | 先未发布候选；人工编辑发布，保留来源链接 |
| S10 引用对象 | 选择器选定的项目/任务/文档真实 ID 与 revision | 服务端加载当前授权内容，不仅回显名称/token |
| S11 评论调用 | 显式 @Agent 评论与授权任务上下文 | 真实 Agent 来源评论/提案；拒绝提案不改字段 |
| S12 拆子任务 | 当前父任务与范围 | 审核后创建正式子任务，保存正确 parent |
| S13 多任务生成 | 指令、项目、候选及选择集合 | 只发布明确选中的候选，不自动发布其余项 |
| S14 批量修改 | 明确选定任务及各自 revision | 优先级/负责人/正文/状态逐项预览、接受/拒绝；完成动作仍由有权人确认 |
| S15 多 Session | 获授权任务的独立 Session/Run 历史 | 显式创建新身份，旧输入/历史不覆盖 |
| S16 面板/全页连续 | 同一私有会话与未发送输入 | 去重、保留输入；切换不重建会话或派发 |
| S17 看板交给 Agent | 明确选择的完整集合；区分筛选全量、已加载、追加分组 | 分析只读；批量编码逐任务独立授权，不因首屏分页缩小范围 |
| S18 项目目标转计划 | 授权项目目标、已有里程碑/任务/依赖 | 编辑候选后分批发布；映射真实 ID，拒绝缺失依赖/成环 |
| S19 查重与关联 | 范围内候选任务与相似依据 | 确认后写关联，不自动合并或删除 |
| S20 依赖分析 | 权限过滤后的真实关系图 | 提案确认后写合法依赖；当前跨项目规则优先，不绕过防环 |
| S21 审查 Diff/Test/PR | 实际 diff、测试 stdout/exit/断言、产物 | 形成分析/本地 PR 草稿；不远端发布、不完成任务 |
| S22 失败转 Bug | 固定失败 Run、日志及证据 | 人工编辑后发布新 Bug，保留失败现场 |
| S23 文档编辑 | 明确文档/关联来源、选区与 revision | before/after、拒绝、接受、安全撤销；不覆盖手工保存 |
| S24 项目总结 | 授权项目下必要任务、Run、文档及来源版本 | 只读总结；不推造完成率、根因或健康事实 |
| S25 失败/停止/重试 | 当前 Run 状态、操作收据和失败信息 | 请求取消不等于已停止；重试是新 Run 与新授权 |
| S26 刷新/断网恢复 | 同一请求/Run 的权威状态与原键 | 只查询核对，不重派、不凭断网修改任务状态 |
| S27 权限与审批 | 当前委托、对象范围、动作参数摘要、审批有效期 | 有权人批准精确动作；拒绝/撤权不派发，恢复权限不自动批准 |
| S28 版本冲突 | 提案冻结 revision 与当前版本 | 冲突拒绝旧写入，保留双方内容；不能静默重算后应用 |
| S29 并行运行 | 各自任务、Session、Run、沙箱与审批 | 独立并发、独立取消，不共享越权工作目录 |
| S30 Inbox/Activity | 授权运行/审批/发现及来源 | 原生已读/导航行为；不因进收件箱自动接受提案 |
| S31 关闭/归档历史 | 授权历史快照与生命周期状态 | 人工原生生命周期操作；活跃/未知执行守卫，归档禁新执行 |
| S32 布局适配 | 无新增业务读取需求 | 纯 UI 适配不扩大权限、不自动附加编辑器草稿 |
| S33 不可用/空态 | 脱敏能力、授权和依赖真实状态 | 无写权限可在读授权内分析/预览，禁止应用；恢复不造 Run |
| S34 跨项目移动 | 源/目标项目权限、关系及历史归属 | 明确原生移动操作；重新授权、保持任务 ID 和历史 Run 输入 |
| S35 大数据边界 | 已授权且被明确选定范围的完整分页/长内容 | 不因分页偷读其他项目，也不将截断正文保存回源对象 |
| S36 审计与撤销 | 原操作、before/after、当前 revision；审计单独授权 | 版本安全撤销；后续编辑拒绝旧撤销，历史审计不可变 |

## 6. P01–P24：主动发现的数据范围与副作用

主动发现不是“模型持续读取所有数据”。先由启用的规则按明确范围获取真实来源，再按必要字段调用模型；Finding、候选和正式对象是不同状态。

| 场景 | 必要来源 | 允许结果与限制 |
| --- | --- | --- |
| P01 相似任务 | 新任务与授权已有任务 | 关联提案；不自动合并/删除 |
| P02 内容缺项 | 更新后的任务与完整性规则 | 补全提案；Level2 可准备 pending，不应用 |
| P03 7 天停滞 | 持久任务活动、评论、Session/Run 时间 | 跟进提案；真实时间，不造旧日期 |
| P04 依赖满足 | 当前依赖与任务工作流 | 排期/状态建议；应用前再查权限与状态 |
| P05 测试通过 | 同版本非空真实测试与验收依据 | 人工送审建议；不自动完成 |
| P06 范围相交 | 正式依赖与声明修改范围 | 协调任务草稿，来源可查 |
| P07 成功总结 | 成功 Run、摘要与成果 | 来源化活动、总结文档候选；文档确认后保存 |
| P08 失败调查 | 失败 Run、日志、测试与文件 | 调查草稿；根因保持假设 |
| P09 遗留事项 | 授权会话中的明确遗留原话 | 未发布任务候选，人工编辑发布 |
| P10 PR/CI 缺口 | 真实外部只读适配器与标准 | 补验收草稿；无适配器/授权则阻塞 |
| P11 并行范围交叉 | 时间重叠的 Run、同受信源码身份与真实 diff | 协调草稿；只提示冲突风险 |
| P12 重复失败 | 多 Run 的失败测试/错误 | 假设与执行申请；不自动执行 |
| P13 明确决策 | 授权来源消息 | 决策文档候选；不代替正式决策批准 |
| P14 超范围修改 | Host diff 与声明范围 | 范围复核草稿；不自动回滚 |
| P15 需求变更影响 | before/after 需求版本及关联下游 | 影响分析文档候选 |
| P16 重复技术主题 | 明确授权的多 Session 内容 | 知识文档候选；不突破私有会话边界 |
| P17 共性失败 | 不同任务真实 Run/失败来源 | 共性调查候选 |
| P18 后续规划 | 阶段完成事实与下游工作 | 规划候选，原生审核后发布 |
| P19 每日变化 | 持久观测边界与真实变化 | 项目摘要；无变化不造日报，浏览器不是调度器 |
| P20 14 天阻塞 | 历史进展与真实阻塞 | 项目调查候选；不倒填业务日期 |
| P21 发布风险 | 里程碑、未完成/失败/待审对象 | 风险文档候选；不宣布可交付 |
| P22 离开期间摘要 | 持久访问水位与新增事实 | 去重摘要；不倒退水位重放 |
| P23 目标偏离 | 目标、未完成目标任务、近期真实文件变化 | 下一步规划候选；不凭 Session 数量判断 |
| P24 后续行动 | 目标任务、满足的依赖、明确遗留 | 可编辑规划候选；不自动发布 |

策略沿用矩阵：Level1 自动观察/建议，明确人工确认的写入仍允许；Level2 仅额外允许自动准备 pending 字段提案，不自动应用；Level3 不开放。项目暂停、逐规则启停、冷却、预算、语义去重、来源版本与权限变化失效均须由服务端执行。

## 8. 必须由应用层兑现的权限合同

### 8.1 读取与发送给模型

- 每次请求绑定可信身份、工作区、明确项目/对象集合和上下文用途；前端 URL、模型文本及引用 token 都不是授权。
- 推荐有效范围为：当前用户权限 ∩ 明确委托范围 ∩ 项目策略 ∩ 实际工具能力；运行派发还必须满足具体动作审批与领域守卫。未来独立 Agent 身份不能继承 owner 全权。
- 服务端读取并生成上下文清单：对象类型/ID、来源 revision 或事件身份、读取时间、选区、是否未保存、必要引用；摘要注明范围是否完整，不能把无权/未加载当成不存在。
- 服务端读取后发送给外部模型属于数据外发，不等于本机普通查看。应展示实际发送范围，最小化正文/日志/附件内容；密钥、认证 cookie、数据库口令及无关个人数据不得进入上下文。
- 切换工作区、撤销权限后停止新读取/派发并释放无权缓存/订阅；已发给供应商的数据不能宣称可以追回。历史上下文再次发送前也需要当前授权复核。

### 8.2 应用提案

- 模型仅返回受校验的候选结构；不能获得直接 SQL、任意 Markdown 路径写入或绕过原应用服务的工具。
- 显示作用对象与字段、before/after、来源版本、可能的副作用；有权人确认后，服务端再次校验权限、当前 revision、归档/终态限制和关联规则。
- 普通规划写入沿用 planning.edit 及项目范围；生命周期沿用原生能力；状态中的 Done 不能作为普通字段更新绕过 workitem.complete 与当前原生规则。批准工具动作与成果审核、任务完成是三件事。
- 批量操作逐对象保留版本和结果，不宣称跨文件/SQL 全部原子成功；应用、发布、撤销使用原请求身份，未知先查收据，不自动换键重做。
- 记录模型来源、发起/确认主体、目标、输入版本、实际写入结果与审计；不修改旧 Run 输入、成果版本、审批/审核历史。

### 8.3 执行与禁止项

- 精确审批绑定 Run、operationId、动作、资源、参数摘要与有效期；更换参数、目标或运行须重新审批，不设永久“全部允许”。
- 模型不能批准自己的动作、提交通过审核、授予自己权限或自行断言工具执行成功；权威回报来自受信 Host/验证服务。
- 明确禁用：任意 shell、读取服务器任意路径、修改原仓库、Git commit/push、远端 PR 创建/合并、生产部署、工作区权限/密钥管理、Level3 自主业务应用。本轮计划不因工具审批而解除这些禁止项。
- 任意 shell 禁用不等于禁用全部测试：允许的是由 Host 适配器限定的可审阅测试动作，限定工作目录、参数、资源与环境；不能让“测试命令”成为任意执行入口。

## 9. 尚需确认的产品选择与推荐默认值

以下是待确认建议，不是本次已获得授权；确认后仍须实现接口与守卫，不能只修改提示词。

| 决策 | 推荐默认值 | 放宽的代价 |
| --- | --- | --- |
| 默认读取范围 | 当前明确选定项目/任务/文档；项目汇总操作才展开该项目的授权关联数据 | 全工作区自动检索会扩大数据外发与越权防护面 |
| 跨项目分析 | 用户显式选择额外项目/引用，各自复核；不默认绑定第一个项目 | 默认跨项目汇总容易混淆完整性与项目边界 |
| 未保存内容 | 默认不发送，用户勾选并标记草稿 | 默认发送会泄露尚未决定保存的内容 |
| 会话与长期记忆 | 当前会话及明确授权关联来源；不启用跨用户私有对话记忆 | 全历史知识化需额外共享授权、撤权与保留策略 |
| 正式业务写入 | 一律预览并明确确认；批量可一次确认已逐项审阅的选择集 | 无确认写入不符合当前计划，不作为快速模式开放 |
| 生命周期与移动 | 模型给建议；有权人在原生流程完成/取消/重开/归档/移动 | 不能用“Agent 有 planning.edit”替代这些独立能力 |
| 附件和代码 | 附件按次选择；代码仅管理员登记的只读源码根快照，写隔离 Run | 全盘/原仓库访问超出当前计划；普通附件解析需另定支持类型与限额 |
| 自动化启用 | 初始关闭；有权人显式启用 Level1，Level2 单独开关；Level3 禁用 | 后台持续外发、模型费用及跨时区调度需预算和审计 |
| 外部模型数据 | 先展示上下文类别/范围、脱敏；不自动附加私密资料 | 供应商保留/地域/合规要求需部署方单独确定，不能由应用保证删除 |

建议后续实施顺序：先接授权只读上下文与真实能力说明，再接提案预览/人工应用，然后接隔离 Host/精确审批，最后接主动发现与自动化。此顺序不代表本次开始实施，也不自动恢复来源计划的历史批次。

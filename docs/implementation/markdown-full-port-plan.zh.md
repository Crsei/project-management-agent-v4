## 1. 执行原则：先复制代码，再适配接口，形成独立模块

用户已明确要求采用以下优先顺序：

1. **直接复制 Lab 中对应的实现、必要样式和行为测试。** 目标已有复制代码时优先核对和复用，不能盲目覆盖用户修改，也不要再创建一套平行实现。
2. **先修改路径、依赖和宿主接口。** 把固定 API 地址、全局缓存键、导航、登录上下文、工作区路径等替换为目标 PM 的接入方式。
3. **以独立模块暴露能力，再由 PM 页面和服务调用。** 不把解析、文件写入和草稿状态分别散落进现有 PM 各页面。
4. **复制后的行为对齐后，再做必要的小范围拆分。** 不以“顺便重构”为由重写解析器、编辑器状态机、查询器或迁移恢复协议。
5. **例外必须有证据和记录。** 只有框架差异、依赖兼容、安全边界或实际缺陷等必要原因才偏离直接复制；说明源文件、目标文件、原因、行为影响和验证。不以个人偏好替换成熟实现。

“独立模块”是有清晰输入输出、可独立验证的工程模块，不要求拆成独立部署服务。PM 不能依赖参考 Lab 的源码路径、端口或常驻进程；复制后的代码由目标仓库维护。

### 1.1 明确禁止

- 只复制界面样式或设计截图，再从零写一套简化行为。
- 把 CodeMirror 换成普通 textarea 交付，或用现有 Tiptap 取代 Lab 原文模式。
- 用正则重新解析整份 Markdown、用 JSON 重序列化全部 YAML，丢掉原有 AST/CST 处理。
- 把外部文件监听改成手工导入，把工作区视图改成仅 localStorage，把文件权威改成 SQL 导出。
- 将旧 PM 的审核、UUID、同项目依赖等冲突规则嵌入复制模块，导致合法 Lab 行为失效。
- 以编译成功、复制完成或 Storybook 展示替代真实接口、文件和浏览器验收。
- 把尚未接通的入口保留为假数据、空实现或永久兼容层。

## 2. 源实现依据与能力边界

参考项目为 `../markdown-pm-lab`。源行为说明见[Lab README](../../../markdown-pm-lab/README.md)和[Lab 模型协议记录](../../../markdown-pm-lab/docs/model-protocol-plan.md)。以下源文件路径均相对于 Lab 根目录。

本专项核对了编解码、预览、工作台交互、客户端、表单、依赖和部分回归用例，不把依赖列表当作全部行为已经在目标项目验收的证据。

### 2.1 已有 Markdown 技术组成

- `yaml` Document/CST：读取 frontmatter、保留式字段修改、注释/锚点/别名处理。
- `unified + remark-parse + remark-gfm`：提取真实标题、清单行、Wikilink 和嵌入 pm-view。
- `@uiw/react-codemirror + @codemirror/lang-markdown`：原文编辑和编辑器能力。
- `react-markdown + remark-gfm`：预览基础 Markdown/GFM；源 `remarkWorkspace` 扩展清单定位、callout 和 Wikilink。
- `pm-schema/query`、`pm-views`：嵌入和主视图共用 DSL、配置、筛选、分组和写回。
- `pm-core`：文件仓库、revision、投影、监听、生命周期、幂等及迁移恢复。

### 2.2 不虚构源项目没有的功能

全量移植是完整保留源能力，不是把所有 Markdown 生态能力都列成已实现。当前预览针对 `pm-view` 有特殊处理，其余代码块按代码展示；不能据此宣称已有 Mermaid 图执行、数学公式插件、MDX、可执行 HTML 或完整代码高亮插件。

Wikilink 的索引提取和界面导航要分别验证，不能把提取时识别 `#片段` 等同于已经实现完整段落锚点跳转。若核对中发现源实现的边界或缺陷，登记并单独处理，不在复制时静默放大承诺。

## 4. 独立模块和宿主接口契约

### 4.1 模块职责

| 模块 | 应负责的内容 | 不得依赖的内容 |
| --- | --- | --- |
| pm-schema | 协议类型、字段/配置/关系/DSL 校验 | PM 页面、登录实现、数据库业务模型 |
| pm-markdown | 纯编解码、AST/CST 提取与保留式修改 | HTTP、React、文件监听、数据库、全局浏览器状态 |
| pm-core | 权威文件、持久状态、投影、命令、监听、context、迁移恢复 | React、浏览器路由、PM 旧任务表写入 |
| pm-views | 主/嵌入看板、表格、树与图及受控操作回调 | 固定 API 地址、独立持久业务副本 |
| pm-workspace-ui（建议新增） | 复制出的完整 Markdown 工作台、预览、表单与草稿交互 | 直接读取 Node 文件系统、导入宿主私有 store、硬编码演示账号和对象 |
| pm-cli | 用户/Agent 命令入口及输出 | 本地旁路改数据库、无条件重试覆盖 |
| PM 宿主适配层 | 路由、认证、工作区定位、事件连接、产品导航和依赖装配 | 重新定义一套 Markdown 解析/状态转换/关系规则 |

模块可按现有工程选择包入口和构建方式，但必须具有明确公开入口、依赖方向和独立验证路径。不要让浏览器 barrel 间接导出 `node:fs`、`node:sqlite` 或启动服务；共享类型使用纯类型入口或 `import type`，不为浏览器再复制一套类型定义。

### 4.2 UI 需要的宿主输入

直接从源实现提取最小接口，不预先建设插件系统或通用执行框架：

1. **客户端方法集合**：以源 `api.ts` 为起点，覆盖 workspace/protocol/file/save/patch/createEntity、生命周期、context、config/query/view、migration 全部方法。
2. **事件订阅**：提供目标工作区的连接和取消订阅方式，保留 ready/change/error 等语义；不能继续固定连接源 `/api/events`。
3. **主体和工作区命名空间**：Query 缓存、draft、selected、preferences 都必须隔离；工作区切换时旧保存响应/事件不能污染新工作区。
4. **导航回调**：对象选择、Wikilink、关系和 context 跳转交给宿主路径适配；内部实体 ID 保持 Lab 身份，不转换成另一套可写对象。
5. **可用性和权限**：宿主可控制读写入口，但服务端仍独立授权。不能把旧 PM 审核前置条件包装成所谓“权限”来阻止 Lab 合法状态转换。
6. **布局与主题边界**：宿主负责页面外壳；模块内部保留源布局、键盘、焦点、禁用状态和反馈，不重复创建应用根或第二个全局数据缓存。

源 App 的固定 `PRJ-001`、`TASK-102`、`pm-lab:*` localStorage key 和 `['workspace']` Query key 必须适配。空工作区应正常进入空态和创建流程，不能要求复制示例数据才可启动。

### 4.3 服务与文件核心接口

- 服务器从已授权工作区映射到经过校验的真实根路径；不允许客户端直接传任意路径。
- 复用 FileRecord/WorkspaceSnapshot、configurationRevision、stale、unsupportedFiles 与 Diagnostic 等协议结果；不要只返回简化 task DTO 导致编辑器缺少原文或版本。
- 保留 raw 与 revision 的保存语义，结构化更新全有或全无，创建幂等、生命周期确认、视图/config 的 CAS 与迁移确认均完整。
- 路由适配保留源文件上限和传输请求体上限各自的作用，JSON 编码大小不能混同文件 UTF-8 大小。
- SSE 触发真实文件变更查询，不把成功写文件改成只改客户端缓存；事件按授权范围分发，退出或切换工作区必须清理订阅。
- `.pm/cache/` 可重建；`.pm/state/`、配置、视图、ID/幂等/墓碑和迁移记录不可当缓存删除。

### 4.4 允许保留的 PM 附加模块

账号、正式审核、成果/附件、对话/意图、白板等按主计划 E01–E12 处理，可以暂不文件化。它们通过核心接口读取或修改共同对象，不得成为本模块的私有反向依赖，也不能要求核心写一份旧 PostgreSQL Task 才能工作。

PM 富文本、日历和甘特也调用同一正文/属性接口；一个对象不能有 CodeMirror 一套状态、富文本另一套正文、SQL 又一套排期。

| MD19 | 创建幂等、归档/恢复/删除与文件引用保护 | C01/C03/C05/C07/C10；L18/L19/L24 | 不重复创建；归档不改 status；删除检查正式/自定义/Wikilink/order 引用，确认后留墓碑，不静默级联 |
| MD20 | Markdown context 装配及入口 | C03/C05/C08/C10；L09 | 已保存项目、父项、阻塞与关联文档进入 context，Web/API/CLI 一致；不混入无权限内容或未保存草稿 |
| MD21 | 协议迁移预览/应用/历史/备份恢复 | C03/C07/C08/C10；L26/L27 | normalize-v1/transform 均能实际使用；预览不改源，需显式确认，过期预览/后续外部修改不被覆盖；合法恢复返回原文 |

| MD23 | 全部 Markdown HTTP/CLI 操作及模块可独立运行 | C08/C09/C10；L29/L30 | 目标服务实际读取/修改文件，CLI typed 参数与 revision/确认生效；不连接参考 Lab，不靠 mock echo 验收 |

### 5.1 源行为与新增安全适配的区别

账号/工作区隔离、授权和 PM 路由接入是必要宿主适配；不改变正文标题、文件身份、Lab 允许的状态转换和关系语义。不能借“安全适配”重新加入旧 PM 的强制审核流程。

发现源实现缺陷时，先记录可复现行为与修复范围；修复后补消费者可见回归。既不要求复制已知缺陷，也不允许把大规模重写伪装成修复。

## 6. 优先复制的实际施工顺序

### MD-P0：确定复制基线，不覆盖已有改动

- 与主计划 P0 同步，核对 C01–C12 与目标现有文件；记录来源版本/摘要和本地差异。
- 明确共享类型、包入口、浏览器/Node 边界、客户端接口、工作区命名空间及 CSS 作用域。
- 把 MD01–MD24 分配到目标文件、负责人及验收场景。已有源码不等于验收完成，不填写推断成绩。
- 门槛：没有未处理的覆盖风险；不把独立模块设计成散落于 PM 页面的一组临时代码。

### MD-P1：复制并落稳纯协议与编解码

- 以 C01/C02 为基础直接复制或复用，先只改导入/依赖，保留函数、诊断及数据结构。
- 迁入对应 roundtrip/protocol/query 行为用例，先证明目标工程中的 AST/CST 和类型语义一致。
- 不先做“统一 PM 模型”的重构，不提前把非 UUID ID、自由分派文本或跨项目阻塞改掉。
- 门槛：MD01–MD04 的完整语义成立，纯模块无需启动 PM 数据库或 UI 即可验证。

### MD-P2：复制文件核心、API 和 CLI，再改宿主接口

- 以 C03/C08/C09/C10 为基础接通目标工作区路径、服务生命周期及授权。
- 持久状态、文件监听、诊断、context、迁移恢复代码优先保留；Hono/Fastify 差异限制在传输适配层。
- 更新全部目标调用方和 CLI，保留 API 方法能力，不增加绕开核心的 PM 私有写入路径。
- 门槛：MD15–MD23 的服务/CLI 部分在真实隔离目录运行，文件和恢复状态可观察。

### MD-P3：复制完整前端工作台，最小化抽取接口

- 先复制 App/Preview/表单/诊断和必要样式，再将源 App 改为独立模块导出，不整体覆盖目标应用根。
- 将固定客户端、SSE、缓存/草稿键和导航改为第 4 节接口；先保留其状态流程，再按需要提取小组件或 hook。
- 保留 CodeMirror、react-markdown、remark 扩展和 pm-views，不用 PM 现有富文本组件替代原文能力。
- 门槛：模块在目标 PM 正式宿主内能操作真实后端；独立挂载验证也使用真实客户端，不用样例状态冒充业务。

### MD-P4：补齐 Markdown 交互专项与旧视图联动

- 逐项完成 MD05–MD14、MD16–MD21、MD24 的真实浏览器场景；不是只看一张预览截图。
- 同步 PM 旧列表/详情/日历/甘特/富文本的适配；这些视图不得为同一个对象保留另一份正文或状态。
- 验证外部编辑、嵌入创建、清单行定位、属性写回、草稿冲突与配置锁写的完整链路。
- 门槛：原文、预览、属性、嵌入和 PM 旧视图共同读写同一权威对象。

### MD-P5：独立 review、故障验收与去除临时接入

- reviewer 检查复制来源/差异、是否被旧业务语义污染、接口依赖方向、全量能力遗漏及安全/恢复边界。
- 修复问题后执行目标工程回归、真实 HTTP/CLI/磁盘/浏览器场景，记录证据到各 MD 项。
- 移除临时 harness、重复客户端和被替代入口；保留正式测试和必要开发展示，但不能依赖临时服务器交付。
- 门槛：所有 MD 项完成，例外有明确依据，review 已复核；只有这时允许专项整体完成。

### 8.1 源测试优先迁入

优先复制这些资源中的有效行为测试，改启动/路径/认证适配后运行；仅断言实现文本、内部结构或偶然文案的用例不作为交付标准。不得为通过目标测试而删除能捕获真实丢数据、越权、状态错误或恢复错误的场景。

源 Lab 记录的 179 项回归和 37 项 smoke 是参考覆盖，不是目标项目已通过。测试数量不能替代逐 MD 项证据。

### 8.2 必须实际操作的关键链路

1. **原文 → 面板 → 文件：** 修改标题、状态、自定义字段，观察 Draft；保存后检查磁盘和其他视图，正文/注释符合保留契约。
2. **面板 → 原文：** 拖拽/属性/表格更新后检查对应 Markdown，刷新和重启后仍一致。
3. **预览 → 原文：** 点击真实清单，核对含 frontmatter 的准确源码行；并发改行后拒绝错写。
4. **文档 → 嵌入视图 → 对象文件：** 渲染真实 pm-view，在嵌入视图创建/编辑，不因全局筛选类型不同写错对象或项目。
5. **外部编辑 → SSE → 页面：** 实际改文件，观察自动更新；写坏、诊断、修复并恢复，不能用主动刷新掩盖监听缺失。
6. **双来源冲突：** 保留本地草稿，另一来源先写；保存收到明确冲突，用户确认合并后才成功。
7. **配置/未知版本：** 无效配置锁写但不丢草稿，修复后恢复；未来 schema 可读不可写且字节不变。
8. **文件迁移与恢复：** 真实预览/确认/应用/历史/恢复，检查原文和协议状态；模拟中断和外部冲突，不只验证 API 返回 success。
9. **宿主隔离：** 切换账号/工作区后不泄露草稿或事件；旧 PM 详情与新工作台不能各自写一份内容。
10. **独立交付：** 目标 PM 单独启动，不读取参考 Lab 的源码或生产 workspace，不调用其服务；真实 UI/API/CLI 均可操作。

浏览器验证包含实际画面、焦点/键盘、弹窗、分隔线及窄屏布局；不是只测试组件“不报错”。文件和恢复操作必须在自有隔离工作区运行，不能用用户数据作为破坏性 fixture。

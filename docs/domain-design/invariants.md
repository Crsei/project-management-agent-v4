# 业务不变量

> 适用性：本文件保留v0.1历史提案/稳定编号，不代表完整业务Runner或旧SQL核心规则已启用。当前Markdown任务状态、审核独立性与关系语义以[已采纳ADR](../architecture/adr/0003-markdown-core.md)及[入口第七节](README.md#implementation-plan)为准；Chat thread/generation不能替代历史Session/Run模型。

这些规则是 [v0.1 提案](README.md) 的可验证约束。UI 隐藏按钮、提示词约束或读模型过滤都不能替代服务端检查。拒绝命令不得发布成功事件。

当前 Markdown 核心对任务状态、审核独立性与跨项目任务依赖的规则，以[已采纳 ADR](../architecture/adr/0003-markdown-core.md)为准；下表保留 v0.1 历史编号，不能据此重新引入已移除的 SQL 核心守卫。Dashboard 新增能力遵守本页末尾的补充规则。

## 拒绝与恢复原则

冲突返回当前版本或可查询的冲突引用，调用方读取后重新决策；不得自动合并可能改变业务意图的字段。重放相同命令前仍检查调用方能否读取原结果，不能借幂等接口泄露已撤销权限的数据。

审核、运行与工作项历史不得因“重新来一次”而清空。一次操作的成功响应只能在本地事实及其待发布事件可靠提交后返回；外部动作结果未明时返回可查询的 unknown，不能伪装成已失败供调用方盲重试。

## Dashboard 补充规则

实施范围和十二项验收见 [Dashboard 后端说明](../guides/project-management.md)；属于当前人工项目管理接入，不开放 Agent。

| 编号 | 必须保持的规则 | 验证边界 |
| --- | --- | --- |
| DASH-INV-01 | 关注、便签、本人资料和工时按 actor 隔离；私有事件与收据不能被其他成员读取。项目受限成员仍能管理自身私有资料，不因此获得整个工作区权限。 | SQL 查询、命令、收据重读、outbox/SSE、前端撤权清理；SC-13/14、INF-03/06 |
| DASH-INV-02 | 每工作区每人最多一个活动计时器；停止与唯一工时记录原子提交。服务端时间是事实，跨日/周/月区间按个人有效 IANA 时区与区间交集汇总；在线状态由有效心跳与显式意图决定，超时不能继续显示在线。 | 唯一约束、并发开始/停止、幂等、重启、DST 与 TTL |
| DASH-INV-03 | 成员加入时间来自真实 membership；姓名与时区修改只作用本人且跨工作区 CAS。会议引用必须是同工作区有效成员，项目作用域与有效起止时间由服务端校验。 | 资料并发、成员撤销、会议范围与时间边界 |
| DASH-INV-04 | Sprint 是原生 cycle，成员关系是 task.cycle；历史是持久有效观测，不是当前快照推造的过去。离线未观察的中间状态不能补造；历史损坏/读取失败不能显示成“没有历史”。 | 原生/API/外部文件编辑、重启、缓存重建、历史错误 |
| DASH-INV-05 | 健康与风险来自显式评估；预算/支出/预测来自具名币种与安全整数最小单位。预测为真实支出加显式剩余成本估计；不可隐式换汇，不可从任务完成率推算健康或金额；修正保留历史。 | 权限、金额溢出、混合币种、历史与版本冲突 |
| DASH-INV-06 | 项目 depends_on 与任务 blocked_by 是独立正式有向关系，均保留引用/防环保护。关键路径仅依据完整有效工期与授权依赖计算；缺失或不可见输入不是零工期。改期只改变日期，不暗改正文、标准或生命周期。 | 原文与 API 同规则、删除保护、CPM 分支/浮时/多关键路径、里程碑 CAS；SC-12/14/17/20 |

## 正式项目页面补充规则

范围与验收见[项目后端说明](../guides/project-management.md)和[项目菜单说明](../guides/project-management.md)，不把展示样例、团队关联或附件上传当作项目完成依据。

| 编号 | 必须保持的规则 | 验证边界 |
| --- | --- | --- |
| PROJ-INV-01 | 个人收藏独立于任务关注，按工作区/主体/项目唯一；私有收据、事件和审计均维持主体隔离。 | CAS、并发/幂等、另一用户、撤权 |
| PROJ-INV-02 | 封面只引用同项目已登记的不可变安全栅格图片版本；不跟随最新版本指针，不允许外链/SVG/HTML 或伪造 MIME。 | 上传登记、字节检查、授权下载、替换/移除、跨项目拒绝 |
| PROJ-INV-03 | 团队只组织已有有效成员，不授予权限；项目最小目录和团队成员展示必须按当前实际访问范围裁剪。 | 管理能力与业务读分离、成员撤销、跨工作区引用、姓名信息泄露 |
| PROJ-INV-04 | 范围清单是稳定条目 ID 的独立协作注释，不替代核心正文/验收标准；勾选不修改生命周期。人工交付信心可未知，独立于健康状态和任务完成率。 | 附加记录 CAS、条目增删、原文不变、历史快照 |
| PROJ-INV-05 | 审计不可变且与受控写入结果一致；拒绝/幂等重放不得产生假成功或重复历史。安全差异只含白名单字段，不存原始正文、消息或秘密；分页不能依赖 SSE 保留期。 | SQL 事务、核心 journal 恢复、当前 audit.read/项目权限、私有事件、游标边界 |
| PROJ-INV-06 | 行内、看板和甘特写入复用原生配置及 revision；不能硬编码旧状态或绕过诊断、归档、冲突、未知写入。未知尝试跨页面/重载保留，先读权威版本，再显式采用或放弃；字段匹配不是命令收据。 | 自定义工作流、源码 CAS、草稿恢复、原生设置/源码入口保护；不宣称实时跨标签页锁 |
| PROJ-INV-07 | 项目复制冻结原始输入和内容清单，先分配全体新 ID，再重映射内部任务关系并重置配置工作流；不继承授权、审核、评论、审计、附件字节或用户代码。部分复制不可作为正常项目发布，查询和重启不自动续写，只能显式恢复同主体的原命令。 | 当前权限、源版本、同键/异参、故障重启、绑定/审计恢复、任务关系 |
| PROJ-INV-08 | 侧栏顺序属于当前主体/工作区，不改变项目业务状态；读写复核授权并排除归档对象。搜索只过滤展示，移动使用全量授权顺序；私有收据和事件不泄露其他主体或撤权项目。 | CAS、跨账号、撤权、归档、全量邻居、SSE 收敛 |
| PROJ-INV-09 | 项目分享复用成员能力和项目范围；增减当前项目必须保留其他范围与能力。最后一个范围移除保留成员资格和空数组，全工作区继承授权不能伪装为可单项目移除；未配置 SMTP 不制造邀请成功。 | 当前 access.manage、版本冲突、最后范围、继承授权、只读目录 |
| PROJ-INV-10 | 永久删除必须先归档，并通过原生引用与 SQL 业务引用检查；命令和原生入口使用同一守卫。不级联删除不可变历史，不删除用户代码目录；归档目录须可达以便恢复和受保护删除。 | 两种删除入口、任务/成果等引用、原文版本、审计保留、代码目录保留 |

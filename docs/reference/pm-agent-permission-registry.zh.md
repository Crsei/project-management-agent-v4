# PM / Agent / Plugin 权限边界登记与统一回归

本文登记[可信执行计划 A—D](pm-agent-trust-context-plugin-plan.zh.md)涉及的权限代码、行为用例与运行证据，不是第二套 ACL、运行时策略或最终全量验收声明。登记日期：2026-11-10。**实际执行状态统一记录于第 5.2 节；其余表格只描述边界与用例，不重复维护状态。** 会话与持久化仍暂沿用 Agent Chat，统一设计尚未收口；PM 成员权限不等同于 Agent 会话所有权隔离。

## 1. 语义与维护约定

- `ENFORCE`：本来已有的身份、成员/项目/能力、明确 OAuth 委托、撤权、服务认证、目录身份、revision/CAS、幂等与 unknown 禁止重派边界。仍然拒绝非法操作；`full` 不覆盖它们。
- `AUDIT`：本轮新增的执行来源、策略、关联与安装记录。默认 `access=full`、`mode=audit-only`，自动记录与非阻塞提醒；不新增用户允许/拒绝选择、审批等待、额外启用开关或基于新策略范围/时间字段的 ACL。
- `MIXED`：同一函数既保留 `ENFORCE`，又携带 `AUDIT` 元数据；两者在表中分开说明。既有显式 `ask`/`auto-approve` 配置及 OAuth 默认只读同意不被本轮改写。
- 稳定键命名为 `PM-PERM-<域>-<边界>`，不依赖行号。文件/符号是实现定位，不通过扫描源码文本来“证明”行为。改变边界时更新对应条目与真实行为用例，不复制工具清单或引入并行权限引擎。
- 每行“证据/提醒”说明运行时证据所在；“测试”引用第 4 节的文件与具体 case。**第 5.2 节是唯一运行状态表**，按执行批次、环境与代码变更说明有效范围。协议夹具、真实数据库、浏览器、真实客户端证明不能互相替代；已有一轮通过不覆盖随后新增修复。
- 内部执行事实与用户可见性正交；对失权读者隐藏状态、目标、参数、正文、错误、收据和 diff，不把业务事实改为失败。不可用不等于被拒绝；没有收据不等于没有提交。
